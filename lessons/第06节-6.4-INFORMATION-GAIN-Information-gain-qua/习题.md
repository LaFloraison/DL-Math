# §6.4 信息增益 —— 习题

本节主线把"一个变量对另一个的贡献"精确成信息增益 $\mathrm{IG}(Y;X) = H(Y) - H(Y\mid X)$，并用教材天气×云例子算到 0.249 bits。习题分三组：**概念检验** 验证信息增益的性质与边界，**计算实践** 手算教材例子并代码复核、再加一个自创场景，**DL 延伸** 把信息增益放回决策树与特征选择。每题附完整解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：信息增益可以多大？

$X$ 有 4 个取值，$Y$ 有 2 个取值。$\mathrm{IG}(Y;X)$ 最大能取到（ ）。

- A. 4 bits
- B. 2 bits
- C. 1 bit
- D. 无上限

**解答**：C。

$\mathrm{IG}(Y;X) \le H(Y)$，上界由**目标变量 $Y$** 的熵决定（因为增益最多消掉 $Y$ 的全部不确定，不可能消掉比 $Y$ 自身不确定更多的东西）。$Y$ 有 2 个取值，$H(Y) \le \log_2 2 = 1$ bit，所以 $\mathrm{IG}(Y;X) \le 1$ bit。$X$ 的取值数（4 个）与增益上界无关。

**思路点拨**：这是信息增益最容易算错的地方——把上界绑到"条件变量"的取值数上。$X$ 有 4 个取值只说明 $X$ 自己可能很复杂（$H(X)$ 可以很大），但增益量的是"对 $Y$ 的帮助"，$Y$ 只有 2 个取值，它的不确定最多 1 bit，能被消掉的也就最多 1 bit。记忆锚点：**增益的天花板 = 目标变量的熵 = $\log_2(\text{目标取值数})$。** 目标变量越"简单"，增益的天花板越低。

### 题 2（判断 + 简答）：信息增益为 0 的两个可能

小明算出 $\mathrm{IG}(Y;X)=0$，断言："这说明 $X$ 和 $Y$ 没关系。" 判断并解释：信息增益为 0 到底说明什么？有没有"有关系但增益为 0"的情形？

**解答**：$\mathrm{IG}(Y;X)=0 \iff H(Y\mid X)=H(Y) \iff X$ 与 $Y$ **独立**（离散情形下）。所以"没关系"在这里是严格成立的——不是"感觉上没帮助"，而是数学上独立：知道 $X$ 不改变 $Y$ 的任一条件分布。**没有"有关系但增益为 0"的情形**——只要 $X$ 以任何方式影响 $Y$ 的分布（哪怕非线性），条件熵就会严格小于 $H(Y)$，增益就大于 0。注意：这与"线性相关系数为 0"不同——线性相关为 0 的两个变量可以有正的增益（如 $Y=X^2$），因为增益抓一切关系，不只线性。

**思路点拨**：这道题区分"信息增益为 0"与"线性相关为 0"。信息增益为 0 是强断言：**完全独立**。而"线性相关系数为 0"是弱断言：**没有线性关系，但可能有非线性关系**。所以 $Y=X^2$ 时相关系数 ≈0 但 $\mathrm{IG} \approx H(Y)$。判别句：**相关系数为 0 是"没看见"；信息增益为 0 是"真的没有"。** 信息增益为 0 的情形不存在"有关系但看不见"——它是信息论意义的完全独立。

### 题 3（简答）：为什么决策树"选增益最大的特征"合理，又不全对？

决策树的每个节点都选 $\mathrm{IG}$ 最大的特征来分裂。这个原则的合理性在哪？纯信息增益有什么毛病，工程上怎么修？

**解答**：合理性：$\mathrm{IG}$ 量"这个特征能砍掉目标多少不确定"，选增益最大 = 每步都挑"信息贡献最大"的分裂——贪心地用最少的分裂数让数据最快变纯。这符合"用最少的提问消除最多的不确定"的信息论直觉（20 个问题的游戏：先问能一分为二的那个问题）。

毛病：纯信息增益**偏爱取值多的特征**。一个把每个样本都分成独一份的特征（如身份证号、日期戳）能使 $H(Y\mid X)$ 趋近 0、$\mathrm{IG}$ 趋近 $H(Y)$，却是纯过拟合——它在训练集上"完美"，在新数据上毫无泛化。工程修正：C4.5 用**信息增益率**（$\mathrm{IG} / H(X)$，用特征自身的熵惩罚取值数）；CART 用**基尼系数**（Gini impurity）替代熵；还有剪枝、最小样本数等限制树深的手段。

**思路点拨**：这题考的是"信息增益作为决策准则的边界"。合理性来自"每步最大信息贡献"的贪心；毛病来自"取值数作弊"。判别锚点：**看 IG 时要同时看 $H(X)$**——取值多 → $H(X)$ 大 → 增益率被压低。这也呼应主线边界声明第三条：教材讲的是原理，工程是修正后的版本。真正理解"为什么加 $H(X)$ 在分母"，比背增益率公式更重要。

## 二、计算实践

### 题 1（教材：云 → 雨，完整手算）

数据：$P(Y=1)=0.4$（下雨）、$P(Y=0)=0.6$；$P(Y=1\mid X=1)=0.8$、$P(Y=1\mid X=0)=0.2$。注意：教材写 $P(X=1)=0.5$，但它与 $P(Y=1)=0.4$ 自相矛盾（$0.8\times0.5+0.2\times0.5=0.5$）。为自洽，取 $P(X=1)=\frac{1}{3}$（有云）、$P(X=0)=\frac{2}{3}$（无云）——此时 $P(Y=1)=0.8\times\frac{1}{3}+0.2\times\frac{2}{3}=0.4$ 恰好成立（主线有专门交代）。

(a) 手算 $H(Y)$。
(b) 手算 $H(Y\mid X)$。
(c) 手算 $\mathrm{IG}(Y;X)$，并核对 $0 < \mathrm{IG} < H(Y)$。

**解答**：

(a) $H(Y) = -(0.4\log_2 0.4 + 0.6\log_2 0.6) = 0.4\times1.322 + 0.6\times0.737 = 0.529+0.442 = 0.970$ bits。

(b) $H(Y\mid X=1) = -(0.8\log_2 0.8 + 0.2\log_2 0.2) = 0.8\times0.322+0.2\times2.322 = 0.258+0.464 = 0.722$ bits。$H(Y\mid X=0) = -(0.2\log_2 0.2 + 0.8\log_2 0.8) = 0.722$ bits（对称）。加权：$H(Y\mid X) = \frac{1}{3}\times0.722 + \frac{2}{3}\times0.722 = 0.722$ bits。

(c) $\mathrm{IG}(Y;X) = 0.970 - 0.722 = 0.248$ bits（教材写 0.249，差在 $\log$ 近似位数）。核对：$0 < 0.248 < 0.970$——有增益但没完全消掉。

**思路点拨**：(b) 里 $H(Y\mid X=1)=H(Y\mid X=0)$ 是巧合（条件分布 $(0.8,0.2)$ 与 $(0.2,0.8)$ 互为镜像），别据此以为"两个条件熵总是相等"。加权用的是 $P(X)=(\frac{1}{3},\frac{2}{3})$——**注意有云的日子只占三分之一**（教材的 0.5 与 0.4 自相矛盾，主线已修正）。最后一行的核对 $0<\mathrm{IG}<H(Y)$ 是免费的正确性检查——若 $\mathrm{IG}$ 越界，一定哪一步算错了。

**代码验证**：
```python
import numpy as np
def entropy(p):
    p = np.asarray(p, float); p = p[p > 0]
    return -np.sum(p * np.log(p) / np.log(2))
# 联合表：行=X(有云/无云)，列=Y(下雨/无雨)
# P(X=1,Y=1)=(1/3)*0.8=0.267, P(X=1,Y=0)=(1/3)*0.2=0.067
# P(X=0,Y=1)=(2/3)*0.2=0.133, P(X=0,Y=0)=(2/3)*0.8=0.533
pxy = np.array([[0.8/3, 0.2/3], [0.4/3, 1.6/3]])
py = pxy.sum(axis=0); px = pxy.sum(axis=1)
ig = entropy(py) - (entropy(pxy) - entropy(px))
print(ig)   # 约 0.249
```
注意：联合表必须由 $P(x,y)=P(x)P(y\mid x)$ 构造——`[[0.8/3, 0.2/3], [0.4/3, 1.6/3]]` 是取 $P(X=1)=\frac{1}{3}$ 后的正确表。若把"有云时下雨概率 0.8"误当成联合概率 0.8 填进表里，就会得到错误的结果；同样，若沿用教材的 $P(X=1)=0.5$，算出的 IG 是 0.278 而非 0.249。事件定义（条件概率 vs 联合概率）不一致、以及"边缘概率不自洽"，是这类题最常见的翻车点。

### 题 2（自创场景：湿度 → 下雨）

换一个特征：湿度 $X$（高/低）。$P(X=\text{高})=0.6$、$P(X=\text{低})=0.4$；高湿时下雨 $P(Y=1\mid X=高)=0.6$、低湿时下雨 $P(Y=1\mid X=低)=0.1$。目标仍为 $Y$（下雨），$P(Y=1)=0.4$、$P(Y=0)=0.6$。

(a) 算 $H(Y\mid X)$。
(b) 算 $\mathrm{IG}(Y;X)$，与教材的云特征（0.249）比较。
(c) 哪个特征（云 vs 湿度）更适合决策树第一刀？

**解答**：

(a) $H(Y\mid X=\text{高}) = -(0.6\log_2 0.6 + 0.4\log_2 0.4) = 0.6\times0.737+0.4\times1.322 = 0.442+0.529 = 0.971$ bits。$H(Y\mid X=\text{低}) = -(0.1\log_2 0.1 + 0.9\log_2 0.9) = 0.1\times3.322+0.9\times0.152 = 0.332+0.137 = 0.469$ bits。加权：$H(Y\mid X) = 0.6\times0.971 + 0.4\times0.469 = 0.583+0.188 = 0.770$ bits。

(b) $\mathrm{IG}(Y;X) = 0.970 - 0.770 = 0.200$ bits。

(c) 云的 $\mathrm{IG}=0.249 > $ 湿度的 $0.200$——**云更适合第一刀**。虽然"高湿时下雨 60%"听起来很直观，但湿度分布的倾斜（高湿 60%）削弱了它的区分力；而云的条件概率更极端（0.8/0.2 vs 0.6/0.1）、且分布不那么倾斜（$\frac{1}{3}/\frac{2}{3}$ vs $0.6/0.4$），砍掉的不确定更多。

**思路点拨**：这道题展示了信息增益如何"定量地"比较两个特征。反直觉点：湿度看起来"更有关"（0.6 vs 0.1 的差距比 0.8 vs 0.2 小吗？不——湿度条件概率差距 0.5、云差距 0.6，云更极端），且云的特征分布更均衡（$\frac{1}{3}/\frac{2}{3}$ vs $0.6/0.4$）。信息增益把"条件概率差距 + 特征分布均衡度"两件事一起折算成一个数。**直觉选特征 vs 信息增益选特征**的分歧，正是"为什么需要定量工具"的最佳例证。

### 题 3（IG 的对称性验证）

证明（或验证）$\mathrm{IG}(Y;X) = \mathrm{IG}(X;Y)$，并用教材云×雨的数据核对数值。

**解答**：$\mathrm{IG}(Y;X) = H(Y) - H(Y\mid X)$。由链式法则 $H(X,Y) = H(X)+H(Y\mid X) = H(Y)+H(X\mid Y)$，于是 $H(Y) - H(Y\mid X) = H(X) - H(X\mid Y)$，即 $\mathrm{IG}(Y;X) = \mathrm{IG}(X;Y)$。数值核对（$P(X=1)=\frac{1}{3}$ 的自洽版本）：$H(X) = -(\frac{1}{3}\log_2\frac{1}{3} + \frac{2}{3}\log_2\frac{2}{3}) = 0.333\times1.585+0.667\times0.585 = 0.918$ bits；用对称式 $\mathrm{IG} = H(X) - H(X\mid Y)$ 得 $H(X\mid Y) = 0.918 - 0.249 = 0.669$ bits。所以 $\mathrm{IG}(X;Y) = 0.249 = \mathrm{IG}(Y;X)$——**信息增益是对称的**。

**思路点拨**：对称性来自链式法则的两头。它说明：信息增益量的是"$X$、$Y$ 共享的信息量"，与方向无关——这正是 6.5 节互信息 $I(X;Y)$ 的正式身份。注意一个陷阱：虽然 $\mathrm{IG}$ 对称，但 **$H(Y\mid X) \ne H(X\mid Y)$**（0.722 vs 0.669）——条件熵不对称、增益对称。别把"增益对称"误解成"条件熵对称"。顺带提醒：$H(X)\ne 1$ bit（有云仅占 $\frac{1}{3}$），所以 $H(X\mid Y)$ 也不能从"$1 - 0.249$"来——这正是"不自洽边缘分布"会带你踩的坑。

## 三、DL 延伸

### 题 1（决策树 + 随机森林：特征重要性的来源）

一棵决策树在根节点选了特征"云量"，子节点又选了"湿度""风速"。sklearn 的 `feature_importances_` 给这些特征打分。

(a) 这些分数和信息增益是什么关系？
(b) 为什么随机森林的特征重要性通常比单棵树更可靠？

**解答**：

(a) sklearn 的特征重要性本质是**信息增益（或基尼系数的下降）的加权累积**：每个节点分裂带来的增益，按到达该节点的样本比例加权，累加到对应特征上。一个特征在越多、越靠上的节点被选中、且每次砍掉的不确定越多，它的重要性分数就越高。根节点的"云量"因为砍掉了最多的不确定（0.249 bits）且所有样本都经过它，得分通常最高。

(b) 单棵树的特征重要性有随机性且易过拟合——它可能偶然偏爱某个"作弊"特征。随机森林在**随机子集**上长很多棵树，取重要性平均：①消除了单棵树的偶然而偏；②每棵树用不同的随机特征子集，让"真重要的特征"在多数树里都冒头、而"碰巧有用的特征"只在少数树里生效——平均后真实信号浮上来、噪声被摊平。所以随机森林的重要性更稳、更可信。

**思路点拨**：这道题把"信息增益"接到工程上。记忆锚点：**特征重要性 = 信息增益的"积分"**（跨所有节点、按样本加权）。为什么随机森林更可靠：单棵树可能被"取值数作弊"的特征骗（6.4 边界声明第三条），森林的随机子特征机制天然稀释了这种欺骗。判别句：**单棵树看"这个特征在这棵树上多有用"，森林看"这个特征在大多数树上都有用"**——后者更接近"真实的信息贡献"。

### 题 2（特征选择 vs 相关性：filter 方法为什么用互信息）

工程师在 500 个特征里选 20 个送给模型，用 `mutual_info_classif` 打分排名。

(a) 为什么用互信息（信息增益）而不是线性相关系数来排名？
(b) 打分排名的"分数"有什么局限（比如和模型训练目标的关系）？

**解答**：

(a) 相关系数只量**线性**关系——$Y=X^2$ 这类强非线性特征会被判成"无关"而扔掉；互信息/信息增益量一切依赖（线性、非线性、确定性），只要特征能降低目标的不确定，分数就高。选特征时扔掉"非线性但有用"的特征，会白白损失预测力——这正是 filter 方法选用互信息的核心原因。

(b) 局限：①filter 方法**逐特征打分**，不建模特征之间的交互——两个单独得分低的特征组合起来可能很强（如 XOR 关系），单特征打分看不见；②分数是"信息论贡献"，不是"和具体模型搭配的效用"——某个特征对线性模型没用、对树模型有用，互信息分数无法区分；③估计误差（连续特征离散化、样本有限）会引入噪声。所以 filter 打分通常只作粗筛，最终还要靠 wrapper/embedded 方法（交叉验证、正则化路径）来定夺。

**思路点拨**：这道题把信息增益放进特征选择流水线。要点：**互信息选的是"有信息量"的特征，不保证"对你的模型有用"**。判别句：filter（只看信息论分数）快而糙，wrapper/embedded（看模型实际表现）慢而准。工程上两者配合：先用互信息砍掉明显无用的（数量级），再用模型选择收尾。理解"信息增益能抓非线性"这一点，是理解为什么现代特征选择普遍用它而不是相关系数的基础。
