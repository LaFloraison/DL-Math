# §7.7.1 GraphSAGE —— 习题

主线把 GraphSAGE 拆成三件事：采样、聚合、更新，并强调"归纳式"（新节点也能分类）。下面三组习题检验你是否理解这个模型的灵魂。每题附解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：GraphSAGE 与 GCN 最本质的区别是什么？

- A. GraphSAGE 更准确
- B. GraphSAGE 用采样邻居替代全邻居聚合，实现"归纳式"——能处理从未见过的新节点
- C. GraphSAGE 不用激活函数
- D. GraphSAGE 只能处理有向图

**解答**：B。

**思路点拨**：GraphSAGE 的两大特征——采样（压规模）与归纳（新节点可表示）。归纳式的根源是"学规则而非学节点"：模型学的聚合函数可移植到任何节点。A 不必然（采样是有损的）；C、D 错。常见错选 A——把"归纳"误当"更准"。

### 题 2（简答）：为什么说 GraphSAGE 是"归纳式"而 GCN 是"转导式"？

**解答**：**GCN**：归一化邻接矩阵 $\hat{A}$ 在训练时编码了整张图（包括所有节点）——训练后模型只对"训练时见过的图"有效，新节点在 $\hat{A}$ 里没有位置，无法生成表示（**转导式**）。**GraphSAGE**：模型学的是"采样-聚合-更新"的**规则**（$W$、AGGREGATE），不依赖任何具体节点的值——新节点接入图后，用同一套规则读它的邻居即可生成表示（**归纳式**）。一句话：转导式背"题"，归纳式会"方法"。

**思路点拨**：答题锚点是"学节点值 vs 学规则"。能把"为什么 $\hat{A}$ 让 GCN 转导"讲清就深刻。常见错误是只背"归纳=处理新节点"没说机制。

### 题 3（判断）：LSTM 聚合函数里，邻居的"顺序"有意义吗？

**解答**：没有——**邻居集合没有天然顺序**。用 LSTM 把邻居当"序列"处理时，必须**随机打乱**邻居顺序，否则模型会把"第 1 个邻居"学成特殊角色，学到不存在的"顺序结构"（伪信号）。这正是为什么 LSTM 聚合要用采样 + 随机化。

**思路点拨**：这是主线边界声明的直考。答题要点是"顺序是伪信号、必须随机化"。常见错误是以为 LSTM 天然适合邻居序列——它适合"有序序列"，邻居不是有序的。

## 二、计算实践

### 题 1（手算 + NumPy：均值版 GraphSAGE 一层）

图：A 连 B、C。特征 $h_A=[1,0]$、$h_B=[0,1]$、$h_C=[1,1]$。用教材的均值公式 $h_v^{(1)} = \sigma(W \cdot \mathrm{mean}(\{h_v\} \cup \{h_u : u\in\mathcal{N}(v)\}))$，$W=I$（恒等），ReLU。手算 $h_A^{(1)}$。

**解答**：$\{h_A\} \cup \{h_B, h_C\} = \{[1,0], [0,1], [1,1]\}$，mean $= [\frac{1+0+1}{3}, \frac{0+1+1}{3}] = [\frac{2}{3}, \frac{2}{3}]$。乘 $W=I$ 不变，ReLU 不变。$h_A^{(1)} = [\frac{2}{3}, \frac{2}{3}]$。**注意：均值公式把"自己"也放进 mean**（A 的 3 个邻居位置 = 自己 + B + C），与拼接版（自己单独接）不同——两种写法，均值和拼接的语义略有差别。

**NumPy 验证**：
```python
import numpy as np
H = np.array([[1.,0.],[0.,1.],[1.,1.]])
self_and_neighbors = H[[0,1,2]]      # A + B + C
print("h_A^(1) =", self_and_neighbors.mean(axis=0))   # [0.667 0.667]
```
```
h_A^(1) = [0.66666667 0.66666667]
```

**思路点拨**：均值公式的 key 是"自己也在 mean 里"。常见错误是只平均邻居忘加自己（$[0.5,1]$）——那样节点在更新时就"丢了自己"的部分。教材的均值公式把"自己"放进集合，是"自环"思想的显式版。

### 题 2（手算：归纳式新节点）

沿题 1 的图，新节点 X 连接 A。X 的特征 $h_X=[0,0]$，$W=I$，均值公式。手算 $h_X^{(1)}$。这说明了归纳式的什么？

**解答**：X 的集合 = $\{X, A\} = \{[0,0], [1,0]\}$，mean $= [0.5, 0]$。$h_X^{(1)} = [0.5, 0]$。**X 在训练时不存在（$h_X=[0,0]$ 是它的初始特征），但用同一套公式（$W=I$、mean 聚合）直接生成了表示**——不需要重训。它的表示反映了"X 只连 A"这个结构。这就是归纳式：模型从没"见过"X，却"知道"怎么读它的邻居。

**思路点拨**：核心是"规则可移植到未见节点"。X 的表示全由"它的邻居 A"决定——**归纳式 = 用结构即时生成，而非用历史记忆**。常见错误是以为新节点需要重训。

## 三、DL 延伸

### 题 1（场景设计）：给"每天 100 万新用户"的推荐系统选模型

一个推荐系统每天新增 100 万用户（之前从未出现），要用图模型给新用户生成表示、立即推荐。请论证：为什么必须用 GraphSAGE 这类归纳式模型，而不是 GCN？如果坚持用 GCN 会怎样？

**解答**：GCN 是转导式——$\hat{A}$ 在训练时固定，新用户不在其中，无法生成表示；每天 100 万新用户意味着要么每天重训（成本、延迟不可接受）、要么对新用户无推荐（业务损失）。GraphSAGE 是归纳式——训练时学"如何从邻居读用户"的规则，新用户接入图（建边）后用规则即时聚合一次就有表示，**无需重训、毫秒级可用**。这就是为什么主流推荐系统（Pinterest PinSage、Facebook）都用 GraphSAGE 家族：**它们面对的世界，永远是"没见过的新对象"。**

**思路点拨**：答题锚点是"转导 vs 归纳 × 新用户的频率"。能把"每天 100 万"和"必须归纳"连起来就很有说服力。常见错误是只说"GraphSAGE 能处理新节点"，没联系"重训成本"这个工程现实。

### 题 2（概念连线）：GraphSAGE 如何同时解决"三道坎"里的两道？

§7.6 有三道坎（太大、在动、太杂）。请说明 GraphSAGE 的采样与归纳，分别解决了哪两道，并指出它在"太杂"这一坎上的局限。

**解答**：**采样**解决"太大"——每层只取固定 k 个邻居，计算与度数解耦（§7.6.1），亿级图可训练。**归纳**解决"在动"——新节点加入无需重训，用规则即时聚合（§7.6.2 的增量友好），动态图"边学边跟"有了底座。**局限**：GraphSAGE 默认"所有邻居一视同仁"，对"太杂"（异质图）需要扩展——不同节点/边类型要分别聚合（分类型 $W_\tau$ 或元路径，§7.6.3），标准 GraphSAGE 不做这个区分。

**思路点拨**：答题要成对给出"机制 × 解决的坎"以及"未解决的坎"。能点出"异质需扩展"就是完整答案。常见错误是宣称 GraphSAGE 解决所有三道坎——它只解决"太大"和"在动"，"太杂"要另加类型处理。
