# 习题：宽度的账单与饱和点

## 第一组：概念检验

**1. 判断题并说明理由**："网络越宽（每层节点越多），性能一定越好。"

**2. 多选题**：教材指出加宽带来的挑战有哪些？
- (A) 更容易过拟合
- (B) 需要更多计算资源与内存
- (C) 存在饱和点——加宽到某点后收益停止
- (D) 一定导致梯度消失

**3. 简答**：深度和宽度都能增加参数，但两者加的"东西"有什么本质不同？给一个"该加宽而不是加深"的任务场景。

### 解答与思路点拨

**1. 错误。** 加宽收益在饱和点处停止（§9.3.1.2 代码：宽 4 到宽 64 准确率都是 1.000），而代价（过拟合、算力、内存）持续累积。教材明确说："加更多节点可能不会让网络更准"。选"正确"的人往往只看到了"容量增加"的一面，漏了"边际收益递减 + 过拟合"的另一面。

**2. (A)(B)(C)。** (D) 是误区——梯度消失主要由**深度**（链式乘法长度）和激活函数（§9.3.4）引起，宽度不是元凶。教材列出的加宽挑战是：过拟合、计算与内存开销、饱和点。

**3.** 深度加的是"组合的级数"（逐级抽象的层级），宽度加的是"并行的探测器"（同层能同时检测多少特征）。该加宽而非加深的场景：任务本身不需要多级抽象，但需要一次性覆盖大量并行特征——比如把高维稀疏特征（词表 100 万的 one-hot）映射到稠密嵌入，一个宽而浅的层就够；或者任务简单到单层理论足够（§9.3.1.2 历史中万能逼近定理的情形），这时加宽比加深更省。

## 第二组：计算实践

**4. 手算**：一个网络拓扑 `[784, 256, 64, 10]`。计算它的连接总数（不含偏置）。提示：逐层乘积求和。

**5. 代码验证**：用本节的 `count_connections` 验证你的手算；再算 `[784, 256, 256, 64, 10]`（多插一层 256）的连接数，对比两次结果，说明"加深一层 256"和"把中间层加到 512"哪个连接数涨得多。

### 解答与思路点拨

**4.** `784×256 + 256×64 + 64×10 = 200,704 + 16,384 + 640 = 217,728`。常见错误：漏掉层与层之间的乘积要**逐对**求和，或者把偏置也算进去（偏置是 $256+64+10=330$，是小数，教材的"连接数"通常指边，不含偏置）。

**5.** 验证：

```python
def count_connections(layers):
    return sum(layers[i]*layers[i+1] for i in range(len(layers)-1))

print(count_connections([784,256,64,10]))              # 217,728
print(count_connections([784,256,256,64,10]))          # 288,000
print(count_connections([784,512,64,10]))              # 437,760
```

```text
[784,256,64,10]     → 217728
[784,256,256,64,10] → 288000
[784,512,64,10]     → 437760
```

对比：加一层 256（深度化）连接数 217,728→288,000（+70,272）；把中间层 256 加到 512（宽度化）217,728→437,760（+220,032）。**同样加这么多参数，宽度化的账单是深度化的 3 倍多**——这就是"宽度是参数放大器"的数字铁证，也是教材建议"找到正确设计而非简单加节点"的根源。

## 第三组：DL 延伸

**6. 场景判断**：你有一个 2 层网络（`[784, 100, 10]`）在 MNIST 上训练误差 3%、测试误差 4%。你打算把隐藏层加到 1000 个节点。请分析：这个改动主要影响什么？在什么前提下它可能（a）有用，（b）有害？

**7. 思考题**：§9.3.1.2 历史中，万能逼近定理说"单层足够宽就能逼近任意函数"，但实践里深度网络效果更好。请从"泛化"而非"表达能力"的角度，解释为什么"深而窄"常常优于"宽而浅"。

### 解答与思路点拨

**6.** 加宽主要影响：参数量（`784×1000+1000×10 = 794,000`）、过拟合风险、算力内存。(a) 有用的前提：训练误差显著高于测试误差（说明容量不足、欠拟合），加宽能提升拟合能力；(b) 有害的前提：训练误差已经很接近测试误差、甚至两者都很低——此时加宽只会让网络把训练细节/噪声背下来，过拟合风险上升而泛化不升。题设 3% vs 4% 差距很小，属于"接近上限"，**加宽很可能有害**——更该做的是加深、加正则、加数据。

**7.** 表达能力（能否表达）是一回事，泛化（表达得是否"平滑/可迁移"）是另一回事。宽而浅的网络可以用大量并行的"查表式"片段拼出函数——等价于记住了大量局部模式，对未见输入泛化差；深而窄的网络用逐级组合的抽象表达函数——每一层学的是可复用的"部件"，对结构的泛化更好。通俗说：**宽度是"背得下"，深度是"理得清"。** 万能逼近定理只承诺"背得下"，没承诺"理得清"。
