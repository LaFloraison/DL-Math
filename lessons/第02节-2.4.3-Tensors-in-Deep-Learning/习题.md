# 习题：深度学习中的张量

## 第一组：概念检验

**1.1（单选）** 一张 64×64 的彩色 RGB 图片，用张量表示的正确形状是：
- A. `(64, 64, 3)`
- B. `(64, 3, 64)`
- C. `(3, 64, 64)`
- D. `(64, 64, 64)`

**1.2（判断并说明）** "两个张量的 shape 相同，就一定是同一个张量。" 这句话对吗？请结合"维的语义"说明。

**1.3（填空）** 一批 8 张 32×32 的 RGB 图，形状是 `____`；一句话 50 个词、每词 300 维嵌入，形状是 `____`；一个 10 分类任务的全连接层输出，形状是 `____`。

## 第二组：计算实践

**2.1（手算 + 代码验证）** 一个卷积层有 16 个 3×3 滤波器、输入 3 个通道。手算：它的权重张量有多少个可学习参数（不含偏置）？偏置张量有几个？两者合计多少？用代码验证。

**2.2（代码验证）** 生成 `(16, 32, 32, 3)` 的批量张量，验证三条性质：① `reshape(16, -1)` 后的元素总数不变；② `transpose(3, 1, 2, 0)` 后的元素总数不变；③ 展平再 `reshape` 回原形状，与原张量逐元素相等。

**2.3（手算）** 一段 4 秒的视频，每秒 25 帧，每帧是 128×128 的 RGB 图像。把 2 段这样的视频装进一个批量张量，它的形状是什么？一共多少个元素？

## 第三组：DL 延伸

**3.1（场景判断）** 一个 Transformer 处理一批 8 句话，每句切分后 20 个 token，每 token 编码为 768 维向量。问：① 输入张量的形状？② 注意力里 $QK^\top$ 这一步产出的张量形状？（$Q$、$K$ 都与输入同形）

**3.2（场景分析）** ① 为什么深度学习里几乎总把"批量大小"放在第 0 维，而不是放在最后？② 一个批次里的句子长度各不相同（有 10 个词的、有 25 个词的），直接装进一个 `(B, L, D)` 张量会遇到什么问题？怎么解决？

## 解答与思路点拨

### 第一组

**1.1 答案：A。**
- **思路**：RGB 图的约定是 $(H, W, C)$——高、宽、通道。所以 64 高、64 宽、3 通道 → `(64, 64, 3)`。
- **点拨**：B 和 C 都是"同样 12288 个数字"的**不同排列**。这正好呼应主线边界声明"形状相同 ≠ 张量相同"——排列不同就是不同张量。图像领域几乎总把通道放最后（`(H,W,C)`），PyTorch 里却默认通道放第二（`(N,C,H,W)`），看到别慌，这是同一张图换了"坐标系"，转置一下即可（见代码.md 步骤 9）。

**1.2 这句话不对。**
- **思路**：shape 只描述"每层抽屉有几格"（壳），不描述"每层抽屉叫什么"（魂）。`(50, 300)` 既可以是 50×300 像素的灰度图，也可以是 50 词×300 维的嵌入序列——数字一样多，语义完全不同。更极端的例子：`(3, 64, 64)` 与 `(64, 64, 3)` 是同一个 64×64 的 RGB 图吗？不是——它们的排列不同。
- **点拨**：判断"是不是同一个张量"要问两件事：shape 是否相同？每一维的语义是否一一对应？只答对第一问，是这道题最常见的丢分点。

**1.3 答案：`(8, 32, 32, 3)`；`(50, 300)`；`(10,)`。**
- **思路**：批量维加在最前；序列是 $(L, D)$；最终输出是每类一个概率的 1 维向量。
- **点拨**：第三空容易答成 `(1, 10)`——如果批量大小为 1，确实常保留成 `(1, 10)` 以符合"四阶批量"惯例；但教材说"单个样本"时就是 `(10,)`。区分"单样本"和"批量=1"：前者是一维，后者是二维。

### 第二组

**2.1**
权重参数 = $16 \times 3 \times 3 \times 3 = 432$。偏置 = 16（每滤波器一个）。合计 = $432 + 16 = 448$。
```python
import numpy as np
W = np.random.rand(16, 3, 3, 3)   # 权重张量
b = np.random.rand(16)            # 偏置张量
print("权重参数 =", W.size)        # 432
print("偏置参数 =", b.size)        # 16
print("合计     =", W.size + b.size)  # 448
```
- **思路**：参数个数就是张量的元素总数 `size = 各维之积`。卷积层的参数量 = 滤波器数 × 输入通道数 × 核高 × 核宽 + 偏置数。
- **点拨**：注意 16 出现了三次（`(16,3,3,3)` 里两个 3 是核的高和宽，不是输入通道）——把形状读成"16 个 3×3 核、每个核有 3 个通道版本"就顺了。

**2.2**
```python
import numpy as np
batch = np.random.rand(16, 32, 32, 3)          # (16, 32, 32, 3)
flat  = batch.reshape(16, -1)                  # (16, 3072)
t     = batch.transpose(3, 1, 2, 0)            # (3, 32, 32, 16)
print(batch.shape, "size =", batch.size)       # (16, 32, 32, 3) size = 49152
print(flat.shape,  "size =", flat.size)        # (16, 3072)      size = 49152
print(t.shape,     "size =", t.size)           # (3, 32, 32, 16) size = 49152
print(np.allclose(flat.reshape(16, 32, 32, 3), batch))  # True：展平可逆
```
- **思路**：`reshape` 与 `transpose` 都只"重排"不"增删"，所以元素总数恒等于各维之积、且恒等于 49152。展平再展回去，每个位置的数回到原处，`allclose` 为 True 证明可逆。
- **点拨**：三条性质共用一个原因——`size = ∏n_i` 是形状重排的不变量。这也解释了为什么 `reshape(16, -1)` 里的 `-1` 能被自动算出来：它必须等于 49152 ÷ 16 = 3072，否则就自相矛盾了。

**2.3**
形状 = `(2, 100, 128, 128, 3)`（批量 2、帧数 25×4=100、高 128、宽 128、通道 3）。
元素总数 = $2 \times 100 \times 128 \times 128 \times 3 = 2 \times 100 \times 16384 \times 3 = 9{,}830{,}400$。
- **思路**：每个新维度都是一种"自由度的刻度"——视频比图片多一维"时间（帧）"，批量再多一维"哪段视频"。
- **点拨**：写形状时从"单位"入手——先写 `(2, 100, 128, 128, 3)`，再逐个核对每一维的单位是不是"段、帧、行、列、通道"，比直接背数字可靠得多。这是"给每一维起名字"最直接的训练。

### 第三组

**3.1 答案：输入 `(8, 20, 768)`；$QK^\top$ 产出 `(8, 20, 20)`。**
- **思路**：批量 8 → 第 0 维；20 个 token → 第 1 维（序列长度 $L$）；768 维 → 第 2 维（$d_{\text{model}}$）。$Q, K, V$ 都与输入同形 `(8, 20, 768)`。$QK^\top$：$Q$ 形状 $(B, L, d)$，$K^\top$ 把 $K$ 的 $(B, L, d)$ 转成 $(B, d, L)$，两者第 2 维 `d` 对齐相乘，得 $(B, L, L)$——第 2 维那个 $20 \times 20$ 矩阵里，位置 $(i,j)$ 是第 $i$ 个 token 与第 $j$ 个 token 的相似度。
- **点拨**：这里每一维都靠"对齐"工作——$QK^\top$ 能乘起来，正是因为 $Q$ 和 $K^\top$ 的嵌入维 `768` 在中间对齐。如果当初把 $K$ 存成 `(8, 768, 20)`（把维顺序弄反），整个注意力就静默算错。这道题是主线桥接"形状对齐是矩阵乘法的前提"的直接验证。

**3.2**
① **批量放第 0 维**：三条理由——(a) 它是通行约定，框架的广播、批归一化、梯度累积都默认第 0 维可批量化；(b) GPU 的并行核心天然按"批量样本"切分任务，放在第 0 维让一次矩阵乘法同时推进整批；(c) 切片 `batch[k]` 取第 $k$ 个样本的操作，第 0 维最自然。放最后不是不能，只是每个库都得为此改默认行为。
② **变长问题**：张量要求规则形状——每行必须等长。把 10 词和 25 词的句子直接拼进一个张量会报错（或退化成 object 数组）。解决办法是 **padding（填充）**：把所有句子填充到批次内最大长度（不足的 token 位置补上特殊记号，如 0），得到统一形状 `(B, L_max, D)`；同时记录一张掩码表（mask），告诉模型哪些位置是"真词"、哪些是"填充的假词"，在注意力/损失计算时把假词排除掉。
- **点拨**：padding 不是"掩盖问题"——它是张量的规则性约束与真实数据的多样性之间的**妥协**，代价是多算了若干填充位置的计算量。这正是主线边界声明"变长序列必须先填充到统一长度"的工程全景。

## 一个"为什么有人会答错"的提醒

1.1 的 B、C 选项设计成"数字一样、顺序不同"——选错的人往往只算了"元素个数一样"就下结论，忽略了排列本身就是张量的一部分。1.2 与 1.3 则是同一件事的两面：**shape 是壳，语义是魂**。2.3 最容易错在把"每秒 25 帧 × 4 秒 = 100 帧"算成 25——忘了先乘时间。3.1 最隐蔽的错是把 $QK^\top$ 记成 `(B, d, d)`——形状对齐时 $L$ 乘 $L$，不是 $d$ 乘 $d$；画一遍 $Q(B,L,d) \cdot K^\top(B,d,L)$ 的维度对齐，就永远不会再错。
