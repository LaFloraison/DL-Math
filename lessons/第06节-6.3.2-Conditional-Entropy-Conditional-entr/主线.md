## 第一步：Toy Model —— 出门前看一眼天

清晨，你站在门口，手搭在伞柄上，面临一个永恒的难题：今天要不要带伞？

过去一年的统计告诉你：**你带伞这件事，本身挺难猜。** 大约 41% 的日子你带了伞，59% 的日子你没带——接近五五开，你的"带伞习惯"有近 1 bit 的不确定：$H(Y) \approx 0.977$ bits。站在门口那一瞬间，你是真的拿不准。

可是你忽然想起一件事——**你可以先看一眼天。**

看一眼天，世界就变了。如果今天是**晴天**（70% 的日子如此），你的习惯是"很少带伞"：20% 带、80% 不带。你的犹豫明显轻了——晴天时你心里已经有底，剩给"要不要带伞"的不确定只有 0.722 bits。

如果今天是**雨天**（30% 的日子如此），你的习惯是"几乎必带"：90% 带、10% 不带。你的犹豫更轻——雨天时你基本已经决定了，剩给"要不要带伞"的不确定只有 0.469 bits。

现在问一个"浅到可笑"的问题：**出门前看了天，你心里"要不要带伞"的总不确定，比不看天时少了多少？**

晴天剩 0.722，雨天剩 0.469——可你不能光取平均（$\frac{0.722+0.469}{2}$），因为晴天比雨天多得多（70% vs 30%）。要算"看了天之后，平均还剩多少不确定"，你得**按晴/雨各自的出现概率加权**：

$$0.7 \times 0.722 + 0.3 \times 0.469 = 0.505 + 0.141 = 0.646 \text{ bits}$$

对比不看天时的 0.977 bits：**看了天，不确定从 0.977 掉到 0.646。** 天气帮你消掉了 0.331 bits 的犹豫。

这就是这一节的主角：**条件熵**——"知道 $X$ 之后，$Y$ 平均还剩多少不确定"。上面的 0.646 bits，正是教材 §6.3.2 亲手算出来的那个数。而"从 0.977 掉到 0.646"这个**差**，是你接下来会反复遇见的另一个概念——信息增益（6.4 节）的种子。直觉已经够用了，接下来把它精确成公式。

## 第二步：正式数学讲解

### 一、撞墙："给定某个值"和"给定整个变量"是两回事

你想给"知道天气之后，带伞还剩多少不确定"一个精确的定义。第一步很自然：先算"给定具体某天天气时的条件熵"。

晴天时，带伞的条件分布是 $P(Y \mid X=S) = (0.2, 0.8)$。这本身就是一个小信源，它有自己的熵：

$$H(Y \mid X = S) = -\big(0.2\log_2 0.2 + 0.8\log_2 0.8\big) = 0.464 + 0.258 = 0.722 \text{ bits}$$

雨天时同理，条件分布是 $(0.9, 0.1)$：

$$H(Y \mid X = R) = -\big(0.9\log_2 0.9 + 0.1\log_2 0.1\big) = 0.137 + 0.332 = 0.469 \text{ bits}$$

现在撞墙了。你有**两个**条件熵：$H(Y\mid S) = 0.722$ 和 $H(Y\mid R) = 0.469$。可"条件熵"应该是一个数——你要的是**整个**"知道天气之后"的平均剩余不确定，而不是某一个天气下的值。怎么合并这两个数？

上一节的教训还在耳边：合并必须**按出现概率加权**。晴天出现的概率是 $P(S) = 0.7$，雨天是 $P(R) = 0.3$。把两个条件熵分别乘以自己天气出现的概率再相加：

$$H(Y \mid X) = \sum_{x} P(x)\, H(Y \mid X = x) = 0.7 \times 0.722 + 0.3 \times 0.469 = 0.646 \text{ bits}$$

这就是"条件熵"的完整定义：**先对每个具体取值 $x$ 算一个条件熵 $H(Y\mid X=x)$，再按 $P(x)$ 加权平均。** 加权，是因为"晴天"和"雨天"并不是各占一半地出现在你的人生里——晴天更多，所以它在平均值里说话更响。

> **条件熵 (conditional entropy)** $H(Y \mid X)$
>
> 物理含义：在已知 $X$ 的取值之后，$Y$ **平均**还剩多少不确定。$H(Y \mid X)$ 越小，说明 $X$ 对 $Y$ 的"帮助"越大。
>
> $$H(Y \mid X) = \sum_{x \in \mathcal{X}} P(x)\, H(Y \mid X = x)$$
>
> 其中 $H(Y \mid X = x) = -\sum_{y \in \mathcal{Y}} P(y \mid x)\log_b P(y \mid x)$。两个式子合一，得到等价形式：
>
> $$H(Y \mid X) = -\sum_{x \in \mathcal{X}}\sum_{y \in \mathcal{Y}} P(x, y)\log_b P(y \mid x)$$
>
> - $P(y \mid x)$：给定 $X=x$ 时 $Y=y$ 的条件概率
> - $P(x, y)$：联合概率（等价形式里用它配条件概率）
> - 性质：
>   - $0 \le H(Y \mid X) \le H(Y)$：知道只会让不确定减少或不变（下界 0 = $X$ 完全决定 $Y$；上界 $H(Y)$ = $X$ 与 $Y$ 独立）
>   - 链式法则：$H(X, Y) = H(X) + H(Y \mid X)$（与 6.3 节呼应）
>   - 注意：$H(Y \mid X) \ne H(X \mid Y)$——条件熵**不对称**，方向不能混

### 二、把条件熵展开：两个极端与一个方向陷阱

条件熵的两端，正好对应关系的两种极端，值得各看一眼。

**极端一：$X$ 完全决定 $Y$。** 如果"雨天必带伞、晴天必不带"，那么知道天气后，带伞毫无悬念：$H(Y \mid X) = 0$。条件熵取到**下界**。这是"确定依赖"的极端——$X$ 把 $Y$ 的不确定**清零**。

**极端二：$X$ 与 $Y$ 完全无关。** 如果带伞习惯与天气毫不相干（晴天带伞概率和雨天一模一样），那么看了天等于没看：$H(Y \mid X) = H(Y)$。条件熵取到**上界**。这是"独立"的极端——$X$ 对 $Y$ **毫无帮助**。

教材的天气例子落在中间：0.646，比 $H(Y) = 0.977$ 小、比 0 大。0.331 bits 的差距，就是"天气对带伞的帮助量"——这一节后面和下一节会用不同的名字反复量它。

方向陷阱值得单独划一条线：**$H(Y \mid X)$ 几乎总不等于 $H(X \mid Y)$。** "知道天气后，带伞还剩多少不确定"和"知道带伞后，天气还剩多少不确定"，是两个不同的数。前者问"天气能帮带伞多少"，后者问"带伞能帮天气多少"——两个变量各自的信息含量不同（$H(Y)$ vs $H(X)$），条件熵自然不同。读公式、写代码、看论文，第一件事永远是确认条件的**方向**。

### 三、边界声明：条件熵的三条底线

**第一，条件熵是"加权平均"，不是"取最小"也不是"算术平均"。** 0.646 不是 $0.722$ 和 $0.469$ 的简单平均（那是 0.596），也不是其中较小的 0.469——而是按天气出现概率 $0.7, 0.3$ 加权。忘记加权，是所有手算错误的头号来源。为什么必须加权？因为"晴天"在你生命里出现 70%，它对应的 0.722 理应占据平均值 70% 的份额。

**第二，条件熵不能为负。** $0 \le H(Y \mid X)$ 是铁律——知道 $X$ 最多把 $Y$ 的不确定消到 0，绝不会"过度消除"出负数。如果算出 $H(Y \mid X) < 0$，那不是信息论错了，是公式或分布错了（最常见：条件概率 $P(y\mid x)$ 忘了归一化）。

**第三，条件熵与"条件概率"要分清。** 条件概率 $P(y \mid x)$ 是"给定 $x$ 时 $y$ 的可能性"，是一组数；条件熵 $H(Y \mid X)$ 是"已知 $X$ 后 $Y$ 的平均剩余不确定"，是一个数。一个是原始材料，一个是加工后的度量。把 $P(y\mid x)$ 当条件熵用，就像把砖头当房子用。

## 第三步：DL 桥接

**条件熵 → 自回归语言模型。** 主线 6.3 节提过链式法则如何把一句话拆成一串条件熵。到这一节，条件熵的身份更清楚了：**语言模型每一步预测的，正是 $H(\text{下一个 token} \mid \text{前面所有 token})$**。给定 "I love you"，模型对下一个词的分布越确定（条件熵越小），说明它越"懂"语言。训练语言模型，本质上是在逐环压低条件熵。你在 6.3 习题里已经见过这个视角，现在有了条件熵的精确定义，可以更扎实地使用它。

**条件熵 → 分类任务的信息论表述。** 一个分类模型预测 $Y$（类别）给定 $X$（输入）。理想的分类器把 $H(Y \mid X)$ 压得极低——给定图片，类别几乎确定。而 $H(Y) - H(Y \mid X)$ 这个差，是"输入 $X$ 到底提供了多少关于类别 $Y$ 的信息"——它就是下一节的信息增益，也是 6.5 节互信息 $I(X;Y)$。**训练好的模型，就是在最大化这个差。**

**条件熵 → 条件生成。** 文本到图像、图像到文本这些条件生成模型，学的都是条件分布 $p(\text{输出} \mid \text{条件})$——它们的目标就是压 $H(\text{输出} \mid \text{条件})$。条件给得好，输出的不确定就小、生成就更确定；条件给得差，输出就发散。条件熵是理解"条件生成为什么有效"的数学透镜。

现在，你已经有了三把尺子：熵 $H(Y)$（知道前）、条件熵 $H(Y \mid X)$（知道后）、以及它们之间的差。下一节我们把那个差正式命名——**信息增益**：$X$ 到底帮 $Y$ 消掉了多少不确定，是 0.249 bits，还是别的什么。这个问题，将直通决策树，也直通互信息。
