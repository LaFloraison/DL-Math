# §8.2.1 流形与流形假说 —— 习题

本章主线讲了三件事：流形的维度是"内在坐标数"而非"表观空间维数"；流形假说（高维数据住在低维流形上）；编码-解码双映射 $f: \mathbb{R}^d \to \mathbb{R}^n$、$g: \mathbb{R}^n \to \mathbb{R}^d$ 如何被 PCA、自编码器、生成模型实现。下面的习题分三组：**概念检验** 验证核心定义，**计算实践** 把"内在维度"亲手算一遍（含代码验证），**DL 延伸** 把流形假说放回自编码器与 GAN 的真实场景。每题附完整解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：弹簧、纸张、球面，哪个说法正确？

- A. 一根盘成一团的弹簧是 3 维流形，因为它占据三维空间
- B. 球面 $S^2$ 是 2 维流形，因为描述球面上一点需要 2 个坐标
- C. 一张平整的纸是 0 维流形
- D. 手写数字的 784 维像素向量是 784 维流形

**解答**：B。

B 正确：流形的维数 = 描述一点所需的**内在坐标数**。球面用经纬度两个坐标即可，所以是 2 维。A 错：弹簧盘在 3D 空间里，但它只是一根线，用一个坐标（沿弹簧的长度）即可定位，是 **1 维流形**——"占据几维空间"（表观）和"本身几维"（内在）是两回事。C 错：纸是 **2 维**流形（需要两个坐标，x 和 y）。D 错：784 维像素向量所在的**空间**是 $\mathbb{R}^{784}$，但流形假说说的是数据"住在"一个低得多的子流形上——不能把"所在空间维数"当"流形维数"。

**思路点拨**：题眼是"维度 = 内在坐标数"。最容易错的是 A 和 D：前者把"嵌在几维里"当"几维"，后者把"表观维数"当"流形维数"。记住弹簧例子——一维的线盘在三维空间里占据三维的体积感，但它的自由度始终是 1。

### 题 2（判断 + 简答）：流形假说是定理吗？

有人说："流形假说是数学定理，所以任何高维数据都必然住在低维流形上。" 判断对错，并说明在什么条件下流形假说会失效。

**解答**：错。流形假说是**经验假设 (hypothesis)**，不是数学定理。它依赖数据确实具有低维结构这一事实，而这不是所有数据都满足的。

失效条件至少有三：① 数据在流形方向上散布得太厚——如果垂直于流形的噪声与流形本身的延伸差不多大，数据就是"实心的高维云"，不贴在任何低维面上；② 流形严重自交或缠绕，低维坐标无法一致地覆盖它（坐标映射矛盾）；③ 数据的表观维度就是它的真实维度——比如真正独立同分布的 100 维高斯噪声，没有低维结构，PCA 会告诉你它需要接近 100 个主成分才能解释大部分方差。

**思路点拨**：核心是把"hypothesis"这个词钉住。流形假说是一条**工作信念**：它常常成立，所以值得按它设计模型（自编码器瓶颈、GAN 的潜变量），但它不是对世界的保证。判断是否理解，就看你能不能说出"什么时候它会失效"——不会失效的流形假说不是假设，是教条。

### 题 3（简答）：PCA 和自编码器，谁能发现弯的流形？

数据真实地坐在一条螺旋线上（1 维流形，弯成螺旋）。用 PCA 和用自编码器分别去学这个流形，谁的还原误差更小？为什么？

**解答**：**自编码器**误差更小。

PCA 的 $f, g$ 都是**线性映射**——它只能发现"过原点的直线子空间"，用一个 1 维超平面（一条直线）去逼近螺旋线。直线无法贴合螺旋的弯曲，还原误差大（螺旋的弧顶被直线削平）。自编码器的编码器/解码器由神经网络构成，ReLU 等非线性激活让 $f, g$ 可以**弯曲**——它能把螺旋线"摊直"成 1 维坐标（编码），再"弯回"螺旋（解码），还原误差远小于线性方法。

一个直觉检验：PCA 是"最平的流形"，自编码器是"能弯的流形"。螺旋线弯曲程度越大，两者误差差得越远。

**思路点拨**：这是主线"线性 vs 非线性流形学习"的判断题。易错点是把 PCA 的适用面想得太广——PCA 只在数据流形接近线性子空间时才优秀。判据很简单：**流形有多弯，就要用多灵活（非线性）的工具。** 这也解释了为什么深度学习几乎总用非线性激活——线性层叠再多也是线性（还是 PCA 的能力），非线性激活才是让网络能"弯折流形"的开关。

## 二、计算实践

### 题 1（内在维度：从 3 维变到 20 维，圆环还是 2 维吗）

把 2000 个点均匀铺在一个单位圆环上（$\mathbb{R}^2$ 中的 $x_1 = \cos t, x_2 = \sin t$），然后把它塞进 $\mathbb{R}^{20}$：其余 18 个坐标全部置 0，并加一点小噪声 $\mathcal{N}(0, 0.05)$。

(a) 凭直觉判断：PCA 给出的"达到 95% 方差所需主成分数"会随表观维度从 2 变到 20 而显著增大吗？为什么？
(b) 运行代码验证，并解释内在维度估计 $d$ 为什么几乎不变。

**解答**：

(a) **不会显著增大**。表观维度 $n$ 只是"装数据的盒子"的大小；数据本身的自由度（圆环的 2 个参数）才是内在维度。PCA 沿"方差最大的方向"找主成分——圆环在它自己的两个方向上有真实信号，其余 18 个方向方差接近 0（只有噪声），PCA 几乎不会把主成分浪费在噪声方向上。

(b) 代码（即代码.md 的合成实验）：

```python
import numpy as np
from sklearn.decomposition import PCA

rng = np.random.default_rng(0)
for ambient in (2, 5, 20, 100):
    t = 2 * np.pi * rng.random(2000)
    X = np.zeros((2000, ambient))
    X[:, 0], X[:, 1] = np.cos(t), np.sin(t)
    X += 0.05 * rng.standard_normal(X.shape)
    pca = PCA().fit(X)
    cum = np.cumsum(pca.explained_variance_ratio_)
    d = int(np.argmax(cum >= 0.95) + 1)
    print("表观维度 n=%-4d  达到95%%方差所需主成分数 d=%d  前2主成分方差比=%.3f"
          % (ambient, d, cum[1]))
```
```
表观维度 n=2    达到95%方差所需主成分数 d=2  前2主成分方差比=0.994
表观维度 n=5    达到95%方差所需主成分数 d=2  前2主成分方差比=0.995
表观维度 n=20   达到95%方差所需主成分数 d=2  前2主成分方差比=0.995
表观维度 n=100  达到95%方差所需主成分数 d=2  前2主成分方差比=0.995
```

看最后一列：表观维度从 2 涨到 100，前 2 个主成分始终解释 99.5% 的方差，内在维度估计稳定在 2。**把盒子做多大，都改变不了里面的东西是 2 维的。** 这就是流形假说的"降维铁证"：表观维度的膨胀只是给数据多提供了 98 个空房间，数据并没有去住。

**思路点拨**：这是主线 $d \ll n$ 的数值演示。陷阱是把"表观维度大"误当"内在维度大"。PCA 的维度诊断本质是"数一数需要几个坐标才能不损失太多方差"——空房间不提供方差，所以不会被数进去。真实数据（手写数字）和这个圆环的差别只有一条：圆环的"空房间"是我们故意塞进去的 0，手写数字的空房间是像素之间的冗余与噪声——结构完全相同。

### 题 2（从累计方差曲线反推内在维度）

某数据集在 $\mathbb{R}^{50}$ 里，PCA 给出的累计方差比为：

```
k = 1: 0.55   k = 2: 0.92   k = 3: 0.965   k = 4: 0.99   k = 5+: 单调趋近 1.0
```

(a) 用阈值 0.95，估计内在维度 $d$。
(b) 这份数据像是"躺在低维流形上"吗？为什么？
(c) 如果换一个噪声更大的版本，累计方差曲线会变成什么样？

**解答**：

(a) 第一个达到 95% 的 $k$ 是 3（$k=2$ 只有 0.92 < 0.95），所以 $d \approx 3$。

(b) **像**。50 维空间里，3 个主成分就解释了 96.5% 方差——前 3 个坐标扛起了几乎全部信号，剩下 47 维贡献不到 3.5%。这是典型的"低维流形 + 少量冗余/噪声"结构，与主线手写数字实验（64 维用 29 个主成分到 95%）同类。

(c) 噪声增大时，曲线会**变得平缓**：前几个主成分解释的方差占比下降（噪声把信号"稀释"到更多方向上），达到 95% 需要的 $k$ 增大。极端情况下（纯噪声），累计方差几乎线性爬升，$d$ 估计接近表观维度 50——流形假说失效。

**思路点拨**：这是一道"读曲线"题。判断数据是否低维，看的是**累计方差曲线升得多快**：陡峭上升 → 少数坐标承载信息 → 低维流形；平缓爬升 → 信息均匀散布 → 高维实心。易错点是只看"第一个主成分解释多少"，忽略整个曲线形状——前 2 个主成分 92% 和 50% 的数据，曲线形状完全不同，低维程度也不同。

### 题 3（编码-解码的双向旅行）

设流形假说成立，自编码器的编码器是 $g: \mathbb{R}^n \to \mathbb{R}^d$，解码器是 $f: \mathbb{R}^d \to \mathbb{R}^n$。

(a) 给定一张真实图片 $x$，先编码再解码，得到 $\hat x = f(g(x))$。在理想情况下 $\hat x$ 和 $x$ 应该有什么关系？这个关系在训练时用什么损失来逼近？
(b) 如果我从 $f$ 的输出侧取一个**不**在流形上的点 $\hat x$（比如给一张真实图片加上强烈的随机噪声），把它编码成 $z = g(\hat x)$，再解码 $f(z)$——直觉上会发生什么？

**解答**：

(a) 理想情况下 $\hat x \approx x$，即 $f \circ g \approx \mathrm{id}$——编码再解码几乎无损还原。训练时用**重建损失 (reconstruction loss)** 逼近，最常用的是均方误差 $\mathcal{L} = \mathbb{E}_x[\|x - f(g(x))\|^2]$（或对图像用二值交叉熵）。这个损失强迫 $g$ 提取"足够信息"的低维坐标，强迫 $f$ 学会把坐标还原成真实图片——两者合作把流形结构编码进瓶颈 $z$。

(b) 加噪声后的 $\hat x$ 偏离了数据流形。编码器 $g$ 把它压到某个 $z$，解码器 $f$ 把这个 $z$ 渲染回**流形上的一个点**——因为 $f$ 只学会了"流形坐标 → 真实图片"，它不会输出"流形外的噪声"。所以 $f(g(\hat x))$ 通常比 $\hat x$ 更"干净"、更接近真实分布。这正是**去噪自编码器 (denoising autoencoder)** 的核心思想：故意污染输入，让模型学会"把偏离流形的点拉回流形"。扩散模型的去噪步骤也是这个原理的高维版本。

**思路点拨**：这道题把主线 $f, g$ 定义块变成可操作的理解。(a) 考的是"自编码器到底在优化什么"——不是记忆图片，而是让 $f \circ g \approx \mathrm{id}$。(b) 考的是"$f$ 的输出为什么总在流形上"——这是解码器训练方式决定的：它只见过（流形坐标 → 真实图片）的配对。理解这一点，你就理解了为什么"编码-解码"天然是去噪机。

## 三、DL 延伸

### 题 1（GAN 的生成器就是那个 $f$）

一个 GAN 的生成器接受随机噪声向量 $z \sim \mathcal{N}(0, I)$（通常 100 维），输出一张 $64\times64\times3 = 12288$ 维的图片。

(a) 用流形语言描述：生成器在做什么？$z$ 是什么？$d = 100$、$n = 12288$ 各代表什么？
(b) 为什么 GAN 训练好之后，两个噪声 $z_1, z_2$ 的**线性插值** $z = (1-\alpha)z_1 + \alpha z_2$ 生成的图片之间往往呈现平滑的语义渐变（比如从"微笑的人"过渡到"严肃的人"）？

**解答**：

(a) 生成器就是解码映射 $f: \mathbb{R}^{100} \to \mathbb{R}^{12288}$。$z$ 是低维流形 $M$ 上的坐标（100 维潜变量），$d = 100$ 是潜在自由度，$n = 12288$ 是表观像素维度。训练后，$f$ 学会把 $z$ 渲染成"看起来真实"的图片——它生成的所有图片都坐落在（或非常靠近）真实数据流形上。GAN 的判别器，本质上是在判断"这个点到底在不在流形上"。

(b) 因为 $z$ 是流形的**坐标**，坐标空间是（近似）平直、连续的。如果流形被 $f$ 光滑地参数化，那么 $z$ 空间里连接两个点的直线段 $(1-\alpha)z_1 + \alpha z_2$，其像 $f(z)$ 就是流形上连接两张图片的光滑路径——沿途每一帧都是"流形上的合理图片"，于是语义平滑渐变。这正是"流形坐标具有连续语义"的直接体现。

**思路点拨**：这道题把主线 DL 桥接的 GAN 例子展开。核心等式是 **生成器 = $f$，潜变量 = $z$，像素 = $x$**。最容易的空泛回答是"GAN 生成图片"——要落到 $f: \mathbb{R}^d \to \mathbb{R}^n$ 这个映射上。(b) 的插值问题考的是"坐标空间的平直性"：只有在 $f$ 是光滑双射（近似）的前提下，直线插值才是流形上的测地线近似。如果流形有严重自交或折叠，插值会产生奇怪图片——这是已知的 GAN 伪影，也是流形结构不理想的表现。

### 题 2（自编码器瓶颈的维度选择）

你想用自编码器压缩人脸图片，瓶颈层维度 $d$ 有三个候选：$d = 2$、$d = 64$、$d = 4096$（等于输入维度）。

(a) 从流形假说角度，哪个最合理？为什么？
(b) 选 $d = 4096$（无压缩）会出什么问题？选 $d = 2$ 呢？

**解答**：

(a) $d = 64$ 最合理。流形假说说真实人脸数据住在低维流形上——假设内在维度是几十量级，那么 $d = 64$ 既足够表达流形坐标（重建误差小），又远小于输入维度（实现了压缩，强迫 $g$ 提取本质特征）。选多大 $d$，本质上是对流形内在维度的一次工程估计。

(b) $d = 4096$：瓶颈没有压缩，网络退化成"逐像素过一遍"——它可能直接学成恒等映射，什么特征也没提取（内存/过拟合风险大，流形学习失效）。$d = 2$：压缩过度——人脸的内在维度远不止 2，瓶颈容量不够，重建会严重模糊、丢失身份信息。**$d$ 是模型对流形维度的"赌注"**：赌得太小，容量不够；赌得太大，失去压缩意义。

**思路点拨**：这是把"内在维度 $d$"变成工程选择的题。易错点是以为"$d$ 越大越好"（那就不叫压缩了）。判据：$d$ 应大致匹配数据的内在维度——太大则模型偷懒学恒等，太小则重建失真。更精确的做法是先用 PCA（代码.md 的方法）估计内在维度，再据此设定瓶颈维度——**先用线性工具量流形，再用非线性模型学流形**，这是表示学习领域的标准工作流。
