# 代码：优化问题长什么样——手工做一个下山者

**目标**：主线里我们只"想象"了雾里下山。这里把它变成真实的代码：定义一个目标函数，用一个**暴力网格搜索 (brute-force grid search)** 去逼近它的最小值，再和解析解（微积分算出的真值）对照。你会亲眼看到"优化"的最低配版本长什么样——也为后面所有聪明的优化器（梯度下降、Adam 等）留好了一个能比较的基准。

## 层一：完整脚本

```python
import numpy as np

# 1. 定义一个一元目标函数：J(theta) = (theta - 3)^2 + 1
def objective(theta):
    return (theta - 3.0) ** 2 + 1.0

# 2. 解析最小值：微积分告诉我们极值在 theta* = 3，最优值 J* = 1
THETA_STAR = 3.0
J_STAR = 1.0

# 3. 网格搜索：在 [-10, 10] 上均匀撒 2001 个点，逐点评估，取最小
grid = np.linspace(-10.0, 10.0, 2001)   # 形状 (2001,)
values = objective(grid)                 # 形状 (2001,)，向量化评估
best_idx = np.argmin(values)             # 最小值的下标
theta_grid = grid[best_idx]              # 网格搜索找到的最优点
j_grid = values[best_idx]                # 网格搜索找到的最优值

# 4. 对照：网格搜索 vs 解析解，误差有多大？
err_theta = abs(theta_grid - THETA_STAR)
err_j = abs(j_grid - J_STAR)

print(f"网格搜索最优点 theta* = {theta_grid:.6f}  (解析解 {THETA_STAR})")
print(f"网格搜索最优值 J*    = {j_grid:.6f}  (解析解 {J_STAR})")
print(f"theta 误差 = {err_theta:.2e},  J 误差 = {err_j:.2e}")
```

输出：

```
网格搜索最优点 theta* = 3.000000  (解析解 3.0)
网格搜索最优值 J*    = 1.000000  (解析解 1.0)
theta 误差 = 0.00e+00,  J 误差 = 0.00e+00
```

一个藏在网格里的巧合：因为 $\theta^* = 3$ 恰好落在我们撒的网格点上，误差是精确的 0。把脚本里的 `3.0` 改成 `np.pi` 再跑一遍，你立刻会看到网格搜索的代价——最优点落在两个网格点之间，误差不再为零，而要想误差更小，只能把网格撒得更密。**这就是"暴力"的本质：精度全靠点数堆。**

## 层二：分步逐函数拆解

### 步骤 1：定义目标函数

```python
def objective(theta):
    return (theta - 3.0) ** 2 + 1.0
```

#### `objective` —— 一元标量目标函数

`(theta - 3.0) ** 2 + 1.0` 是主线里的 $f(x) = (x-3)^2 + 1$ 的 Python 翻译。这是一个**开口向上的抛物线**，唯一的最低点在 $\theta = 3$ 处。

**操作**：把输入 $\theta$ 代入 $(\theta-3)^2 + 1$ 计算标量输出。
**输入**：`theta` —— 标量 `float`（决策变量）。也可以传一个 NumPy 数组（形状 `(N,)`），此时 `** 2` 和 `+` 都是**逐元素 (elementwise)** 运算，返回形状 `(N,)` 的数组——这正是第 3 步向量化评估能跑的原因。
**输出**：标量 `float`，即该点上的目标值 $J(\theta)$。
**可调参数**：
- 把 `3.0` 改成别的数，最低点的位置就挪走；改成负数，抛物线翻成开口向下——优化就从"最小化"变成"最大化"（取相反数即可）。
- 把 `(theta - 3.0) ** 2` 换成 `(theta - 3.0) ** 2 * np.sin(theta * 5.0)` 之类，函数就有了多个洼地——网格搜索依然能找到最小值，但你会发现"找到的到底是不是全局最小"开始变得可疑。这为 §5.4 全局 vs 局部最优埋下了引线。

**对应数学**：$J(\theta) = (\theta - 3)^2 + 1$，主线定义块里的**目标函数**。

---

### 步骤 2：写死解析解

```python
THETA_STAR = 3.0
J_STAR = 1.0
```

**操作**：把微积分算出的精确答案存成常量，作为"真值"。
**输入**：无（硬编码）。
**输出**：两个 `float`——最优变量 $\theta^* = 3$ 和最优值 $J^* = 1$。
**可调参数**：这是基准答案，理论上不该改。但你可以故意改错它，观察第 4 步的误差如何变大——**用已知真值检验求解器**，是优化调试的第一步。

**对应数学**：由 $\frac{dJ}{d\theta} = 2(\theta-3) = 0$ 解得 $\theta^* = 3$，代入得 $J^* = 1$。微积分在前四章是主角，在这里只是"裁判"。

---

### 步骤 3：网格搜索——最笨但最诚实的优化器

```python
grid = np.linspace(-10.0, 10.0, 2001)   # 形状 (2001,)
values = objective(grid)                 # 形状 (2001,)
best_idx = np.argmin(values)             # 标量 int
theta_grid = grid[best_idx]              # 标量 float
j_grid = values[best_idx]                # 标量 float
```

#### `np.linspace(-10.0, 10.0, 2001)` —— 生成均匀网格

**操作**：在闭区间 $[-10, 10]$ 内均匀取 2001 个点，相邻两点间隔 $\frac{10-(-10)}{2001-1} = 0.01$。
**输入**：`start=-10.0`（起点）、`stop=10.0`（终点，含）、`num=2001`（点数）。
**输出**：形状 `(2001,)` 的一维数组。每个位置是候选的决策变量值。
**可调参数**：
- `num` 越大，网格越密，搜索越精确，但评估次数线性增长。从 2001 提到 20001，误差从可能 0.005 级缩到 0.0005 级——**精度和计算量是线性交换**，这就是"暴力"的边界。
- `start`/`stop` 圈定搜索范围。如果真值 $3$ 不在 $[-10,10]$ 里，网格搜索会找错——**它只能看到你让它看的地方**。这个局限在 §5.3.6 梯度下降里会以另一种形式重现。

#### `objective(grid)` —— 向量化批量评估

**操作**：一次性把 2001 个 $\theta$ 同时代入目标函数。NumPy 的逐元素运算让这次调用等价于一个 for 循环，但快几个数量级。
**输入**：形状 `(2001,)` 的数组。
**输出**：形状 `(2001,)` 的数组，第 $i$ 个元素是 $J(\text{grid}[i])$。
**可调参数**：无直接参数。若目标是多元函数，`grid` 要换成多维网格（`np.meshgrid`），评估变成对每个格点的批量计算——代价呈维度指数爆炸（**维度诅咒**），这正是梯度下降存在的理由之一。

#### `np.argmin(values)` —— 找最小值的位置

**操作**：扫描 2001 个值，返回最小元素的**下标**（第一个遇到的最小值）。注意它返回的是下标，不是值本身。
**输入**：形状 `(2001,)` 的数组。
**输出**：标量 `int`——`values` 中最小值所在的位置。
**可调参数**：无。若想找最大值，用 `np.argmax`。

**对应数学**：这一步执行的是 $\arg\min_{x \in \text{grid}} J(x)$——只不过是在离散的候选集上取精确最小。它直接对应主线定义块里的 $\arg\min$。

---

### 步骤 4：误差对照

```python
err_theta = abs(theta_grid - THETA_STAR)
err_j = abs(j_grid - J_STAR)
```

**操作**：用 `abs`（绝对值）计算网格解与解析解的偏差，量化搜索质量。
**输入**：`theta_grid`、`j_grid`（网格解）、`THETA_STAR`、`J_STAR`（解析解）。
**输出**：`err_theta`、`err_j` 两个 `float`——偏差的绝对值。
**可调参数**：无。

**对应数学**：这是主线里"逼近方法"的量化——我们算不出保证最优时，就用"离真值多远"来评判方法好坏。这个概念在整章反复出现：梯度下降的收敛证明（§5.3.6）研究的正是这个误差如何随迭代次数缩小。

## 如果想让代码更强

- 加一个 `wiggly` 版本目标函数（如 `objective(theta) + 0.5*np.cos(theta*8)`），画出曲线，观察局部极小如何骗过网格搜索——只要网格不够密，某个洼地就会被漏掉。这是进入 §5.4 的最佳引子。
- 把目标换成二元函数（如 $J(\theta_1,\theta_2) = \theta_1^2 + \theta_2^2$），用 `np.meshgrid` + 等高线图可视化，你会第一次"看到"损失面。
- 配一段 `matplotlib` 画 `grid` vs `values` 的曲线，标出最小值点——优化从此有了眼睛。

**禁止黑盒的说明**：这里每一步都是裸 NumPy 运算，没有调用任何优化库。你会看到"优化"在最低层是什么——评估、比较、挑选。下一节的梯度下降，只是把"撒点比较"换成"朝坡度方向迈步"，本质没变，聪明得多。
