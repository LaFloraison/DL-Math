# §7.6.3 异质图 —— 习题

主线给了异质图的两条路：异质 GNN（分类型聚合）与元路径（跨类型路径）。下面三组习题检验你是否理解"类型即语义"这个核心。每题附解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：同质 GCN 在异质图上的核心问题是什么？

- A. 计算太慢
- B. 把所有节点、边一视同仁地聚合，丢失了"类型语义"
- C. 参数太多
- D. 无法反向传播

**解答**：B。

**思路点拨**：同质 GCN 用一套 $W$、一个邻接矩阵处理所有邻居——"张伟"（人）和"北京"（地点）被当成同类，"位于"和"任职"被当成同种关系，语义被抹平。A、C 是工程问题，D 错（GCN 可训练）。常见错选 C——把"异质图的代价（参数多）"误当"同质图的问题"。

### 题 2（简答）：异质 GNN 和元路径方法，各解决什么问题？

**解答**：**异质 GNN**：解决"邻居类型不同，怎么聚合"——按类型分组，每类用各自的变换矩阵 $W_\tau$，再组合（类型即参数）。**元路径**：解决"关系跨类型，怎么表达"——用"按类型走的路径模板"（如"作者-论文-作者"）抓取跨类型的间接语义（类型即路径）。前者管"怎么听"，后者管"听谁"。

**思路点拨**：答题要成对给出"解决的问题 + 手段"。核心区分：异质 GNN 分参数，元路径选路径。常见错误是混为一谈。

### 题 3（判断）：异质图越"分得细"越好吗？

**解答**：不是。类型粒度是权衡：粒度太粗丢语义（所有关系一种类型），太细参数爆炸（每类一套 $W_\tau$，小数据易过拟合）。元路径本身也要人设计——选错元路径就捕捉错语义。**异质不是"越细越好"，而是"分到刚好保住语义"。**

**思路点拨**：这是主线边界声明的直考。答题要点是"粒度权衡 + 元路径要设计"。常见错误是"类型越多越精确"。

## 二、计算实践

### 题 1（手算 + NumPy：共同作者元路径）

作者 A1 写论文 P1、P3；A2 写 P2、P3；A3 写 P1。

(a) 写"作者-论文"矩阵 $M$（行=作者，列=论文）。
(b) 算 $M M^\top$，解释每个元素含义。
(c) A1 的共同作者有谁？共享几篇？

**解答**：

(a) $M = \begin{pmatrix}1&0&1\\0&1&1\\1&0&0\end{pmatrix}$（P1,P2,P3）。

(b) $M M^\top = \begin{pmatrix}2&1&1\\1&2&0\\1&0&1\end{pmatrix}$。$(i,j)$ = 作者 i 与作者 j 共同写的论文数（对角线 = 自己写的论文数，2 表示 A1 写 2 篇）。

(c) A1 行 $[2,1,1]$（非对角线）：A2 共享 1 篇（P3）、A3 共享 1 篇（P1）。共同作者 {A2, A3}。

**NumPy 验证**：
```python
import numpy as np
M = np.array([[1,0,1],[0,1,1],[1,0,0]], dtype=float)
MM = M @ M.T
np.fill_diagonal(MM, 0)
print("共同作者矩阵：\n", MM)
```
```
共同作者矩阵：
 [[0. 1. 1.]
  [1. 0. 0.]
  [1. 0. 0.]]
```

**思路点拨**：$M M^\top$ 就是元路径"作者-论文-作者"的路径计数（§7.2 的"矩阵幂数路径"的异质版）。常见错误：忘了 $\top$ 的方向——$M^\top M$ 数的是"论文-作者-论文"（共享作者的论文对），语义完全不同。记住"从谁出发就谁在前"。

### 题 2（手算：分类型聚合）

异质图：作者 A 写论文 P；机构 O 雇佣 A。特征：$h_A=[1,0]$、$h_P=[0,1]$、$h_O=[1,1]$。用"分类型聚合"：A 的表示 = $W_{论文}A$ 邻居贡献 + $W_{机构}A$ 邻居贡献。设 $W_P = [[1,0],[0,1]]$、$W_O = [[0.5,0],[0,0.5]]$。手算 A 的异质表示。

**解答**：A 的"论文邻居"是 P：$W_P h_P = [0,1]$。A 的"机构邻居"是 O：$W_O h_O = [0.5, 0.5]$。A 的异质表示 = 两类之和 $= [0.5, 1.5]$。**注意"论文段"（$[0,1]$，来自 P）与"机构段"（$[0.5,0.5]$，来自 O）的贡献来源可辨**——若混成一个聚合（$[0,1]+[1,1]$ 求和），你分不清哪部分是"写论文"哪部分是"被雇佣"。

**思路点拨**：核心是"分类型 = 每类邻居各走各的 $W_\tau$，来源可辨"。常见错误是把 $W_P$、$W_O$ 当成同一个权重——它们的区别正是"类型即参数"的意义。

## 三、DL 延伸

### 题 1（场景设计）：学术网络的元路径设计

一个学术推荐系统：作者、论文、会议三类节点。想推荐"可能合作的作者"。请设计：(a) 一条合适的元路径及其语义；(b) 为什么这条元路径比"直接找共同论文"更丰富？

**解答**：(a) 元路径"作者-论文-会议-论文-作者"（$A \xrightarrow{\text{写}} P \xrightarrow{\text{发表}} C \xrightarrow{\text{发表}^{-1}} P \xrightarrow{\text{写}^{-1}} A$）——语义："两位作者在同一会议发表过论文"，捕捉"学术方向相近但未合作"的潜在合作者。更长的元路径可加机构："作者-机构-机构-作者"（同机构背景）。(b) 直接共同论文只捕捉"已经合作过"；元路径能捕捉"**没合作过但学术轨迹重叠**"（同会议、同方向）——这正是推荐"潜在合作"比"已知合作"更有价值的地方。

**思路点拨**：答题要给出具体元路径 + 其语义 + 与"直接共同论文"的对比。加分点：指出"元路径长度编码关系的远近"。常见错误是只给"作者-论文-作者"一种，没根据任务（推荐**潜在**合作）设计更长的元路径。

### 题 2（概念连线）：异质 × 动态 × 大规模——三道坎的合流

一个实时知识图谱：节点有实体多类、边有多类关系、每秒新增三元组、规模十亿。请说明三道坎（§7.6.1–7.6.3）如何在这个系统里**同时**出现，以及各自的对策如何配合。

**解答**：(1) **异质**——实体/关系多类型，用异质 GNN（每类关系 $W_r$）或元路径处理（§7.6.3）。(2) **动态**——每秒新增三元组，用增量/流式更新，只重算受影响子图（§7.6.2）。(3) **大规模**——十亿规模，用采样 + mini-batch，每批只展开种子子图（§7.6.1）。三者配合：采样先圈定"当前批次涉及的子图"（大规模），增量决定"这个子图里哪些要重算"（动态），异质决定"这些重算怎么分类型"（异质）。**真实系统不是三道坎选一道，而是三道坎叠着过。**

**思路点拨**：答题锚点是"三对策如何配合成一个流水线"。能把"采样圈范围 → 增量定更新 → 异质定变换"串起来就是满分。常见错误是只答一道坎。这题是全章 §7.6 的收官整合题。
