# 习题：量子计算导论

## 第一组：概念检验

### 1.1 判断正误并说明理由："量子计算对所有问题都比经典计算快。"

**解答**：错误。量子加速是**结构性**的——它只奖励叠加恰好对得上问题结构的问题。Grover 对无结构搜索给 $O(\sqrt{N})$（平方根加速，且轮数不是越多越好）；Shor 对因数分解给多项式级（指数级改写），但即便如此，"测量破坏叠加"的代价意味着算法必须精心设计才能让收益大于损失。排序、哈希查找这类经典本就有 $O(\log N)$ 或 $O(1)$ 的问题，量子没有优势甚至更慢。教材说量子计算"could change deep learning"——用的是"could"，因为它不是免费的万能加速器。

**思路点拨**：很多人看到"量子计算机比经典快"就全盘接受。抓住两个反例：(1) 有结构的问题经典更快；(2) 振幅放大轮数翻倍反而失效（见代码实验 1）。加速是有精确适用域的。

### 1.2 为什么测量是量子计算"最深的沟"？用叠加与坍塌的关系回答。

**解答**：量子比特处于叠加态 $|\psi\rangle = \alpha|0\rangle + \beta|1\rangle$ 时，同时"携带"两种可能；但**测量（observation）会让它坍塌**到 $|0\rangle$ 或 $|1\rangle$ 之一，且结果是随机的——只能知道概率 $|\alpha|^2$ 和 $|\beta|^2$，不知道本次会吐哪一个。这造成一个不对称：不测量时叠加提供"同时性"（并行之力），测量时叠加被破坏、只能得到单个概率结果（并行的代价）。"同时知道所有门"和"推开某一扇门"不是一回事——把叠加的并行"读出来"，必须以破坏叠加为代价。所以量子算法的全部艺术，在于尽量让"读出来"的那一下损失最小。

**思路点拨**：这是本章反复出现的主题。别答成"测量就是读出结果"——要点在"**读出 = 破坏**"。Ghirardi 等学者为这个矛盾争论了几十年，可见它不是小问题。

### 1.3 你被要求在一个无序数据库（$N = 10^8$ 条）里找目标。分别给出经典最坏查询次数与 Grover 的理论轮数，并解释轮数公式的来历。

**解答**：经典最坏 $N = 10^8$ 次。Grover 理论轮数约 $\frac{\pi}{4}\sqrt{N} = \frac{\pi}{4} \times 10^4 \approx 7854$ 次。轮数公式来历：每次振幅放大把目标的概率相角抬高 $2\theta$，其中 $\theta = \arcsin(1/\sqrt{N}) \approx 1/\sqrt{N}$（目标初始振幅很小，相角近似等于振幅）；从接近 0 抬到 $\pi/2$ 需要约 $\frac{\pi/2}{2\theta} = \frac{\pi}{4}\sqrt{N}$ 轮。

**思路点拨**：不必死记，关键是理解"轮数与 $\sqrt{N}$ 成正比，不是与 $N$ 成正比"。$10^8$ 的平方根是 $10^4$，是 $N$ 的万分之一的量级。

## 第二组：计算实践

### 2.1 手算 + 验证：三比特的均匀叠加向量

写出 3 个量子比特的均匀叠加向量（共 $2^3 = 8$ 个基态），确认每个振幅的模平方之和为 1。然后用代码验证。

**解答**：均匀叠加每个振幅为 $1/\sqrt{8}$。验证 $\sum_{i=0}^{7} |1/\sqrt{8}|^2 = 8 \times \frac{1}{8} = 1$。测量得到任一基态的概率都是 $1/8$。

```python
import numpy as np
psi = np.ones(8, dtype=complex) / np.sqrt(8)
print(f"振幅 = {psi}")                # 每个都是 0.35355339...
print(f"模平方和 = {np.sum(np.abs(psi)**2):.6f}")   # 1.0
```

输出：

```text
振幅 = [0.35355339+0.j ...]           # 8 个 1/√8
模平方和 = 1.000000
```

**思路点拨**：这道题检验"归一化法律"——不管叠加装下多少个状态，概率总和恒为 1。代码里的 `np.abs(psi)**2` 正是主线定义块 $|\alpha|^2$ 的实现。

### 2.2 手算：Grover 最优轮数，$N = 10^6$ 与 $N = 4$

用公式 $\lceil \frac{\pi}{4}\sqrt{N} \rceil$ 分别计算 $N=10^6$ 和 $N=4$ 的轮数。

**解答**：
- $N = 10^6$：$\sqrt{N} = 10^3$，$\frac{\pi}{4} \times 10^3 \approx 785.4$，取整 $\lceil 785.4 \rceil = 786$。
- $N = 4$：$\sqrt{N} = 2$，$\frac{\pi}{4} \times 2 \approx 1.57$，取整 $\lceil 1.57 \rceil = 2$。

验证 $N=4$：经典最坏 4 次，Grover 2 轮。可以手算验证：4 个等振幅 $1/2$ 的状态，标记目标 → 均值变 $-1/8$？让我们精确算：初始 $\psi = [\frac12,\frac12,\frac12,\frac12]$。第 1 轮：标记目标（下标 0）→ $[-\frac12,\frac12,\frac12,\frac12]$；均值 $= (-\frac12 + \frac32)/4 = \frac{1}{4}$... 更正：均值 $= \frac{-0.5+0.5+0.5+0.5}{4} = \frac{1}{4} = 0.25$。绕平均翻转：$2 \times 0.25 - \psi = 0.5 - \psi$ → $[0.5-(-0.5), 0.5-0.5, 0.5-0.5, 0.5-0.5] = [1, 0, 0, 0]$。目标概率已经是 1，一轮就够（因为 $N=4$ 是特殊情形，$\theta = \arcsin(1/2) = \pi/6$，$2\theta = \pi/3$，只需 $\frac{\pi/2}{\pi/3} = 1.5$ 轮，取整后实际 1-2 轮都行）。

```python
import numpy as np
for N2 in (10**6, 4):
    r = int(np.ceil(np.pi / 4 * np.sqrt(N2)))
    print(f"N = {N2}: Grover 轮数 = {r}")
```

输出：

```text
N = 1000000: Grover 轮数 = 786
N = 4: Grover 轮数 = 2
```

**思路点拨**：$N=4$ 是练习手算的黄金尺寸——振幅只有 4 个，可以一步一步写出翻转过程。注意 $N=4$ 时一轮就能命中（因为 $\theta$ 较大），公式给 2 是"保守取整"。真实实现里，$N$ 很小时轮数公式的近似性会显现。

### 2.3 验证：振幅放大轮数翻倍为何失效？

用代码演示：对 $N=10^6$，分别做 393、786、1572 轮放大，打印目标概率。

**解答**：见《代码.md》实验 1 的输出——393 轮 → 0.5016，786 轮 → 1.0000，1572 轮 → 0.0000。轮数翻倍，概率从 1.0000 跌回 0.0000。原因是绕平均翻转是**周期运动**：目标振幅像钟摆一样从 0 荡到最大，再荡过头、荡回零点。轮数是最优值两倍时，正好荡回起点的零点。

```python
import numpy as np
N = 10**6; target = N - 1
def amplify(psi, rounds):
    for _ in range(rounds):
        psi[target] *= -1
        psi = 2 * np.mean(psi) - psi
    return psi
optimal = int(np.ceil(np.pi / 4 * np.sqrt(N)))
for f in (0.5, 1.0, 2.0):
    p = amplify(np.ones(N, dtype=complex)/np.sqrt(N), int(f * optimal))
    print(f"轮数 = {int(f*optimal):6d} → P(目标) = {np.abs(p[target])**2:.4f}")
```

输出：

```text
轮数 =    393 → P(目标) = 0.5016
轮数 =    786 → P(目标) = 1.0000
轮数 =   1572 → P(目标) = 0.0000
```

**思路点拨**：很多初学者以为"多试几次更保险"。这道题逼你看清：量子加速对**参数精度**极其敏感——轮数是个要精确计算的值，不是越大越好。这一点与经典直觉（多查几次总没错）形成尖锐反差。

## 第三组：DL 延伸

### 3.1 深度学习训练的瓶颈之一是矩阵乘法 $Wx$（$W$ 是 $n \times n$ 权重矩阵）。有人提出用"量子矩阵乘积估计"加速——在 $O(\log n)$ 步内读出 $\langle y | W | x \rangle$ 的近似值。请判断：这个方案能直接替代现有的 `W @ x` 吗？为什么？

**解答**：不能直接替代。两点关键限制：
1. **量子方法读出的是"统计量/内积"而非"完整结果"**。测量只能吐概率，无法一次吐出整个 $Wx$ 向量——你需要重新编码、重复测量、再拼接，拼接成本可能吃掉优势。
2. **数据编码成本**。把经典数据 $x$ 编码成量子振幅 $\alpha_i$ 本身要时间；$x$ 的维度越大，编码越贵。当编码成本接近或超过 $O(\log n)$ 的加速时，整体收益归零（这正是教材在 §12.3.2 点名的"converting regular data into quantum states … can be complicated and time-consuming, sometimes canceling out the speed advantages"）。

所以现实中的 QML 只对"最终只需要内积/期望"的任务（如某些核方法、注意力分数）可能划算——完整的层前向传播仍然是经典为主。

**思路点拨**：这道题的核心是"编码成本与计算加速的赛跑"。别只答"能，因为快"——必须把测量破坏叠加和编码成本这两个拦路虎写进去。

### 3.2 量子机器学习算法（如量子聚类、QSVM、量子回归，见 §12.3.2）目前最大的工程障碍是什么？如果一个量子模型把 10 天的股票收盘价编码后预测失误（预测 $140 而非实际的 $175），最可能的原因是什么？

**解答**：最大障碍是**量子态的稳定性（相干时间 coherence time）与误差纠正**——当前量子计算机容易出错，只能短暂保持量子态。预测失误最可能的原因是：数据编码过程中的误差 + 量子态过早坍塌/退相干（decoherence），导致计算中途失真。教材的例子（$150,152,148,...,170$ 十个数 → 预测 $140 而非 $175）正是为了说明：即便数据成功编码，量子系统的不稳定性也会让结果跑偏。这也是"诚实划定边界"：NISQ（有噪声中等规模量子）时代，算法的理论加速和硬件的实际误差之间有一条鸿沟。

**思路点拨**：别答成"量子算法算错了"——要点是**硬件层面的不稳定性**（退相干、误差），而不是算法逻辑错误。同时注意"编码成本"是另一个独立障碍，二者不要混淆。
