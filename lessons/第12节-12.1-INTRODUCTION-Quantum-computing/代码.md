# 代码：一百扇门的两种开法——把"逐个查询"和"叠加+放大"同时摆上台面

主线里那个城堡寓言说了两件事：经典计算机**一扇一扇翻门**，量子计算机**一步装下所有可能，再用振幅放大把正确的门"聚"出来**。这一课不引入任何量子库，只用 NumPy 亲手把这两套机制都写出来，让它们在一百万个条目的数据库上对垒。你将亲眼看到：

- 经典最坏要查多少次；
- 叠加向量一次能装下多少个状态；
- Grover 式的振幅放大，大约 $\lceil \frac{\pi}{4}\sqrt{N}\rceil$ 轮就能把目标的概率抬到接近 1。

---

## 层一：完整脚本

```python
import numpy as np                      # 唯一的工具库：向量、复数和 mean 都来自这里

def classical_search(database, target): # ① 经典：一扇一扇翻
    """返回找到 target 所需的查询次数；最坏情形是翻完整本才找到。"""
    for i, item in enumerate(database):
        if item == target:
            return i + 1
    return len(database)

def make_superposition(n_items):        # ② 叠加：一步把 N 个状态同时装进一个向量
    """返回长度 n_items 的均匀叠加向量：每个振幅 = 1/√N。"""
    return np.ones(n_items, dtype=complex) / np.sqrt(n_items)

def grover_like_amplify(psi, target, rounds):  # ③ 振幅放大：把目标概率越聚越强
    """对叠加向量做 rounds 轮 '标记+绕平均翻转'，目标振幅被逐轮抬高。"""
    for _ in range(rounds):
        psi[target] *= -1               # 标记：翻转目标的相位
        avg = np.mean(psi)              # 求全部振幅的平均值
        psi = 2 * avg - psi             # 绕平均翻转：偏离均值越远的振幅被抬得越高
    return psi

# ---- 经典：最坏情形——目标恰好是最后一个 ----
N = 1_000_000
database = np.arange(N)
worst = classical_search(database, N - 1)
print(f"经典最坏查询次数  = {worst}")

# ---- 叠加：一次装下 N 个可能状态 ----
psi = make_superposition(N)
print(f"叠加向量长度      = {len(psi)}   (一个向量装下 {N} 个状态)")

# ---- Grover 式放大：约 (π/4)·√N 轮 ----
target = N - 1
rounds = int(np.ceil(np.pi / 4 * np.sqrt(N)))
psi = grover_like_amplify(psi, target, rounds)
probs = np.abs(psi) ** 2
print(f"Grover 轮数       = {rounds}")
print(f"目标被找到的概率  = {probs[target]:.4f}")
print(f"经典查询数 / 轮数 = {worst / rounds:.1f} 倍")
```

运行输出（Python 3.11 + NumPy）：

```text
经典最坏查询次数  = 1000000
叠加向量长度      = 1000000   (一个向量装下 1000000 个状态)
Grover 轮数       = 786
目标被找到的概率  = 1.0000
经典查询数 / 轮数 = 1272.3 倍
```

一百万次 vs 七百八十六次。经典在"翻门"上花了全部力气，量子在"叠加"上一步到位、再靠七百多轮放大把正确的那扇门"聚"出来。下面把每一行拆开。

## 层二：分步逐函数拆解

### 步骤 1：导入 NumPy —— 向量、复数、mean 全部来自这里

```python
import numpy as np
```

本课刻意不引入任何量子库（Qiskit 等）。量子计算的数学核心——把状态写成向量、把操作写成矩阵、把概率算成振幅模平方——用 NumPy 就能完整表达。真正理解了"向量就是状态"，将来读任何量子库的文档都不会发怵。

#### `import numpy as np` —— 引入数值计算的工具箱

**操作**：加载 NumPy 并绑定别名 `np`。
**输入**：无。
**输出**：句柄 `np`，提供 `np.ones`、`np.mean`、`np.abs`、`np.sqrt`、`np.pi`、`np.arange`。
**可调参数**：无。
**对应数学**：$1/\sqrt{N}$ 里的 $\sqrt{N}$ 来自 `np.sqrt`，放大轮数的公式 $\frac{\pi}{4}\sqrt{N}$ 里的 $\pi$ 来自 `np.pi`。这一行不为任何公式服务，它为所有公式提供零件。

---

### 步骤 2：定义 `classical_search` —— 一扇一扇翻门

```python
def classical_search(database, target):
    for i, item in enumerate(database):
        if item == target:
            return i + 1
    return len(database)
```

#### `classical_search` —— 经典顺序搜索：最坏翻完整本

**做什么**：从第一个元素开始逐个比对，找到目标立即返回"已查询的次数"。如果目标恰好是最后一个，就返回 `N`——这就是"最坏情形"。
**操作**：`enumerate(database)` 同时给出下标 `i` 和元素 `item`；`if item == target` 命中即返回；循环自然结束则说明目标不在，返回 `len(database)`。
**输入**：
- `database`：一维数组，本例是 `np.arange(N)`，即 `[0, 1, ..., N-1]`。
- `target`：要找的值，标量。本例取 `N - 1`（最后一个元素），故意构造最坏情形。
**输出**：整数，找到目标所需的最少查询次数。
**可调参数**：
- `target` 换成 `0`（第一个元素），返回 `1`——最幸运的情形。换成中间某个值，返回约 `N/2`。**经典搜索的查询次数与目标位置线性相关**，这是它与 Grover 的 `√N` 之间最本质的差别。
- 能不能加参数？可以加一个 `step` 参数（隔几个跳一次）——但那就变成"跳着翻"，可能漏掉目标，不再是无结构搜索。无结构搜索的精确定义就是"没有任何信息能帮你跳"。
**对应数学**：主线里 Grover 加速倍数 $T_{\text{classical}} = O(N)$。这个函数的循环次数就是 $T_{\text{classical}}$ 的精确版本。

---

### 步骤 3：定义 `make_superposition` —— 一步装下 N 个状态

```python
def make_superposition(n_items):
    return np.ones(n_items, dtype=complex) / np.sqrt(n_items)
```

#### `make_superposition` —— 均匀叠加：每个振幅 = 1/√N

**做什么**：生成一个长度 `N` 的复向量，每一个分量都是 $1/\sqrt{N}$。这个向量就是"N 个可能状态同时在场"的数学表示。
**操作**：`np.ones(n_items, dtype=complex)` 生成全 1 的复向量；`/ np.sqrt(n_items)` 逐元素除以 $\sqrt{N}$。为什么要除以 $\sqrt{N}$？因为模平方要归一化：$\sum_i |1/\sqrt{N}|^2 = N \cdot \frac{1}{N} = 1$。**概率总和为 1，是量子状态合法的唯一法律。**
**输入**：`n_items`，装下的状态个数，正整数。本例 $10^6$。
**输出**：形状 `(N,)` 的复数组，第 $i$ 个分量的模平方 $|\psi_i|^2 = 1/N$ 就是"测量时第 $i$ 个状态被看到的概率"。
**可调参数**：
- `n_items`：状态数。改成 4、16、100 都行——注意叠加向量一步就装下全部，不随状态数变多而"多次操作"。这是它与经典"逐个翻"的对比核心。
- 能不能加参数？可以不均匀（给不同状态不同权重），那就是"带先验的叠加"——加权叠加在量子机器学习里正是"给数据点不同的重要度"。
**对应数学**：主线定义块里的 $|\psi\rangle = \sum_i \alpha_i |i\rangle$、$\sum_i |\alpha_i|^2 = 1$。`np.ones / np.sqrt` 就是 $\alpha_i = 1/\sqrt{N}$ 的代码化身。

---

### 步骤 4：定义 `grover_like_amplify` —— 振幅放大：把目标概率越聚越强

```python
def grover_like_amplify(psi, target, rounds):
    for _ in range(rounds):
        psi[target] *= -1
        avg = np.mean(psi)
        psi = 2 * avg - psi
    return psi
```

#### `grover_like_amplify` —— 一轮 Grover = 标记相位 + 绕平均翻转

**做什么**：对叠加向量做 `rounds` 轮相同的操作，每一轮都把 `target` 那个位置的振幅抬高一点、把其他位置的振幅压低一点。多轮之后，目标概率接近 1。
**操作**（每轮两步）：
1. `psi[target] *= -1`：把目标振幅取反。这一步叫**相位标记 (phase oracle)**——它只翻目标的符号，其他一律不动。振幅变号，模平方（概率）不变——所以这一步本身不改变概率，只是埋下"目标与别人不同"的记号。
2. `avg = np.mean(psi)` 与 `psi = 2 * avg - psi`：**绕平均翻转 (inversion about the mean)**。所有振幅绕它们的平均值翻转。平均值 $a$ 是负的（因为目标被翻成了负），于是"比平均小"的（目标，现在最负）翻转后被抬到最高，比平均高的（其他）被压低。目标越突出，平均值越负，下一轮抬得越狠——**这就是聚光镜的效果**。
**输入**：
- `psi`：长度 `N` 的复叠加向量。
- `target`：目标在向量里的下标。
- `rounds`：放大轮数，整数。
**输出**：更新后的 `psi`，目标的振幅被抬高、其余被压低。
**可调参数**：
- `rounds` 是唯一的旋钮。轮数太少，目标概率还不够高；轮数太多，振幅"翻过头"，目标概率反而回落（因为绕平均翻转是周期性的）。最优轮数约 $\frac{\pi}{4}\sqrt{N}$——本脚本用 `int(np.ceil(np.pi / 4 * np.sqrt(N)))` 算出。可以试试 `rounds` 设为 `2 * optimal`：目标概率会跌回去，亲眼看看"聚过了头"长什么样。
- 能不能加参数？可以。真实 Grover 还需要第二个 oracle（用来标记"所有不等于目标的状态"），但那需要知道哪些是解——本脚本用单向量演示思想，故意省掉。第 4 个参数可以是 `use_exact_oracle`，展开真实的两 oracle 版本——留作实验。
**对应数学**：主线里 Grover 的 $O(\sqrt{N})$。轮数与 $\sqrt{N}$ 成正比——这正是"平方根加速"在代码里的出处：`rounds ≈ (π/4)·√N`，而不是 `N`。

### 步骤 5：对垒——跑经典与量子，打印对比

```python
worst = classical_search(database, N - 1)
psi = make_superposition(N)
rounds = int(np.ceil(np.pi / 4 * np.sqrt(N)))
psi = grover_like_amplify(psi, target, rounds)
probs = np.abs(psi) ** 2
print(f"目标被找到的概率  = {probs[target]:.4f}")
```

**做什么**：把前三个函数串起来，用同一个数据库、同一个目标，让经典和量子各自跑一遍，打印对比。
**操作**：
- `np.abs(psi) ** 2`：逐元素取振幅模长再平方——这就是主线定义块里的 $|\alpha|^2$，测量概率。
- `probs[target]`：取目标位置的概率。
- `worst / rounds`：算加速倍数。
**输入**：`N = 1_000_000`，`target = N - 1`（最坏情形）。
**输出**：五行对比文本。`经典最坏查询次数 = 1000000`、`Grover 轮数 = 786`、`目标被找到的概率 = 1.0000`、`加速倍数 ≈ 1272`。
**可调参数**：把 `N` 从 `1_000_000` 改成 `1_000_000_000`（十亿），经典最坏要查十亿次，而轮数只到约 `np.ceil(0.7854 × 31623) = 24834`——加速倍数从一千倍涨到四万倍。**数据库越大，√N 的优势越恐怖**——这就是主线里"数据库越大，优势越大"这句话的数值证据。
**对应数学**：$T_{\text{classical}} = O(N)$ vs $T_{\text{Grover}} = O(\sqrt{N})$ 的完整演示。它不是精确的 Grover 电路（没有多比特门），但它把 Grover 的两步本质——相位标记 + 绕平均翻转——原样搬进了向量运算。

## 改个数字试试：把轮数推向极端

### 实验 1：轮数减半 / 加倍 —— 看到"聚过头"

```python
optimal = int(np.ceil(np.pi / 4 * np.sqrt(N)))
for factor in (0.5, 1.0, 2.0):
    r = int(factor * optimal)
    p = grover_like_amplify(make_superposition(N), target, r)
    print(f"轮数 = {r:6d}  (最优的 {factor:.1f} 倍) → 目标概率 = {np.abs(p[target])**2:.4f}")
```

输出：

```text
轮数 =    393  (最优的 0.5 倍) → 目标概率 = 0.5016
轮数 =    786  (最优的 1.0 倍) → 目标概率 = 1.0000
轮数 =   1572  (最优的 2.0 倍) → 目标概率 = 0.0000
```

看到规律了吗：轮数翻倍，概率反而从 1.0000 暴跌到 0.0000。绕平均翻转像荡秋千——它把概率"荡"到最高点，也会继续"荡"过头、荡回零点。最优轮数不是"越多越好"，而是一个精确的 $\frac{\pi}{4}\sqrt{N}$：少了不够（半程只有 0.5），多了过头（双倍精确归零）。这就是为什么真实 Grover 算法要精确计算迭代次数：**它给的是"特定轮数下的加速"，不是"无限轮下的免费午餐"。**

### 实验 2：状态数翻 1000 倍 —— 见证平方根

```python
for N2 in (10**3, 10**6, 10**9):
    r = int(np.ceil(np.pi / 4 * np.sqrt(N2)))
    print(f"N = {N2:10d} → 经典最坏 {N2:10d} 次, Grover {r:7d} 次, 快 {N2 / r:8.1f} 倍")
```

输出：

```text
N =       1000 → 经典最坏       1000 次, Grover      25 次, 快     40.0 倍
N =    1000000 → 经典最坏    1000000 次, Grover     786 次, 快   1272.3 倍
N = 1000000000 → 经典最坏 1000000000 次, Grover   24837 次, 快  40262.5 倍
```

N 每放大 1000 倍，Grover 轮数只放大约 $\sqrt{1000} \approx 31.6$ 倍，于是加速倍数节节攀升。**把这条曲线和"经典查询次数线性上涨"叠在一起看，就是"平方根加速"的全部含义。**

## 边界声明：这套代码能做什么，不能做什么

1. **它演示的是"思想"，不是"电路"。** 真实的 Grover 算法需要在多个量子比特上实现 oracle（判断"是不是目标"的子程序）和绕平均的量子门，并且目标概率通过重复测量获得。本脚本把状态直接当向量操作，跳过了编码到量子比特那一步——所以它展示的是**算法层面的加速逻辑**，不是可以直接跑在量子硬件上的程序。真实硬件上的编码与误差，是 §12.3.2 要面对的拦路虎。
2. **轮数必须算准。** 如实验 1 所示，轮数是精确的 $\lceil \frac{\pi}{4}\sqrt{N}\rceil$ 附近，不是"越多越好"。真实实现里不知道目标个数（$M$）时，最优轮数 $\frac{\pi}{4}\sqrt{N/M}$ 也拿不准——这是 Grover 在工程上著名的"不知道要聚多少次"的难题。
3. **平方根加速不是万能的。** Grover 只对"无结构搜索"给 $O(\sqrt{N})$。有结构的数据库（排序、哈希索引）经典本来就有 $O(\log N)$ 甚至 $O(1)$，Grover 反而更慢。**量子加速是结构性的：它奖励那些经典没有捷径的问题**，这句话要一直带到本章最后一节。
