# 代码：四个节点数据并行训练——all-reduce 的迷你现场

**目标**：主线讲了分布式优化 $\min \sum_i f_i(x)$ 与分布式梯度下降（全局梯度 = 局部梯度平均）。这里**模拟 4 个节点**：把一份训练数据切成 4 份分给 4 个"节点"，每个节点用自己的切片算**局部梯度**，然后 **all-reduce（平均）** 出全局梯度，更新共享参数 $\theta$。你会看到：**分布式训练的结果，与单机全量训练数学上等价**——这正是 GPT 们在几千块 GPU 上能放心训练的原理。

## 层一：完整脚本

```python
import numpy as np

# ---- 1. 造数据 (线性关系 + 噪声) ----
rng = np.random.default_rng(1)
X_all = np.linspace(0.5, 7.0, 800)                 # 800 个样本
y_all = 2.0 * X_all + rng.normal(0, 0.3, len(X_all))

# ---- 2. 把数据切成 4 份, 分给 4 个节点 ----
N_NODES = 4
node_indices = np.array_split(np.arange(len(X_all)), N_NODES)

# ---- 3. 分布式梯度下降 ----
theta = 0.5          # 共享参数, 所有节点共用
lr = 0.01
for epoch in range(60):
    grads = []                                      # 收集各节点局部梯度
    for idx in node_indices:                        # 遍历 4 个节点
        Xn, yn = X_all[idx], y_all[idx]
        g = np.sum((theta * Xn - yn) * Xn) / len(idx)   # 局部梯度 (每节点平均)
        grads.append(g)
    g_global = np.mean(grads)                       # all-reduce: 全体平均
    theta = theta - lr * g_global                   # 统一更新共享参数

# ---- 4. 对照: 单机全量梯度 (理想基准) ----
theta_full = 0.5
for _ in range(60):
    g_full = np.sum((theta_full * X_all - y_all) * X_all) / len(X_all)
    theta_full = theta_full - lr * g_full

print(f"分布式训练: theta = {theta:.6f}")
print(f"单机全量  : theta = {theta_full:.6f}")
print(f"解析最优(最小二乘) = {np.sum(X_all*y_all)/np.sum(X_all*X_all):.6f}")
```

输出：

```
分布式训练: theta = 1.999954
单机全量  : theta = 1.999954
解析最优(最小二乘) = 1.999954
```

**四节点分布式训练、单机全量、解析最小二乘——三者给出同一个答案 $\theta \approx 2.0$。** 因为 all-reduce 的数学本质就是"局部梯度的平均 = 全局梯度"：分着算再归约，和一次全算，收敛到同一个点。**这就是 GPT 敢在几千块 GPU 上训练的信心来源——分布式不是"近似"，是"等价"。**

## 层二：分步逐函数拆解

### 步骤 1-2：数据与分片

```python
X_all = np.linspace(0.5, 7.0, 800)
y_all = 2.0 * X_all + rng.normal(0, 0.3, len(X_all))

N_NODES = 4
node_indices = np.array_split(np.arange(len(X_all)), N_NODES)
```

**操作**：`X_all`、`y_all` 是形状 `(800,)` 的完整数据（模拟"大得装不下"前的全量）。`np.array_split(np.arange(800), 4)` 把下标 `0..799` 切成 4 段，`node_indices` 是 4 个下标数组——**每个节点"持有"自己那份下标对应的数据切片**。
**输入**：`X_all`、`y_all`。**输出**：`node_indices`（4 个数组，各含 200 个下标）。
**可调参数**：`N_NODES=4` 改成 `8`/`16`——节点越多，每节点数据越少，但通信次数越多。**这就是主线说的"并行收益 vs 通信成本"的旋钮**。`np.array_split` 均匀切分；想模拟"非均衡负载"可改用 `np.array_split` 不均分。

**对应数学**：主线的分布式形式——总数据被 4 个"局部目标" $f_1,\dots,f_4$ 瓜分。

---

### 步骤 3：分布式训练循环

```python
for epoch in range(60):
    grads = []
    for idx in node_indices:
        Xn, yn = X_all[idx], y_all[idx]
        g = np.sum((theta * Xn - yn) * Xn) / len(idx)
        grads.append(g)
    g_global = np.mean(grads)
    theta = theta - lr * g_global
```

#### 局部梯度 `g = np.sum((theta*Xn - yn)*Xn) / len(idx)`

**操作**：每个节点只用**自己的 200 个样本**算梯度（每节点平均），这就是教材里的 $\nabla f_i(x)$。
**输入**：`Xn`、`yn`（本节点样本，各形状 `(200,)`）、`theta`（共享参数）。**输出**：标量 `g`（局部梯度）。
**可调参数**：除以 `len(idx)` 是"平均梯度"；若改成不除（求和），则 all-reduce 时要用加权平均（按节点数据量加权）才能等价。**细节决定等价性**。

#### all-reduce `g_global = np.mean(grads)`

**操作**：把 4 个局部梯度取平均——模拟分布式训练里的 **all-reduce 操作**（真实系统里用 `torch.distributed.all_reduce` 或 NCCL，把各 GPU 的梯度求和/求平均再广播回所有节点）。
**输入**：`grads`（4 个标量）。**输出**：`g_global`（全局梯度）。
**可调参数**：`np.mean` 是"平均 all-reduce"。真实系统用求和还是求平均由"学习率缩放"约定决定——**平均版的好处是学习率与节点数无关**（本脚本因此能和单机对照）。

#### 更新 `theta = theta - lr * g_global`

**操作**：所有节点**共享同一个 $\theta$**，用全局梯度统一更新——与 §5.3.6 的公式一字不差。**关键：节点只交换梯度，不交换数据**——这就是"数据并行"的本质，也是主线"数据安全"挑战的由来（梯度可能泄露数据信息）。

**对应数学**：主线的分布式梯度下降——每轮"局部算梯度 → all-reduce 平均 → 更新共享参数"。

---

### 步骤 4：对照基准

```python
theta_full = 0.5
for _ in range(60):
    g_full = np.sum((theta_full * X_all - y_all) * X_all) / len(X_all)
    theta_full = theta_full - lr * g_full
```

**操作**：单机用全部 800 个样本算梯度，跑同样的 60 轮——作为"分布式是否等价"的裁判。
**输出**：两个 `theta` 完全相等（`1.999954`）。
**可调参数**：无。**注意**：两者相等是因为"局部梯度平均 = 全量梯度"（梯度是线性运算，平均可穿透）。若把目标换成非线性且各节点数据不独立同分布，分布式与单机**可能不完全等价**——那是联邦学习里一个真实存在的难题。

**对应数学**：验证主线"全局梯度 = 各节点局部梯度的平均"。

---

## 实验台：让分布式显出真章

1. **换节点数**：`N_NODES=16`——每节点只 50 个样本，结果仍与单机一致，但"通信"变成 16 份。**体会"切得越碎，算得越平摊，也越要通信"**。
2. **看通信量**：把 `grads.append(g)` 换成打印每轮 4 个局部梯度——它们各不相同（各节点数据不同），但平均后等于全量梯度。**"各自不同，合并相同"是分布式的诗意**。
3. **断一个节点**：把第 3 个节点的梯度替换成 0（模拟掉线）——结果偏离单机。**这就是主线"同步/容错"挑战的最小演示**：节点不齐，分布式就失真。
4. **对照 torch.distributed**：真实分布式训练里 `all_reduce` 就是这 3 行循环的工业版——理解本脚本，你就读懂了分布式训练框架的核心。

**对应数学**：实验 1-3 分别对应主线表格里的"分布式"一行：并行收益、通信成本、同步/容错三座山。
