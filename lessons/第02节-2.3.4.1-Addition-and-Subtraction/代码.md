# 代码：逐元素加与减——并亲手撞一次"形状不匹配"的报错

主线里我们算过 $A+B$ 与 $A-B$。这一节用 NumPy 复现，并做三件有用的事：**① 逐元素加减；② 验证"减法 = 加法 + 数乘 -1"；③ 观察形状不匹配时的报错与广播行为。**

---

## 层一：完整脚本

```python
import numpy as np                          # NumPy：逐元素运算

# ---- ① 教材的两个矩阵 ----
A = np.array([[1, 2], [3, 4]])
B = np.array([[2, 0], [1, 3]])
print("A + B =\n", A + B)                    # [[3 2] [4 7]]
print("A - B =\n", A - B)                    # [[-1 2] [2 1]]

# ---- ② 验证：减法 = 加法 + 数乘 (-1) ----
print("A + (-1)*B 与 A-B 一致:", np.allclose(A - B, A + (-1) * B))   # True

# ---- ③ 形状不匹配：报错 ----
try:
    C = np.ones((2, 3))                      # 形状 (2,3)
    _ = A + C                                # (2,2) + (2,3)
except ValueError as e:
    print("形状不匹配报错:", e)

# ---- ④ 广播加法：矩阵 + 向量（深度学习加偏置的本质）----
Z = np.array([[1.0, 2.0, 3.0],               # (2,3) 批量输出
              [4.0, 5.0, 6.0]])
b = np.array([0.1, 0.2, 0.3])                # (3,) 偏置
print("Z + b（广播）=\n", Z + b)              # 每行都加 b
```

运行输出（Python 3.11 + NumPy）：

```text
A + B =
 [[3 2]
  [4 7]]
A - B =
 [[-1  2]
  [ 2  1]]
A + (-1)*B 与 A-B 一致: True
形状不匹配报错: operands could not be broadcast together with shapes (2,2) (2,3)
广播加法 Z + b =
 [[1.1 2.2 3.3]
  [4.1 5.2 6.3]]
```

下面拆开看。

## 层二：分步逐函数拆解

### 步骤 1：`A + B` / `A - B`

#### `ndarray + ndarray` —— 逐元素加法

**操作**：同形状数组对应位置相加。`A+B` 每个元素 = $A_{ij}+B_{ij}$。
**输入**：两个 `(2,2)` 数组。
**输出**：`(2,2)` 数组 `[[3,2],[4,7]]`。
**可调参数**：加法的 `+`、减法的 `-` 都是逐元素。**矩阵乘法是 `@`，不是 `*`**——`A*B` 是逐元素乘（Hadamard 积），不是矩阵乘法，别混。
**对应数学**：主线 $(A+B)_{ij}=A_{ij}+B_{ij}$。

### 步骤 2：`np.allclose(A - B, A + (-1)*B)`

**操作**：验证 $A - B = A + (-1)B$——减法被加法与数乘定义。`-1` 乘到每个元素，再加。
**可调参数**：换成 `A + np.negative(B)` 或 `np.subtract(A, B)` 也等价。
**对应数学**：主线"减法 = 加法 + 数乘 $-1$"。**这证明减法不是独立运算，是组合。** 与向量情形（§2.2.1.2）完全同构。

### 步骤 3：形状不匹配报错

```python
try:
    _ = A + C      # (2,2) + (2,3)
except ValueError as e:
    print(e)
```

**做什么**：`(2,2)` 与 `(2,3)` 相加，NumPy 报 `ValueError`——形状无法对齐。
**操作**：`try/except` 捕获异常并打印。报错信息 "could not be broadcast together" 说明 NumPy 尝试广播失败。
**可调参数**：换任何不匹配形状都会报错。`(2,2)` 与 `(3,2)`、`(2,2)` 与 `(2,2)`（成功）。
**对应数学**：主线"形状必须完全相同"（严格数学意义）。**数学说"无定义"，代码说"报错"**——两者是同一件事的两副面孔。

### 步骤 4：广播加法 `Z + b`

#### `(2,3) + (3,)` —— 广播

**操作**：`(3,)` 的 `b` 自动"复制"到每一行：$Z_{0,:}+b$、$Z_{1,:}+b$。输出 `(2,3)`。
**输入**：`Z`（`(2,3)`）、`b`（`(3,)`）。
**输出**：`(2,3)`——每行都加了同一个偏置。
**可调参数**：广播规则：后对齐，缺失的维自动补齐。`(2,3)+(3,)` 对齐 `3` 匹配，`(2,)` 自动扩展。若 `b` 形状 `(2,)` 则按"列广播"，语义完全不同。
**对应数学**：主线"深度学习里的加偏置"——$\mathbf{z}=W\mathbf{x}+\mathbf{b}$ 的批量版。**这是全深度学习出现频率最高的"加法"。** 注意：广播是工程便利，不是"矩阵 + 向量"的数学定义（数学里形状不同的矩阵不能相加）。

## 边界声明：这套代码能做什么，不能做什么

1. **`*`（逐元素乘）≠ `@`（矩阵乘）**。`A*B` 是 Hadamard 积（对应位置相乘），`A@B` 是矩阵乘法。初学者第一大坑。§2.3.4.3 会严格讲 `@`。
2. **广播有隐式风险**。`(2,3)+(3,)` 合理，但 `(3,2)+(3,)` 会报错、`(2,3)+(2,)` 则按另一条轴广播——**看似"能加"，语义却可能不是你以为的**。看到"能跑但结果奇怪"，先怀疑广播方向。
3. **"逐元素相加"让矩阵加法平凡，但它不是"矩阵运算的核心"**。深度学习的"灵魂运算"是矩阵乘法（`@`）。加法负责"装配"（加偏置、残差），乘法负责"变换"。分工不同，别本末倒置。
4. **`np.allclose` 而非 `==`**：浮点逐元素加法有舍入误差，比较用 `allclose`。若用 `==`，两个"数学上相等"的矩阵可能报 False。
