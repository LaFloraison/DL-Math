# §7.6.1 可扩展性 —— 习题

主线给了可扩展性的两块砖：图采样 + mini-batch。下面三组习题检验你是否理解"为什么采样能救亿级图，以及它付出什么代价"。每题附解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：GraphSAGE 采样的直接目的是什么？

- A. 提升准确率
- B. 让每层的计算量与节点度数解耦，压住"邻居爆炸"
- C. 减少模型参数
- D. 让图变得更小

**解答**：B。

**思路点拨**：采样固定 k 个邻居，让"一个节点算多少邻居"与度数无关——5000 万粉丝和 3 个朋友算一样久（§7.4.4 实验 B）。这压住了多层展开的指数爆炸（$d^K \to k^K$）。A 错——采样通常略微损失精度换效率；C、D 与采样无关。常见错选 A，把"采样"当精度优化。

### 题 2（简答）：mini-batch 训练为什么能控制内存？

**解答**：因为 **$K$ 层 GCN 的每个节点只看 $K$ 跳邻域**（§7.4.4：层数 = 视野半径）。所以一个 batch 的前向只需"种子节点的 $K$ 跳子图"——每批内存 = 子图大小，与全图规模解耦。全图前向要存 $n\times n$ 邻接 + 所有中间激活（亿级装不下）；分批后每批只存一小块子图的激活（装得下）。

**思路点拨**：答题锚点是"子图 = 层数跳的邻域"。能把"层数 → 视野半径 → 子图大小"这条链说清就得分。常见错误是只说"分批"不说"为什么子图够用"。

### 题 3（判断）：采样是无损的吗？训练用采样、推理用全邻居，有什么道理？

**解答**：不是无损，是**有损近似**——被采掉的邻居不参与。但采样**期望无偏**（多次采样的平均接近全聚合），代价是单次方差。训练用采样（快、容忍噪声，方差还能当正则化），推理用全邻居（准、稳定，不需要赶速度）——**把效率与准确放在不同阶段**，是工程上的标准做法。

**思路点拨**：这是主线性界声明的直考。答题要点是"有损但期望无偏、方差可控"+"训练/推理分离"。常见错误是断言"采样无损"或"采样没价值"。

## 二、计算实践

### 题 1（手算 + NumPy：采样聚合的期望与方差）

节点 v 有 4 个邻居，特征值 1, 2, 3, 4（一维）。采样 2 个邻居求和：

(a) 所有可能的采样组合及结果？
(b) 采样结果的期望 = ? 与全聚合（1+2+3+4=10）关系？
(c) 标准差？

**解答**：(a) 组合 $\binom{4}{2}=6$ 种：{1,2}=3, {1,3}=4, {1,4}=5, {2,3}=5, {2,4}=6, {3,4}=7。(b) 期望 $=(3+4+5+5+6+7)/6 = 30/6 = 5$。全聚合 10 的"平均邻居"是 2.5，采样 2 个的期望 = $2\times$平均邻居 = 5——**采样期望是"按比例缩放的全聚合"**（这里 k/4 × 10 = 5），即无偏（在知道比例的意义上）。(c) 方差 $= [(3-5)^2+(4-5)^2+0+0+(6-5)^2+(7-5)^2]/6 = (4+1+1+4)/6 = 10/6 \approx 1.67$，标准差 $\approx 1.29$。

**NumPy 验证**：
```python
import numpy as np
from itertools import combinations
vals = [sum(c) for c in combinations([1,2,3,4], 2)]
print("均值", np.mean(vals), " 标准差", np.std(vals))
```
```
均值 5.0  标准差 1.2909944487358056
```

**思路点拨**：这是"采样有方差"的最小手算。要点：期望与全聚合一致（无偏），标准差量化"单次采样可能偏离多远"（约 1.29/5 ≈ 26%）。常见错误是以为"采样 = 随便选，结果没意义"——它有期望、有方差，是可分析的近似。

### 题 2（手算：mini-batch 子图规模）

一条 100 节点的链（1–2–…–100），2 层 GCN。取种子节点 50，展开它的 2 跳子图：包含哪些节点？规模多大？与全图（100 节点）比，省了多少？

**解答**：种子 50 的 1 跳邻居 {49, 51}，2 跳邻居 {48, 50, 52}（49 的邻居 48、50；51 的邻居 50、52）。2 跳子图 = {48, 49, 50, 51, 52}，共 **5 个节点**。全图 100 节点——**省了 95%**。若种子在端点（如 1），子图更小（{1,2,3}）。链上每个种子只需局部子图，这正是"层数=视野半径"的直接后果。

**思路点拨**：核心是"$K$ 层只需 $K$ 跳"。链的演示让"子图规模"肉眼可见——2 层就是 ±2 个邻居。常见错误是以为 mini-batch 要保留全图结构；其实每个 batch 只关心自己那块"局部拼图"。

## 三、DL 延伸

### 题 1（场景设计）：给亿级社交推荐设计可扩展训练

一个社交推荐系统，10 亿用户、人均 300 好友，要用 GNN 学用户表示。请设计训练策略，并说明每一步解决什么。

**解答**：(1) **稀疏存储**——邻接用稀疏矩阵，只存边（§7.6《代码.md》实验 A），解决"存不下"。(2) **mini-batch**——每批取种子用户，只展开 2–3 跳子图（§7.6.1 题 2），解决"一次前向的内存"。(3) **邻居采样**——每层采样固定 k 个好友（GraphSAGE），解决"人均 300 好友"的计算爆炸。(4) **训练用采样、推理用全邻居**——训练求快、推理求准。四步合起来：**从"10 亿 × 300"压到"批大小 × k × 层数"**——与全图规模完全解耦。

**思路点拨**：答题要给出完整的"四步链路"并说明每步对付哪个问题。加分点：提到"归纳式"（新用户直接算，不用重训）。常见错误是只答"用 GraphSAGE"，没分解问题。

### 题 2（概念连线）：采样方差怎么影响训练稳定性？怎么缓解？

§7.6.1 习题题 1 显示采样有方差。请解释：(a) 训练时方差大会怎样？(b) 缓解手段有哪些？

**解答**：(a) 方差大 → 每个 batch 的梯度/表示波动大 → 训练不稳定、收敛慢；但也可能带来轻微正则化效果（噪声让模型不那么过拟合）。整体上方差过大会伤害收敛。(b) 缓解：(1) **增大 k**（采更多邻居，方差随 $\sqrt{1/k}$ 下降）；(2) **重要性采样**（FastGCN）——按度加权，让"重要邻居"更可能被采到，降低方差的同时不显著增计算；(3) **方差控制/控制变量**（如 VR-GCN 存历史表示做基线）；(4) **训练/推理分离**——推理用全邻居彻底消除方差。

**思路点拨**：答题锚点是"方差 ↔ 训练稳定性"。能给出至少两个缓解手段（增大 k、重要性采样）就达标。常见错误是只说"方差存在"不提对策——工程问题必须配工程解。
