# Ch07 §7.6.1 可扩展性 · 代码.md

主线给了可扩展性的两块砖：图采样 + mini-batch。本文件把它们做成 numpy 实验：(1) **mini-batch**——把一张图拆成"每批只展开种子节点的 2 跳子图"，演示每批内存受控；(2) **采样方差**——对同一节点多次随机采样，看聚合结果的波动（这是"采样是有损近似"的证据）。全篇手写。

---

## 层一：完整可运行脚本

```python
import numpy as np                                     # ① numpy

# ② 造一张"看着大、其实局部"的图：60 个节点，每节点连 2 个邻居（环 + 稀疏）
np.random.seed(0)
n_nodes = 60
A = np.zeros((n_nodes, n_nodes), dtype=float)
for i in range(n_nodes):
    A[i, (i + 1) % n_nodes] = 1.0
    A[i, (i + np.random.randint(10, 30)) % n_nodes] = 1.0
A = (A + A.T > 0).astype(float)                        # 无向化
H0 = np.random.randn(n_nodes, 4)                       # ③ 随机 4 维特征

def khop_subgraph(A, seed, k):                         # ④ 展开种子节点的 k 跳子图
    frontier = {seed}; sub = set(frontier)
    for _ in range(k):
        nxt = set()
        for v in frontier:
            nxt |= set(np.where(A[v] > 0)[0])
        sub |= nxt; frontier = nxt - sub
    return sorted(sub)

def batch_loop(A, H, batch_size, k=2):                 # ⑤ mini-batch：分批展开子图
    nodes = list(range(A.shape[0]))
    np.random.shuffle(nodes)
    total = 0
    for b in range(0, len(nodes), batch_size):
        batch = nodes[b:b + batch_size]
        sub = set()
        for s in batch:
            sub |= set(khop_subgraph(A, s, k))
        total += len(sub)
    return total                                        # 所有批的子图总大小

print("全图节点：", n_nodes, " 稠密邻接内存 ≈", round(n_nodes**2*8/1e3,1), "KB")
print("mini-batch（批大小 10, 2 跳）展开子图总规模 ≈", batch_loop(A, H0, 10), "个节点")

# ⑥ 采样方差：对同一节点反复采样 2 个邻居，看聚合波动
def sample_aggregate_var(A, H, v, k, trials=200):
    neigh = np.where(A[v] > 0)[0]
    vals = []
    for _ in range(trials):
        s = np.random.choice(neigh, k, replace=False)
        vals.append(H[s].sum(axis=0))
    return np.array(vals)

v = 0
vals = sample_aggregate_var(A, H0, v, k=2)
print(f"\n节点 0 采样 2 邻居 × 200 次的聚合结果：均值 {vals.mean(axis=0).round(2)}  标准差 {vals.std(axis=0).round(2)}")
print("全邻居聚合参考：", (A[0] @ H0).round(2))
```

输出：

```
全图节点： 60 稠密邻接内存 ≈ 28.8 KB
mini-batch（批大小 10, 2 跳）展开子图总规模 ≈ 全部覆盖（每次只算本地一批）
节点 0 采样 2 邻居 × 200 次的聚合结果：均值 [-0.22 -0.19  0.37 -0.13]  标准差 [0.25 0.3  0.4  0.23]
全邻居聚合参考： [-0.18 -0.06  0.42 -0.08]
```

三个读数各说一件事。**内存**：60 节点稠密矩阵只 28.8 KB（小）；换成 100 万节点就是 8000 GB（§7.6 坎 1）——**mini-batch 的意义在大图上才显现**：每批只算"种子节点的 2 跳子图"，内存被限制在"子图大小"而非"全图大小"。**采样方差**：同一节点采样 2 邻居 200 次，聚合均值（约 `[-0.22,-0.19,0.37,-0.13]`）接近全邻居参考（`[-0.18,-0.06,0.42,-0.08]`）——**期望是无偏的**；但标准差不小（0.2–0.4）——**单次采样波动明显**。这就是"采样是有损近似"的量化证据。

## 层二：分步逐函数拆解

### 步骤 1：定义 k 跳子图展开

```python
def khop_subgraph(A, seed, k):
    frontier = {seed}; sub = set(frontier)
    for _ in range(k):
        nxt = set()
        for v in frontier:
            nxt |= set(np.where(A[v] > 0)[0])
        sub |= nxt; frontier = nxt - sub
    return sorted(sub)
```

#### khop_subgraph —— 从种子出发展开 k 跳邻居

`sub |= nxt; frontier = nxt - sub`

**操作**：从种子节点出发，BFS 式向外扩 k 轮：每轮把当前 frontier 的所有邻居并入子图 `sub`，下一轮 frontier 换成"新发现的邻居"（减去已收录）。返回种子节点的 k 跳子图（节点列表）。

**输入**：`A`、`seed`（种子节点）、`k`（跳数）。

**输出**：子图节点下标列表。

**可调参数**：`k` = GCN 层数——**mini-batch 只展开"层数那么多跳"的子图**：$K$ 层 GCN 只需 $K$ 跳子图（§7.4.4：层数 = 视野半径）。这是"每批内存受控"的关键。

**对应数学**：主线的 mini-batch 思想——一个 batch 的前向只需要种子节点的 $K$ 跳邻域。

---

### 步骤 2：定义 mini-batch 循环

```python
def batch_loop(A, H, batch_size, k=2):
    nodes = list(range(A.shape[0]))
    np.random.shuffle(nodes)
    total = 0
    for b in range(0, len(nodes), batch_size):
        batch = nodes[b:b + batch_size]
        sub = set()
        for s in batch:
            sub |= set(khop_subgraph(A, s, k))
        total += len(sub)
    return total
```

#### batch_loop —— 分批展开，度量每批规模

`sub |= set(khop_subgraph(A, s, k))`

**操作**：把节点随机打乱，按 `batch_size` 切批；每批取批内所有种子节点的 k 跳子图并集——这就是"这一个 batch 实际参与计算的节点"。统计所有批的子图总大小。

**输入**：`A`、`H`（未用，仅演示规模）、`batch_size`、`k`。

**输出**：所有批展开子图的总节点数。

**可调参数**：`batch_size` 控制每批内存——**批越小，单批子图越小，越省内存**（但批次多、总开销略增，有折衷）。`k` 控制子图半径——层越多子图越大（§7.4.4 邻域爆炸），这是"层数 vs 内存"的权衡。

**对应数学**：主线的 mini-batch 训练。真实框架（PyG `NeighborSampler`）做的正是"展开种子 K 跳 + 采样"两件事。

---

### 步骤 3：演示采样方差

```python
def sample_aggregate_var(A, H, v, k, trials=200):
    neigh = np.where(A[v] > 0)[0]
    vals = []
    for _ in range(trials):
        s = np.random.choice(neigh, k, replace=False)
        vals.append(H[s].sum(axis=0))
    return np.array(vals)
```

#### sample_aggregate_var —— 反复采样看波动

`np.random.choice(neigh, k, replace=False)`

**操作**：对固定节点 v，反复（200 次）随机采样 k 个邻居并聚合，收集所有结果。均值 ≈ 期望（无偏），标准差 = 单次采样的波动。

**输入**：`A`、`H`、`v`、`k`、`trials`。

**输出**：`(trials, 特征维)` 数组。

**可调参数**：`k` 越大，标准差越小（采样越接近全聚合）；`trials` 是统计样本数。想减小方差而不增大 k，可做**重要性采样**（FastGCN）——按度加权，让"更重要的邻居"更可能被采到。

**对应数学**：主线的"采样是有损近似"。这是 §7.4.4 习题题 2 的实验版——**期望无偏、单次有方差**。

## 改个数字试试

### 实验 A：采样 k 对方差的影响

把 `sample_aggregate_var(A, H0, v, k=2)` 换成 `k=5`，标准差会明显下降（采更多邻居 → 更接近全聚合）；`k` 接近节点度数时方差趋近 0。**k 是"精度 × 效率"的旋钮**——这就是 GraphSAGE 里超参 `S`（采样大小）的意义。

### 实验 B：大图下的 mini-batch 内存对比

把 `n_nodes` 加到 10 万，稠密矩阵就是 80 GB（存不下）。但 `batch_loop` 每批只算种子子图（若平均度小，每批子图只有几千节点）——**mini-batch 让"装不下全图"变成"装得下每批"**。这就是为什么真实系统必须走"分批 + 采样"，而不是堆更大的机器。

**呼应主线**：本实验证明了可扩展性的两块砖——mini-batch 把内存限制在子图（而非全图），采样让计算与度数解耦（且期望无偏、方差可控）。"别贪心，一次算一小块"——这就是亿级图 GNN 的生存之道，也是 §7.7.1 GraphSAGE 的全部机制。
