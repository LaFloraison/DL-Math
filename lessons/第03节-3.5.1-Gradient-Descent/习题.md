# 习题：梯度下降

## 一、概念检验

### 题 1.1（填空）

梯度下降更新规则 $\theta_{t+1} = \theta_t - \eta \nabla J(\theta_t)$ 中，$\theta_t$ 是____，$\eta$ 是____，$\nabla J(\theta_t)$ 是____。三种变体 SGD、Mini-Batch、Batch 的区别只在于____。

**解答**：第 $t$ 次迭代的参数向量；学习率；损失对参数的梯度；每次更新用多少样本数据计算梯度。
**思路点拨**：最后一个空是本节的灵魂——三种变体不是三个算法，是同一规则的三个采样频率。答成"区别在学习率"就错了：三种变体共享同一个 $\eta$ 与同一个更新公式，唯一的差异是 `grad_batch` 喂进去的 `idx` 大小。

### 题 1.2（选择）

数据集有 10000 个样本，batch size = 100。一个 epoch（扫完一遍数据）内大约会发生多少次参数更新？（ ）

A. 1
B. 100
C. 10000
D. 100

**解答**：D（100 次）。$\lceil 10000/100 \rceil = 100$ 次更新。
**思路点拨**：epoch 数与更新次数要分清——一个 epoch 指"数据被完整用一遍"，更新次数 = 数据集大小 ÷ batch size（向上取整）。注意 B 和 D 数值相同是巧合（100 = batch size 也 = 更新次数），真正的算法是 $N/|batch|$。如果把 batch size 改成 32，10000/32 ≈ 312 次更新，而 batch size 仍是 32——**更新次数取决于除法，不是 batch size 本身**。

### 题 1.3（简答）

为什么"梯度噪声"对深度学习不完全是坏事？请给出一个它成为好处的场景，和一个它成为坏处的场景。

**解答**：好处：多谷的损失曲面上，SGD 的单样本梯度带随机性，可能把参数"震出"浅的局部洼地，有机会到达更好的谷底——噪声是跳出陷阱的随机扰动。坏处：收敛时噪声让参数在谷底附近**徘徊**，无法精确落底；若学习率不衰减，模型会在极小点周围持续抖动，损失曲线永远带着毛刺。
**思路点拨**：这道题考的是主线"频率权衡"背后的噪声双重性。能同时给出好处（逃出浅洼）与坏处（难以精确收敛），说明你理解了"噪声"在优化里不是单纯的敌人。实践中用"学习率衰减"（随着训练减小 $\eta$）让噪声逐渐安静，正是对这两种面孔的调和。

## 二、计算实践

### 题 2.1（手算）

教材例子：当前参数 $\theta(t) = 0.5$，$\eta = 0.01$，某样本对某参数的梯度为 $\nabla\theta = 0.2$。

(a) 计算 SGD 更新后的 $\theta(t+1)$。
(b) 如果该样本的梯度换成 $-0.1$，更新后的值是多少？
(c) 两次更新的步长分别是多少？说明了 SGD 单步的什么特点？

**解答**：(a) $\theta(t+1) = 0.5 - 0.01 \times 0.2 = 0.5 - 0.002 = 0.498$。(b) $0.5 - 0.01 \times (-0.1) = 0.5 + 0.001 = 0.501$。(c) 步长分别为 0.002 和 0.001——都极小。说明 SGD 单步的步幅很小（$|\eta \cdot g|$ 由 $\eta$ 和梯度共同决定），但它的优势是**更新频率高**：积小步为快，一个 epoch 里能更新 1000 次。
**思路点拨**：注意 (b) 中负梯度意味着"这个样本想让参数增大"——不同样本的梯度可能方向相反，这正是 SGD 噪声的来源：**每个样本都朝自己的方向拽一把**，整体平均才指向真实下降方向。手算一遍，你就明白为什么单样本更新"抖"。

### 题 2.2（代码验证）

用 NumPy 复现"同一规则、不同频率"：数据集 $y = 3x + \text{noise}$，分别用 SGD、mini-batch(32)、batch 各训练 10 个 epoch，打印终点 $w$ 与路径抖动（更新序列标准差）。

```python
import numpy as np
np.random.seed(0)
N = 1000
x = np.random.randn(N); y = 3.0*x + np.random.randn(N)*0.5
def grad(w, idx):
    xi, yi = x[idx], y[idx]
    return 2.0*np.mean(xi*(w*xi - yi))
def run(mode, eta=0.05, epochs=10):
    w, hist = 0.0, []
    for _ in range(epochs):
        idx = np.arange(N) if mode=='batch' else (np.random.choice(N, 32, replace=False) if mode=='mini' else np.random.randint(0, N))
        w = w - eta*grad(w, idx)
        hist.append(w)
    return w, np.std(hist)
for m in ['sgd', 'mini', 'batch']:
    wf, j = run(m)
    print(f"{m:<6} w={wf:.4f}  抖动={j:.4f}")
```

**解答**：三种都收敛到 $w\approx 3.0$ 附近，但抖动依次递减（SGD 最大、batch 最小）。具体值与随机种子有关；用 `seed(0)` 可复现《代码.md》的输出量级。
**思路点拨**：`idx` 的选择是唯一的分叉——`np.arange(N)`、`np.random.choice(N,32)`、`np.random.randint(0,N)` 三种索引构造对应三种变体，更新的数学一模一样。把 `eta` 改成 0.5，SGD 抖动急剧放大而 batch 相对温和——亲手验证"频率与噪声"的权衡。

## 三、DL 延伸

### 题 3.1

一家公司要在 5000 万个样本上训练模型。工程师说："我们每步都用全量数据算梯度，保证最准。"请从本节知识评价这个选择，并给出更合理的方案及理由。

**解答**：不现实——5000 万样本全量算一次梯度，单步计算量极大，训练周期以月计。更合理的方案是 **mini-batch SGD**（batch size 32–512）：每步只算一小批的平均梯度，一个 epoch 内更新上万次，GPU 并行让小批量的批量矩阵运算非常高效；且小批量带有的梯度噪声还能帮助跳出浅洼。若数据确需"较准"的梯度，可适当增大 batch size（如 1024）配合调整学习率，但纯 batch 在百万级数据上不可行。
**思路点拨**：这道题考"频率权衡"在规模下的必然选择。能说出"全量贵 + mini-batch 平衡 + 噪声福利"三点，就理解了主线"三种变体"的实用面向。注意不要只说"mini-batch 快"——它的另一个优势（噪声帮助逃离浅洼）正是批梯度与全量梯度在**质量**上的差异，而不只是速度。

### 题 3.2

训练曲线显示：loss 在 0.3 附近持续震荡，降不下去。工程师怀疑"收敛后噪声徘徊"。给出两种应对手段，并说明各自作用机制。

**解答**：① **学习率衰减**（learning rate decay）：随着训练把 $\eta$ 逐渐调小，SGD 的噪声步幅随之减小，参数在谷底附近的徘徊半径收缩，loss 曲线变平、更接近谷底——直接作用于"噪声幅度"。② **增大 batch size 或切换为 mini-batch 更大批次**：平均梯度噪声随 batch size 增大而降低，参数路径更平滑——直接作用于"梯度估计的噪声水平"。③ 也可改用带动量/自适应的优化器（Adam 等），但那是第 5 章的正式内容。
**思路点拨**：两种手段一个"调大减小 $\eta$"、一个"调大批次降噪"，本质都是让"噪声 × 步幅"这个乘积变小。能说清"学习率衰减缩小的是噪声的步幅，增大 batch 缩小的是噪声本身"，就真正理解了 §3.5.1 的频率权衡。
