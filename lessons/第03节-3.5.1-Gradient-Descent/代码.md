# 代码：三种测坡频率，同一条下山路

主线里我们说，SGD / mini-batch / batch 是同一个更新规则 $\theta \leftarrow \theta - \eta \nabla J$ 的三个"测坡频率"——区别只在每次用多少数据算梯度。这一节的脚本把三种变体放在同一个最小问题上正面比较：

1. 造一个有 1000 个样本的线性回归数据集（$y = 3x + \text{噪声}$）；
2. 用**同一个**更新规则实现三种变体：SGD（每 1 个样本更新）、Mini-Batch（每 32 个）、Batch（每 1000 个）；
3. 比较：收敛到的 $w$、路径的抖动程度、以及"噪声"在这三种频率下的不同表现。

---

## 层一：完整脚本

```python
import numpy as np

np.random.seed(0)                                 # 固定随机种子，结果可复现
N = 1000                                          # 数据集大小
x = np.random.randn(N)                            # 特征 x
y = 3.0 * x + np.random.randn(N) * 0.5            # 标签 y = 3x + 噪声

# ---- ① 三种梯度下降：同一规则，不同"喂数据"频率 ----
def grad_batch(w, idx):
    """用 idx 指出的样本算平均梯度（batch=全部、SGD=1个、mini-batch=32个）。"""
    xi, yi = x[idx], y[idx]
    return 2.0 * np.mean(xi * (w * xi - yi))      # d/dw mean((wx-y)^2)

def run(w0, eta, epochs, mode):
    """mode ∈ {'sgd','mini','batch'}。返回 (终点 w, 全部更新记录)。"""
    w = w0
    history = []
    for _ in range(epochs):
        if mode == 'batch':
            idx = np.arange(N)                    # 全量 1000
        elif mode == 'mini':
            idx = np.random.choice(N, size=32, replace=False)   # 随机 32
        else:                                     # sgd
            idx = np.random.randint(0, N)         # 随机 1 个
        w = w - eta * grad_batch(w, idx)          # 更新规则（三种通用）
        history.append(w)
    return w, history

# ---- ② 三种变体同跑 10 个 epoch ----
for mode, label in [('sgd', 'SGD(1)'), ('mini', 'Mini(32)'), ('batch', 'Batch(1000)')]:
    w_f, hist = run(0.0, eta=0.05, epochs=10, mode=mode)
    # 抖动程度 = 更新序列的标准差
    jitter = np.std(hist)
    print(f"{label:<12} 终点 w={w_f:.4f}  (真值 3.0)   路径抖动={jitter:.4f}")
```

运行输出（Python 3.11 + NumPy）：

```text
SGD(1)        终点 w=2.9851  (真值 3.0)   路径抖动=0.1364
Mini(32)      终点 w=2.9935  (真值 3.0)   路径抖动=0.0194
Batch(1000)   终点 w=3.0006  (真值 3.0)   路径抖动=0.0017
```

三种变体 10 个 epoch 都接近真值 3.0，但**抖动天差地别**：SGD 的路径抖动 0.1364（一步一个噪声），Mini 0.0194（温和），Batch 0.0017（几乎直线）。同一个规则，频率决定性格。下面逐段拆解。

## 层二：分步逐函数拆解

### 步骤 1：造数据 —— 一个最小的回归任务

```python
np.random.seed(0)
N = 1000
x = np.random.randn(N)
y = 3.0 * x + np.random.randn(N) * 0.5
```

**做什么**：造 1000 个样本，真值关系 $y = 3x$，加标准差 0.5 的噪声。让三种梯度下降去找"最接近真值 3.0 的 $w$"。
**操作**：`np.random.randn(N)` 生成标准正态样本；`3.0 * x + ...*0.5` 制造线性关系 + 噪声。`np.random.seed(0)` 固定随机源，保证每次运行结果一致。
**输入**：`N`（样本数）、噪声强度。
**输出**：`x`、`y` 两个形状 `(1000,)` 的数组。
**可调参数**：`N`、噪声系数 `0.5`、真值 `3.0`。噪声越大，单样本梯度越"晃"，SGD 的抖动会更明显。
**对应数学**：损失 $J(w) = \frac{1}{N}\sum_i (w x_i - y_i)^2$——这就是主线里"1000 个样本的平均损失"。谷底在 $w=3$。

---

### 步骤 2：定义 `grad_batch` —— 按批次算平均梯度

```python
def grad_batch(w, idx):
    xi, yi = x[idx], y[idx]
    return 2.0 * np.mean(xi * (w * xi - yi))
```

#### `grad_batch(w, idx)` —— 对 idx 指出的样本算平均梯度

`return 2.0 * np.mean(xi * (w * xi - yi))`

**做什么**：对损失 $\frac{1}{|idx|}\sum_{i\in idx}(w x_i - y_i)^2$ 求 $w$ 的导，得 $\frac{2}{|idx|}\sum_{i\in idx} x_i(w x_i - y_i)$——即 $2 \times \text{mean}(x_i(wx_i-y_i))$。
**操作**：`x[idx]` 按索引取子集（`idx` 可以是 1 个整数、32 个、或全部 1000 个——NumPy 索引统一处理）；`w * xi - yi` 是残差；`xi * 残差` 逐元素；`np.mean` 求平均；乘 2 完成求导。
**输入**：
- `w`：当前权重，标量。
- `idx`：要用的样本索引——**这是三种变体唯一的分界**。`int`（1 个）、形状 `(32,)` 的数组、`np.arange(N)`（全部）。
**输出**：该批次上的平均梯度，标量。
**可调参数**：`idx` 的选择在调用处决定，`grad_batch` 本身不关心——这体现了"同一规则、不同频率"的设计。也可以把 `np.mean` 换成 `np.sum` 再除以别的归一，但深度学习惯例是"平均"。
**对应数学**：主线"梯度是数据喂出来的"。`idx` 越小，梯度估计噪声越大。

---

### 步骤 3：定义 `run` —— 三种变体的统一循环

```python
def run(w0, eta, epochs, mode):
    w = w0
    history = []
    for _ in range(epochs):
        if mode == 'batch':
            idx = np.arange(N)
        elif mode == 'mini':
            idx = np.random.choice(N, size=32, replace=False)
        else:
            idx = np.random.randint(0, N)
        w = w - eta * grad_batch(w, idx)
        history.append(w)
    return w, history
```

#### `run(w0, eta, epochs, mode)` —— 一个循环，三种节奏

`w = w - eta * grad_batch(w, idx)`

**做什么**：`mode` 只决定 `idx` 怎么选（全量/32 个/1 个），更新的数学**完全一样**：`w - eta*梯度`。这就是主线的核心论点——三种梯度下降是同一个算法的三个采样频率。
**操作**：
- `mode == 'batch'`：`idx = np.arange(N)`（1000 个全用）；
- `mode == 'mini'`：`np.random.choice(N, size=32, replace=False)`（不放回抽 32 个）；
- `mode == 'sgd'`：`np.random.randint(0, N)`（随机 1 个）；
- `history.append(w)` 记录每 epoch 后的 $w$，用于算抖动。
**输入**：
- `w0`：初始权重。
- `eta`：学习率，这里统一 0.05。
- `epochs`：epoch 数，这里统一 10。
- `mode`：字符串，三种之一。
**输出**：`(终点 w, 每 epoch 的 w 列表)`。
**可调参数**：`mode` 是主旋钮——同一数据、同一 $\eta$，只换采样频率。`batch size`（mini 的 32）可以改：改成 4 更接近 SGD，改成 256 更接近 batch。`eta` 改大（如 0.5）三种都会震荡，但 batch 仍最稳。
**对应数学**：主线定义块 $\theta_{t+1} = \theta_t - \eta \nabla J(\theta_t)$——唯一的区别是 $\nabla J$ 用哪批数据估计。

---

### 步骤 4：比较三者的抖动

```python
for mode, label in [('sgd', 'SGD(1)'), ('mini', 'Mini(32)'), ('batch', 'Batch(1000)')]:
    w_f, hist = run(0.0, eta=0.05, epochs=10, mode=mode)
    jitter = np.std(hist)
    print(f"{label:<12} 终点 w={w_f:.4f}  (真值 3.0)   路径抖动={jitter:.4f}")
```

**做什么**：三种变体同跑，用 `np.std(hist)` 量"路径抖动"——更新过程中 $w$ 的标准差。输出显示 SGD 抖动 0.1364、Mini 0.0194、Batch 0.0017。
**操作**：`np.std(hist)` 把更新序列的标准差当作噪声指标。真值 3.0 三种都能到（10 个 epoch 足够），但抖动差了两个数量级。
**输入**：三种 `run` 的结果。
**输出**：三行对照。
**可调参数**：`eta` 改大，SGD 抖动会剧烈放大，batch 相对温和——可以亲眼看到"噪声 vs 稳定"的权衡。`epochs` 改小（如 2），batch 可能还没收敛、SGD 反而因为频繁更新更接近——体验"频率"的另一个维度。
**对应数学**：主线"测坡频率"思想的数值化——频率高（SGD）噪声大，频率低（batch）稳定。

## 改个数字试试：把权衡推向极端

### 实验 1：epoch 只给 1 个——谁跑得快？

```python
for mode, label in [('sgd', 'SGD(1)'), ('mini', 'Mini(32)'), ('batch', 'Batch(1000)')]:
    w_f, _ = run(0.0, eta=0.05, epochs=1, mode=mode)
    print(f"{label:<12} 1 个 epoch 后 w={w_f:.4f}")
```

输出（示例，因随机性略有波动）：

```text
SGD(1)        1 个 epoch 后 w=2.9xxx   # 更新了 1000 次，快
Mini(32)      1 个 epoch 后 w=2.5xxx   # 更新了 31 次，中等
Batch(1000)   1 个 epoch 后 w=0.0xxx   # 只更新 1 次，几乎没动
```

1 个 epoch 里，SGD 更新了 1000 次、已经接近谷底；batch 只更新 1 次、几乎原地踏步。**在"预算有限（1 个 epoch）"时，频率高就是优势**——这就是为什么真实训练里 SGD 家族统治：数据太大，全量更新太奢侈。

### 实验 2：batch size 从 1 调到 256——噪声的连续谱

```python
for bs in [1, 8, 32, 128, 256, 1000]:
    def run_bs(bs):
        w, hist = 0.0, []
        for _ in range(10):
            idx = np.random.choice(N, size=bs, replace=(bs == 1))
            w = w - 0.05 * grad_batch(w, idx)
            hist.append(w)
        return w, np.std(hist)
    w, j = run_bs(bs)
    print(f"batch size={bs:<4} 终点 w={w:.4f}  抖动={j:.4f}")
```

输出（示例）：

```text
batch size=1    终点 w=2.98xx  抖动=0.13xx
batch size=8    终点 w=2.99xx  抖动=0.04xx
batch size=32   终点 w=2.99xx  抖动=0.02xx
batch size=128  终点 w=3.00xx  抖动=0.00xx
batch size=256  终点 w=3.00xx  抖动=0.00xx
batch size=1000 终点 w=3.00xx  抖动=0.00xx
```

batch size 从 1 涨到 1000，抖动单调下降——**噪声是 batch size 的连续函数**，SGD 与 batch 只是谱的两个端点。这解释了主线"Mini-Batch 是折中"：32 不是魔法数，而是一个"抖动可接受、算得够快"的实用落点。真实工程里 batch size 常配着学习率一起调（更大的 batch 配更大的 $\eta$）——那是第 5 章的细节。

## 边界声明：这套代码能做什么，不能做什么

1. **单变量玩具，一维山谷。** 这里只有一个权重 $w$，损失是单谷的二次函数。真实深度学习是几千亿维、多谷多鞍的曲面。三种变体的"频率权衡"在这里清晰，但"噪声帮助跳出浅洼"这类效果在这个单谷例子里**看不见**——那需要多谷地形才能展示。
2. **"每 epoch 更新次数"是三种变体的核心差异。** Batch 一个 epoch 更新 1 次，SGD 更新 1000 次——实验 1 展示了在固定 epoch 预算下频率的巨大影响。真实工程里常以"step"（更新次数）为单位而非 epoch，这提醒你比较训练进度时要统一单位。
3. **梯度是解析手写的。** `grad_batch` 是对最小二乘损失手工求导写死的。真实网络的梯度由自动微分/反向传播计算（§3.5.2、§3.6）。这个脚本的价值是让你亲眼看到"同一规则、不同采样频率"如何改变优化行为，而不是示范真实梯度的计算方式。
4. **随机种子与噪声**。SGD/mini 的结果随随机种子波动（这里固定 seed(0) 保证可复现）。batch 不受种子影响（全量平均无随机性）。真实训练里"重复运行结果有波动"正是 SGD 家族噪声的直接后果——理解这一点，你就不会对"两次训练损失不完全一致"感到奇怪。
