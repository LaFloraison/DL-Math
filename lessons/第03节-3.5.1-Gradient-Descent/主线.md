## 第一步：Toy Model —— 三个盲人，三种测坡的频率

上一节我们讲了梯度在深度学习中会遇到消失、爆炸与鞍点。现在假设那些困难都不存在——你有一座干净的山谷，一个可靠的梯度。剩下的问题只有一个：**你多久测一次脚下的坡？**

三个盲人同时下山，他们的向导只能偶尔帮他们测坡度。**甲**走得极谨慎：每迈一小步，就停下来让向导测一次坡。他永远踩着最准的方向，但一步一停，慢得像蜗牛，而且因为太在意单步的误差，方向经常被一点点噪音带得发抖。**乙**聪明一点：每走一小段路（比如 32 步），停下来测一次坡，然后一口气走完这一段。他既不频繁到发抖，也不吝啬到迷路。**丙**最稳：他要走完整整一千步——把整条路都走一遍——才测一次坡，然后只调整一次方向。他每次调整都极准，可他走一千步才发现自己偏了，而且那一千步里全在走错方向。

三个人，同一个山坡，同一种下山法——区别只在**多久测一次坡**。频率决定一切：测得太勤（甲）噪声大、走得慢；测得太疏（丙）方向滞后、浪费路；折中（乙）刚刚好。

现在问那个"浅到可笑"的问题：甲每走一步就测一次，方向最"新"，为什么反而不好？直觉告诉你：因为单一步的"坡"带噪声——测一次只能看到脚下那一小片地，而那一小片可能恰好不平。**频率太低不好懂，频率太高也未必好**——这个"中间地带"的思想，就是本节的三种梯度下降。直觉到此为止——"多久测一次坡"要怎样精确成数学，并且算清每种频率的代价？该请微积分登场了。

## 第二步：正式数学讲解

### 一、撞墙：梯度是"数据喂出来的"，喂多少决定梯度准不准

回忆更新规则：$\theta_{t+1} = \theta_t - \eta \nabla J(\theta_t)$。这里 $\nabla J(\theta_t)$ 是损失函数对参数向量 $\theta$ 的梯度。但有一个我们一直没细想的细节：**这个梯度是怎么算出来的？**

损失 $J(\theta)$ 是**整个数据集**上的平均损失——对 1000 个训练样本，$J$ 是 1000 个样本各自损失的均值。它的梯度 $\nabla J$ 是"1000 个样本的梯度平均"。可问题是：算这个梯度，要把 1000 个样本全部前向+反向传播一遍——**很贵**。

于是你面临一个选择：测坡的时候，看**多少个**数据？

- **只看 1 个样本**，算它的梯度，就更新——快，但这一条样本的梯度只是"整个数据集的粗略估计"，噪声大（甲：一步一测）；
- **看 32 个样本**，平均这 32 个的梯度，再更新——中等噪声、中等成本（乙）；
- **看全部 1000 个**，平均全部梯度，再更新——最准、最贵（丙）。

三种选择，就是三种梯度下降。它们共享同一条更新规则，只差"梯度用什么数据算"。

> **梯度下降 (gradient descent)** $\theta_{t+1} = \theta_t - \eta \nabla J(\theta_t)$
>
> 物理含义：迭代地沿负梯度方向调整参数向量，以极小化损失 $J$。
>
> $$\theta_{t+1} = \theta_t - \eta \nabla J(\theta_t)$$
>
> - $\theta_t$：第 $t$ 次迭代的参数向量（$t$ 个权重）
> - $\eta$：学习率，控制步幅
> - $\nabla J(\theta_t)$：损失对 $\theta$ 的梯度（在 $\theta_t$ 处）
> - 三种变体只在"用什么数据算 $\nabla J$"上不同：单样本（SGD）、小批量（mini-batch）、全量（batch）

### 二、三种变体，逐一说清

#### (a) 随机梯度下降 (Stochastic Gradient Descent, SGD)

**定义**：每处理**一个**训练样本，就计算该样本的梯度并立即更新参数。

- 数据集 1000 个样本：每看 1 个样本更新一次，一个 epoch（扫完一遍数据）会更新 1000 次。
- **优点**：快——每次只算 1 个样本的梯度，计算量极小，参数频繁更新；而且**噪声是帮手**：单样本梯度带随机性，能帮模型跳出浅的局部洼地（撞墙时别忘了）。
- **缺点**：梯度估计噪声大——单样本的梯度可能严重偏离真实梯度，参数路径剧烈抖动，收敛时在谷底附近徘徊（难以精确落底）。

教材给了一个具体数字：当前参数 $\theta(t) = 0.5$，学习率 $\eta = 0.01$，该样本对某一参数的梯度 $\nabla\theta = 0.2$，则更新：

$$\theta(t+1) = 0.5 - 0.01 \times 0.2 = 0.5 - 0.002 = 0.498$$

只挪了 0.002——单样本更新的步子往往很小且方向含噪，但积少成多。

#### (b) 小批量梯度下降 (Mini-Batch Gradient Descent)

**定义**：每处理一个小批量（如 32 个样本），计算这批的**平均梯度**，更新一次参数。

- 数据集 1000 个样本，batch size = 32：一个 epoch 更新约 $\lceil 1000/32 \rceil \approx 31$ 次。
- **优点**：平衡——批量平均噪声比单样本小得多，路径平滑；批量并行计算（GPU）效率高；更新频率仍足够快。
- **缺点**：仍需调 batch size（太小≈SGD 噪声大，太大≈batch 昂贵）。

**为什么它是实际的标准？** 因为深度学习工程里"噪声小 + 算得快 + 更新勤"三者不可兼得，mini-batch 恰好落在最优折中：32–256 个样本是普遍默认。GPU 对批量矩阵运算的高度优化，也让"一次算 32 个"远比"算 32 次 1 个"便宜。

#### (c) 批量梯度下降 (Batch Gradient Descent)

**定义**：每处理**整个**数据集（全部 1000 个样本），计算全量平均梯度，更新一次。

- 一个 epoch 只更新 1 次。
- **优点**：梯度最准——全量平均消除了采样噪声，参数沿真实梯度平滑下降，收敛稳定。
- **缺点**：极贵——每更新一次要遍历全部数据；1000 个样本还凑合，百万级数据集（真实深度学习）每步都要全量扫描，慢到不可接受；且全量梯度没有噪声，"跳不出浅洼"。

### 三、一张对照表：三种变体的权衡

| | SGD | Mini-Batch | Batch |
|---|---|---|---|
| 每次用多少样本 | 1 | 32（典型） | 1000（全部） |
| 每 epoch 更新次数 | 1000 | ≈31 | 1 |
| 梯度噪声 | 大 | 中 | 零 |
| 路径平滑度 | 抖 | 较平 | 平滑 |
| 计算成本/更新 | 最低 | 中（GPU 友好） | 最高 |
| 能否凭噪声跳出浅洼 | 能 | 部分 | 不能 |
| 深度学习中的使用 | 变体的基础 | **标准** | 小数据集才用 |

一句话记住：**三种梯度下降不是三个算法，是同一个"测坡频率"问题的三个答案**——频率由"每次喂多少数据"决定，而频率的选择是"噪声、速度、稳定"之间的三角权衡。

### 四、边界声明：梯度下降不是万能钥匙

把边界立起来。**第一**，梯度下降只能保证**逐步下降**，不保证**全局最优**——多谷的损失曲面会把模型困在局部洼地；SGD 的噪声能部分解围，但不是担保。**第二**，$\eta$ 与 batch size 是两个需要协同调的旋钮：$\eta$ 太大震荡，太小缓慢；batch size 太大梯度太"准"反而失去噪声福利且昂贵。**第三**，这里的"epoch"概念——扫完一遍数据——是 SGD 家族特有的；batch 梯度每 epoch 只更新一次，epoch 数不等于更新次数。**第四**，真实深度学习几乎不采用纯 batch 或纯单样本 SGD，而是 mini-batch + 各种增强（动量、自适应学习率，第 5 章优化论展开）。本节是这三块地基，别把它们当成生产环境的全部。

## 第三步：DL 桥接

梯度下降是深度学习训练的同义词——它是那个"每步更新权重"的引擎。

具体到符号层面：训练一个 Transformer，数据有 10 亿个样本，batch size = 32。那么每一步：

1. 随机抽 32 个样本；
2. 前向传播，算出这 32 个样本的损失 $J_{\text{batch}}(\theta)$；
3. 反向传播（§3.5.2）算出梯度 $\nabla J_{\text{batch}}(\theta)$——32 个样本梯度的平均；
4. $\theta \leftarrow \theta - \eta \nabla J_{\text{batch}}(\theta)$；
5. 再抽 32 个，重复。

这个"随机抽一批→算梯度→更新"的循环，就是 mini-batch SGD。你今天听到的所有大模型训练，都在跑这个循环——只是参数规模是几千亿、batch 32 换成 batch 若干千、$\eta$ 由 Adam 动态调度。**$w_{t+1} = w_t - \eta \nabla J$ 这个式子，是深度学习唯一真正在执行的更新；剩下的一切（架构、初始化、正则）都是为了让这个式子跑得更远、更稳、更准。** 三种变体的数值对比，见《代码.md》。
