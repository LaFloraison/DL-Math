# §6.6 数据压缩 —— 习题

本节主线把"压缩"引到那堵墙前：无损压缩的平均码长 $L \ge H(X)$（香农第一定理），Huffman 编码逼近下界（$L \le H+1$），并区分无损与有损。习题分三组：**概念检验** 验证压缩的极限与边界，**计算实践** 手算 Huffman 编码并代码验证，**DL 延伸** 把压缩放回"预测即压缩"与表示学习。每题附完整解答与思路点拨。

---

## 一、概念检验

### 题 1（选择）：哪个说法正确？

一个信源 $X$，熵 $H(X) = 1.5$ bits。以下哪个**正确**？

- A. 一定存在一种无损编码，平均码长 1.0 bits/符号
- B. 任何无损编码的平均码长都 $\ge 1.5$ bits/符号
- C. 有损压缩的平均码长不能低于 1.5 bits/符号
- D. Huffman 编码的平均码长恰好等于 1.5 bits/符号

**解答**：B。

B 是香农第一定理的直接陈述：无损编码平均码长 $L \ge H(X)$。A 违反定理（1.0 < 1.5 不可能）。C 错——有损压缩允许低于熵（它靠丢信息换码率）。D 错——Huffman 保证 $H \le L \le H+1$，只是"不超过熵加 1"，不保证"恰好等于熵"。

**思路点拨**：这题考的是熵作为"墙"的位置。记忆锚点：**熵之上是无损的领地（$L \ge H$），熵之下必须付"丢信息"的代价（有损）。** 最容易错的是 D——"最优"不代表"恰好贴墙"，Huffman 的承诺是 $H+1$ 这个上界；想要更贴墙用算术编码，但也永远不低过熵。把"≥ 熵"和"≤ 熵+1"两个方向都记住，就不容易混。

### 题 2（判断 + 简答）：英文真的被"每符号熵"限制吗？

有人读了教材，说："英文的无损压缩极限就是每符号约 4.1 bits（26 字母的熵）——谁也别想压得比这更低。" 判断并解释。

**解答**：对**独立同分布**的字母序列，这个说法对；对**真实英文**，不对。真实英文有大量上下文结构："q"后几乎必是"u"、"the"反复出现、词与词之间有语法约束。用上下文（条件熵 $H(\text{下一个} \mid \text{前面})$）可以把每符号成本压得远低于"无上下文熵"——香农 1951 年实测英文的条件熵约 0.6–1.3 bits/字母。所以：**$H(X)$ 是"无上下文"的下界；有上下文时，下界是条件熵的序列平均，更小。** 教材那句话针对的是独立同分布模型，不是真实语言的压缩上限。

**思路点拨**：这是主线边界声明第一条的展开。判别句：**"熵是下界"的前提是"符号独立"**——一旦允许利用符号间的依赖（条件熵），下界就收缩了。gzip 能压缩英文文本、语言模型能继续压缩，靠的都是"挖掘上下文依赖"，而非挑战"无上下文的熵"。理解了这一点，就理解了为什么"预测即压缩"。

### 题 3（简答）：无损与有损，谁在"低于熵"？

无损压缩和有损压缩，哪个的平均码长可以低于熵？这说明了什么？

**解答**：**有损压缩**可以低于熵。无损压缩必须保留全部信息，平均码长 $\ge H(X)$；有损压缩允许丢弃部分信息（细节、高频分量），所以能用低于熵的码率表示"够用"的数据——JPEG、MP3 正是如此。**"低于熵"这个行为本身，就是在丢信息。** 这说明熵是"信息含量的客观度量"：你省下的每一点码率，都必须用某处的信息丢失来偿还。有损压缩的艺术，在于"丢的信息恰好是感知上不重要的"——把比特预算花在刀刃上。

**思路点拨**：这题考"低于熵"的代价。记忆锚点：**平均码长 < 熵 ⟺ 不是无损 ⟺ 丢了信息。** 有损压缩不是"打败了熵"，而是"用保真度换码率"——它交易的锚点正是熵。理解这个，就理解了为什么 JPEG 压缩到极致会糊、MP3 压到极致会失真：因为你在熵之下借债，债要还（丢细节）。

## 二、计算实践

### 题 1（手算 Huffman 树 + 熵）

五个符号：a(0.4)、b(0.2)、c(0.2)、d(0.1)、e(0.1)。

(a) 手工构建 Huffman 树，写出每个符号的码。
(b) 手算熵 $H$ 与平均码长 $L$，验证 $H \le L \le H+1$。
(c) 与等长码（5 符号需 3 位）对比，Huffman 省了多少？

**解答**：

(a) 合并步骤（每次取概率最小的两个）：
1. d(0.1)+e(0.1)=0.2。现：a(0.4)、b(0.2)、c(0.2)、de(0.2)。
2. b(0.2)+c(0.2)=0.4。现：a(0.4)、de(0.2)、bc(0.4)。
3. de(0.2)+bc(0.4)=0.6。现：a(0.4)、debc(0.6)。（注意：第 2、3 步里"最小的两个"可能并列，选哪个都行，码字会略不同但码长分布一样。）
4. a(0.4)+debc(0.6)=1.0。

标码（左 0 右 1）——按上述合并顺序：根=0.6节点⊕a；0.6节点=de⊕bc；bc=b⊕c；de=d⊕e。
- a → `0`
- 0.6 节点 → `1`：bc → `10`，de → `11`
- b → `100`，c → `101`，d → `110`，e → `111`

码表：a:`0`、b:`100`、c:`101`、d:`110`、e:`111`。

(b) $H = -(0.4\log_2 0.4 + 0.2\log_2 0.2\times2 + 0.1\log_2 0.1\times2) = 0.4\times1.322 + 2\times0.2\times2.322 + 2\times0.1\times3.322 = 0.529+0.929+0.664 = 2.122$ bits。$L = 0.4\times1 + 0.2\times3\times2 + 0.1\times3\times2 = 0.4+1.2+0.6 = 2.2$ bits。验证：$2.122 \le 2.2 \le 3.122$ ✓。

(c) 等长码 3 bits/符号。Huffman $L=2.2$，省 $3-2.2 = 0.8$ bits/符号（约 27%）。

**思路点拨**：(a) 是 Huffman 的手算演练，最易错的是**并列时选哪个**——只要每次合并的是两个最小概率节点，任何并列选法都得到"最优码长分布"（码字可能不同，但 $L$ 一样）。判别句：**Huffman 保证的是"平均码长最短"，不是"码字唯一"。** (b) 用 $H \le L \le H+1$ 核对是免费的正确性检查。

**代码验证**：
```python
import heapq, math
class Node:
    def __init__(s, sym, prob, left=None, right=None):
        s.sym, s.prob, s.left, s.right = sym, prob, left, right
    def __lt__(self, o): return self.prob < o.prob
def build(probs):
    h = [Node(k, v) for k, v in probs.items()]; heapq.heapify(h)
    while len(h) > 1:
        a, b = heapq.heappop(h), heapq.heappop(h)
        heapq.heappush(h, Node(None, a.prob+b.prob, a, b))
    return h[0]
def codes(n, p="", out=None):
    out = out or {}
    if n.sym is not None: out[n.sym] = p
    else: codes(n.left, p+"0", out); codes(n.right, p+"1", out)
    return out
probs = {"a":0.4,"b":0.2,"c":0.2,"d":0.1,"e":0.1}
c = codes(build(probs)); print(c)
H = -sum(p*math.log2(p) for p in probs.values())
L = sum(p*len(c[k]) for k,p in probs.items())
print(f"H={H:.3f}  L={L:.3f}  H<=L<=H+1: {H<=L<=H+1}")
```

### 题 2（教材例子：归一化 vs 未归一化）

教材给出四字母频率 "e":0.3、"a":0.25、"t":0.2、"z":0.05（和 0.8），并算得熵≈1.9 bits。

(a) 指出这个例子的问题。
(b) 归一化后重算熵与 Huffman 平均码长，并与"和 0.8 的版本"对比为什么必须归一化。

**解答**：

(a) 概率和是 $0.3+0.25+0.2+0.05 = 0.8 \ne 1$——这不是合法概率分布。熵公式要求 $\sum P(x)=1$，用一个不归一的分布算熵，得到的数字没有"每符号平均码长下界"的意义。

(b) 归一化：除以 0.8，得 e:0.375、a:0.3125、t:0.25、z:0.0625。$H = -(0.375\log_2 0.375 + 0.3125\log_2 0.3125 + 0.25\log_2 0.25 + 0.0625\log_2 0.0625) \approx 1.805$ bits。Huffman 码表（主线 Toy Model 的一种最优赋值）：e→`0`、a→`10`、t→`110`、z→`111`，平均码长 $L = 0.375\times1 + 0.3125\times2 + 0.25\times3 + 0.0625\times3 = 1.9375$。$1.805 \le 1.9375 \le 2.805$ ✓。而用未归一的 0.8 版本（0.3/0.25/0.2/0.05）算熵得约 1.70、算码长得约 1.55——**码长小于"熵"**，直接违背定理（教材打印的 1.9 也是同样的舍入失误），可见那个版本是坏的。归一化是让"熵"与"码长"可比的必要条件。

**思路点拨**：这题是主线边界声明第三条的实操。判别句：**算熵之前先检查 $\sum P = 1$**——和不是 1 的"概率表"，算出的熵是垃圾输入垃圾输出。教材的例子是常见的印刷失误，主线用归一化版本重做正是为了"诚实对待数字"。工程里（统计词频、语言模型输出）也一样：先归一化再进熵公式。

### 题 3（前缀码的必要性）

某编码方案给出：A→`0`、B→`01`、C→`10`。收到比特串 `010`。

(a) 这个方案是前缀码吗？
(b) `010` 能被无歧义地解码吗？能分成哪些可能？
(c) 用这个例子说明"前缀性"为什么是解码的硬要求。

**解答**：

(a) **不是**。`01`（B 的码）以 `0`（A 的码）开头——A 的码是 B 的码的前缀。

(b) 不能。`010` 有至少两种切分：`0|10` = A 后跟……但 `10` 是 C 的码，所以 `0|10` = A、C；又可切 `01|0` = B 后跟 `0`（但 `0` 是 A 的码）→ B、A。两种切分都合法、结果不同：`010` 既可读作 A+C，也可读作 B+A。**一个比特串对应多种解码，信息就丢了。**

(c) 前缀性是"唯一可解码"的充要条件（对即时码而言）：只有任何码都不是另一个码的前缀，0/1 流才能被**从左到右、边读边定**地无歧义切分。Huffman 树天然满足前缀性（叶子路径不会互相包含），所以它作为无损编码是安全的。**一套编码如果违反前缀性，就根本不能当无损码用**——解码歧义等于信息无法还原。

**思路点拨**：这道题把"前缀码"的必要性做成反例。最容易误解的是"读的时候能猜"——不，无损要求"自动、无歧义"的切分，不允许靠猜测。判别句：**前缀码 ⟺ 边读边定、绝不歧义。** Huffman 树的"叶子路径互不包含"结构，恰好是前缀性的保证——这也是为什么 Huffman 能被广泛用于无损压缩而不用担心解码出错。

## 三、DL 延伸

### 题 1（预测即压缩：语言模型是一台压缩器）

大语言模型训练时最小化交叉熵损失。有观点说："模型每降低 1 bit 的交叉熵，就等于把训练数据的压缩率提高了约 1 bit/符号。"

(a) 这个观点的信息论依据是什么？
(b) 为什么说"能预测 = 能压缩"？反过来，"压缩得好"对"学得好"意味着什么？

**解答**：

(a) 依据是**预测与编码的等价性**：香农的信源编码定理 + 条件熵链式法则。语言模型预测"下一个 token"给出条件分布 $q(w_t\mid w_{<t})$，而用这个分布做算术编码时，平均码长正是交叉熵 $\mathrm{H}(p,q)$——所以最小化交叉熵，就是在优化压缩率。模型的交叉熵越低，用它的分布编码文本所需的平均比特数越少，压缩率越高。

(b) "能预测 = 能压缩"来自上述等价性：一个分布若能准确预测下一个符号（压低条件熵），它就把文本的冗余榨干了，编码自然短。"压缩得好 = 学得好"则来自最小描述长度原理：一个模型能以低码率描述数据，说明它抓住了数据的**真实结构**（而非死记——死记的码率高）。所以"通用压缩器"（LLM-as-compressor）现象不是巧合，而是学习与压缩本质同一的体现。

**思路点拨**：这道题把压缩与深度学习缝合。要点：**交叉熵损失 = 用模型分布编码真实分布的平均比特数 = 压缩成本。** 训练语言模型就是在给训练数据做压缩，而模型在验证集上交叉熵低，等价于它能压缩没见过的数据——这正是"泛化"的另一种说法。判别句：**一个模型对数据压缩得多好，它就多懂这数据。** 这给了"深度学习在学什么"一个非常具体的信息论答案。

### 题 2（表示学习：潜变量是一台"语义压缩机"）

自编码器把高维图像 $x$ 压成低维潜码 $z$，再重建。有人把潜码 $z$ 称为"压缩后的表示"。

(a) 用熵的语言，为什么"$z$ 的维度远小于 $x$"不直接等于"$z$ 的信息远小于 $x$"？
(b) 如果潜码 $z$ 的熵接近 $x$ 的熵，说明这个"压缩"有什么问题？

**解答**：

(a) **维度不等于信息量**。$x$ 是 100 万维图像，但真实图像的熵远低于"100 万维随机"——因为图像有海量冗余（相邻像素强相关）。$z$ 是低维潜码，但如果它保留了 $x$ 的几乎全部熵（信息含量），那它并没有"压缩"——只是换了个坐标系。真正的压缩是"熵下降"，不是"维度下降"。**维度是载体，熵是内容**——低维空间也可以装下接近全部信息（如果编码紧），高维空间也可能大部分是冗余。

(b) 如果 $H(z) \approx H(x)$，说明潜码 $z$ 几乎没丢信息——那它更像"恒等编码"（$z\approx x$ 的变形），既没压缩也没学到抽象结构。好的潜码应该：$H(z)$ 远小于 $H(x)$（压掉了冗余）但 $I(x;z)$ 足够大（重建不塌）。**"压缩好"= 用低熵的 $z$ 承载高比例的 $x$ 的信息**，这正是信息瓶颈（最大化 $I(T;Y)$、最小化 $I(X;T)$）的另一种表述。

**思路点拨**：这道题把"压缩"与"表示学习"对齐。要点：**压缩的对象是熵，不是维度。** 自编码器/VAE 真正想做的是"把 $x$ 的熵塞进更少的比特里"，而"更少的比特"在深度学习里用"更少的维度"来近似。判别句：**$z$ 的维度低 ≠ 熵低；$z$ 的熵低且 $I(x;z)$ 高，才是好压缩。** 理解了这一点，就理解了为什么"降维"不是"压缩"的充分条件——压缩的判据是信息量，不是坐标系大小。

### 题 3（权重量化：把模型本身"压"一遍）

工程师把神经网络权重从 32 位浮点量化到 8 位整数部署，模型体积缩小到 1/4，准确率只掉了一点。

(a) 这个操作属于无损还是有损压缩？
(b) 用熵/信息论解释：为什么"大部分权重其实不需要 32 位"？量化在丢什么、保留什么？

**解答**：

(a) **有损压缩**——8 位无法精确还原 32 位的每个权重，量化后的权重与原始权重有差异。但它保留了"够用"的信息：量化误差对下游输出（logits、准确率）影响小。

(b) 32 位权重的"信息含量"远低于"32 位"这个载体：权重在训练中被正则化、趋近某些典型值，它们有**内在的冗余**——真正的熵远低于 $32$ bits/权重（比如有效信息只有几 bit）。量化到 8 位是"用更贴合真实熵的码率表示权重"：丢的是权重尾数的噪声（对输出几乎无影响），保留的是权重的主要信息（决定模型行为的部分）。**量化是"感知/任务导向的有损压缩"**——它利用"权重冗余大"这一事实，把 4 倍的体积省了下来，代价是微不足道的精度损失。

**思路点拨**：这道题把压缩原理用到模型部署。要点：**量化 = 承认权重是"低熵信源"**——真正需要的信息远少于 32 位载体，所以可以无损地（近似）压到 8 位。判别句：**权重的"熵"低，是因为训练后的权重有强结构（趋同、稀疏、低秩）**——量化就是在榨这份冗余。这也解释了为什么"量化友好训练"（QAT）能保住准确率：它让权重分布更利落（更低的熵、更少的离群值），量化时丢的更少。从信息论看，量化是"在熵与保真之间找平衡"的有损压缩，而训练目标之一就是让权重成为"好压缩的信源"。
