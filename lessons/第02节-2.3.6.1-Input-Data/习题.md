# 习题：输入数据的矩阵表示

## 第一组：概念检验

**1.1（单选）** 5 张 $28\times28$ 的灰度 MNIST 图堆成批量，形状是：
- A. $(5, 28)$
- B. $(28, 28, 5)$
- C. $(5, 28, 28)$
- D. $(5, 784)$

**1.2（判断并说明）** "把一批图像堆成张量时，应该用拼接（concatenate）而不是堆叠（stack）。" 这句话对吗？为什么？

**1.3（填空）** 单张灰度图用____矩阵表示，元素是 0–255 的____值；$B$ 张图堆成三维张量形状 $\_\_\_$，第 0 维表示____。

## 第二组：计算实践

**2.1（手算 + 代码验证）** 用 NumPy 造教材的 $I = \begin{bmatrix} 100&150&200\\50&100&150\\0&50&100\end{bmatrix}$，打印 `shape`、`I[2,2]`，并把图像转成浮点、除以 255 归一化，观察范围。

**2.2（代码验证）** 造 4 张 $3\times3$ 随机图，用 `np.stack` 堆成 `(4,3,3)`；再分别用 `stack(axis=1)` 与 `reshape` 尝试其他形状，比较各形状的语义。

**2.3（动手理解）** 对比"展平"与"保持矩阵"：把一张 $2\times2$ 图 `[[100,150],[50,100]]` 展平成 `(4,)`，再 reshape 回 `(2,2)`，验证无损；思考：这种"先展平再还原"在什么场景有用（如卷积→全连接→再 reshape）。

## 第三组：DL 延伸

**3.1（场景判断）** PyTorch 的 MNIST `DataLoader` 返回的 batch 形状通常是 `(B, 1, 28, 28)`。请解释四个维各代表什么，并说明为什么多了一个 `1`。

**3.2（场景分析）** 一张 RGB 彩色图，用 PyTorch 的 NCHW 惯例表示成 `(B, 3, H, W)`。请说明：为什么"通道"成了独立的一维？如果把图像"展平"成 `(B, 3*H*W)`，对卷积意味着什么损失？

---

## 解答与思路点拨

### 第一组

**1.1 答案：C（$(5,28,28)$）。**
- **思路**：批大小 5 在最前，每张图 $28\times28$ 在后。$(B,H,W)$。
- **点拨**：A 是"5 个样本 × 28 个特征"（把图误当向量）；D 是展平后的 `(5,784)`；B 把样本维放最后。**"样本在最前"是惯例。**

**1.2 不对。**
- **思路**：`concatenate` 沿已有轴拼接（3 张 2×2 → `(6,2)`），会把"第 2 张图"拼到"第 1 张图"的下面——图与图的边界被污染，卷积会把跨图区域当相邻像素。`stack` 增加新轴（→ `(3,2,2)`），每张图保持独立。
- **点拨**：**造"批量"用 stack，拼接"内容"用 concatenate**——两者语义完全不同。这也是本节最容易踩的工程坑。

**1.3 答案：$H\times W$；亮度；$(B,H,W)$；样本（第几张图）。**
- **思路**：灰度图 = $H\times W$ 矩阵；元素是亮度（0–255）；批量 $(B,H,W)$，第 0 维是样本。
- **点拨**：这一串填空把"图像 = 矩阵、批量 = 张量"钉死。

### 第二组

**2.1**
```python
import numpy as np
I = np.array([[100,150,200],[50,100,150],[0,50,100]])
print(I.shape)        # (3,3)
print(I[2,2])         # 100
Inorm = I.astype(float) / 255.0
print(Inorm.min(), Inorm.max())   # 0.0  ~0.784
```
- **思路**：`I[2,2]` 是右下角（100）；除以 255 归一化到 [0,1]。
- **点拨**：**归一化是把"原生像素"变成"模型友好输入"的第一道工序。** 0–255 的范围对初始化好的权重太大。

**2.2**
```python
imgs = [np.random.randint(0,256,(3,3)) for _ in range(4)]
b = np.stack(imgs)          # (4,3,3)
c = np.stack(imgs, axis=1)  # (3,4,3) 新轴插在中间
print(b.shape, c.shape)
```
- **思路**：`axis=0` 把"样本"放最前；`axis=1` 把"样本"插到第 1 位（语义变奇怪）。`reshape` 只改读法不保证语义正确。
- **点拨**：**`stack` 的 `axis` 决定新维的位置，即语义。** 默认 `axis=0` 是"样本在前"的行业惯例。

**2.3**
```python
M = np.array([[100.,150.],[50.,100.]])
flat = M.reshape(-1)        # [100 150 50 100]
back = flat.reshape(2,2)    # [[100 150] [50 100]]
print(np.allclose(M, back)) # True
```
- **思路**：展平再还原无损（元素顺序不变）。这在"卷积层 → 全连接层 → 输出层再 reshape 回空间形状"（如分割任务的分辨率恢复）里常用。
- **点拨**：**`reshape` 是形状之间的桥，不丢数据、只换读法。** 但要小心"展平顺序"——行优先 vs 列优先（§2.2.3.1 习题）必须一致。

### 第三组

**3.1 答案：四个维分别是：$B$（批大小，几张图）、$1$（通道数——灰度只有 1 个通道）、$28$（高）、$28$（宽）。多出的 `1` 是"通道维"。**
- **思路**：即使灰度图没有"颜色通道"的概念，PyTorch 仍统一用 `(B, C, H, W)`——灰度就是 $C=1$。这是为了与彩色图（$C=3$）共用同一套卷积代码（核要在通道上求和）。
- **点拨**：**"多余的 1 维"是框架的统一约定**。§2.5.3.2 讲卷积核时会看到，核的形状里也要有这个 $C$。

**3.2 思路**
- "通道"独立成维，因为**每个通道是一张独立的"图"**：RGB 的 R、G、B 三通道承载不同的颜色信息，卷积核要分别处理再求和（§2.2.3.7 的"核 × 通道"）。把通道压平会打乱"每个空间位置三个颜色值"的结构。
- 展平成 `(B, 3*H*W)` 的损失：与 §2.2.3.1 展平同理——空间邻近（像素上下左右）与通道邻近（同位置的 R/G/B）被压成"扁平序号"，模型要重新学习。**卷积的"局部结构"完全失效。**
- **点拨**：**"展平是信息无损、结构有损"**（§2.2.3.1）在这里再次成立——而且多了"通道结构"也一起损失。CNN 保持 `(B,C,H,W)`，正是为了保留空间 + 通道的双重结构。
