# 习题：张量 (Tensor)

## 第一组：概念检验

**1.1（单选）** 一张 $64 \times 64$ 的**灰度**图片（每个像素只有一个亮度值，没有颜色通道）是几阶张量？
- A. 0 阶（标量）
- B. 1 阶（向量）
- C. 2 阶（矩阵）
- D. 3 阶（张量）

**1.2（判断并说明）** "深度学习里的'张量'和爱因斯坦广义相对论里的'张量'是同一个概念，只是用了不同的场合。" 这句话对吗？为什么？

**1.3（填空）** 一个形状为 $(10, 20, 5)$ 的张量是____阶张量，它的元素总数是____。要取它"第 2 个维度第 3 个位置、第 5 个位置（三个维度各取一个）"的元素，需要____个下标。

## 第二组：计算实践

**2.1（手算 + 代码验证）** 教材里那张 $100 \times 100 \times 3$ 的 RGB 彩色图片，元素总数是多少？用 NumPy 造出它，打印 `.ndim`、`.shape`、`.size`，并验证"元素总数 = 形状各维之积"。

**2.2（代码验证）** 用 `np.array` 分别造出 0 阶、1 阶、2 阶、3 阶张量各一个（内容自选），打印每个的 `ndim` 和 `shape`。再对每个张量验证 `np.prod(T.shape) == T.size` 恒成立。

**2.3（动手理解阶与下标）** 令 `T = np.zeros((100, 100, 3))`。写出 `T[20, :, 1]` 的形状与语义。再回答：为什么"用一个下标 `T[20]`"不能完整定位一个像素的颜色？这恰好说明了张量阶数的什么本质？

## 第三组：DL 延伸

**3.1（场景判断）** 你准备把一批图片送进卷积神经网络：32 张、每张 $224 \times 224$ 像素、RGB 彩色。在 PyTorch 中这批数据最合理的形状是什么？为什么必须是 4 阶而不是 3 阶？

**3.2（场景分析）** 在 $(高, 宽, 通道)$ 的三维张量里，颜色通道 $C$ 被保留为独立的一维，而不是把 3 个通道"拼进"宽或高里（比如 $100 \times 300$）。请说出至少两条理由，说明为什么通道必须独立成维。

---

## 解答与思路点拨

### 第一组

**1.1 答案：C。**
- **思路**：灰度图片每个像素只有 1 个亮度值，所以定位一个像素只需 2 个下标——第几行、第几列。2 个下标 = 2 阶 = 矩阵。只有当每个像素有 3 个通道（如 RGB）时，才需要第 3 个下标，才升级为 3 阶。
- **点拨**：选 D 的人多半被"图片"两个字带偏了，以为凡图片必 3 阶。判据永远是"**取一个元素需要几个下标**"，不是"这个数据是不是图片"。

**1.2 这句话是错的。**
- **思路**：爱因斯坦的张量，核心性质是**坐标变换下的不变性**——换一套坐标系，分量的数值按特定规律一起变，物理对象本身不变。深度学习借用了"张量"这个名字，却把它简化为"多维数组"这个**数据容器**——没有任何坐标变换律。两个词，两套含义。
- **点拨**：这是本节最重要的边界声明。看到文献里出现"张量"时，先问一句：它在谁的语境里？物理张量谈"变换"，深度学习的张量只谈"形状"。

**1.3 答案：3 阶；$10 \times 20 \times 5 = 1000$；3 个下标。**
- **思路**：形状元组长度是 3，所以有 3 个维度、3 个下标；元素总数是各维大小之积；要同时指定三个维度各取哪个位置，正好需要 3 个下标——下标个数 == 阶数。
- **点拨**：元素总数只与形状有关，与里面存了什么数无关。这是"形状是张量的身份证明"的直接推论。

### 第二组

**2.1** 元素总数 $= 100 \times 100 \times 3 = 30000$。

```python
import numpy as np
T = np.zeros((100, 100, 3))            # 一张 RGB 彩色图片
print(T.ndim, T.shape, T.size)         # 3  (100, 100, 3)  30000
print(np.prod(T.shape) == T.size)      # True
```
- **思路**：三个维度分别是高、宽、颜色通道；`size` 就是元素总数，与 `np.prod(shape)` 恒等。
- **点拨**：这正是教材的例子 $T_{ijk}$（$i, j = 1,\ldots,100$，$k = 1, 2, 3$）的代码形态——3 个下标，3 阶。

**2.2**

```python
import numpy as np
ts = [
    np.array(5.0),                      # 0 阶：标量
    np.array([1.0, 2.0, 3.0]),          # 1 阶：向量
    np.array([[1.0, 2.0], [3.0, 4.0]]), # 2 阶：矩阵
    np.zeros((2, 3, 4)),                # 3 阶：三维块
]
for t in ts:
    print(t.ndim, t.shape, np.prod(t.shape) == t.size)
# 0 () True
# 1 (3,) True
# 2 (2, 2) True
# 3 (2, 3, 4) True
```
- **思路**：`ndim` 数出阶数（元组长度），`shape` 列出各维大小，元素总数永远等于形状之积。
- **点拨**：注意 0 阶张量 `np.array(5.0)` 的 `shape = ()`、`size = 1`——空元组之积约定为 1。它和 `np.array([5.0])`（形状 `(1,)`，1 阶）不是一回事。

**2.3** `T[20, :, 1]` 的形状是 `(100,)`——它取"第 21 行整行像素的绿色分量"。
- **思路**：`20` 锁死第 0 维（行），`:` 展开第 1 维（宽，100 个位置），`1` 锁死第 2 维（通道 1，即绿色）。结果是一个长度 100 的数组——第 21 行上每个像素的绿色值。而 `T[20]` 单独只锁死"行"一个维度，取回的是整行 3 通道（形状 `(100, 3)`）——它还没定位到具体某一个颜色，所以取不到一个像素的颜色。
- **点拨**：要"完整定位一个像素的颜色"必须把高、宽、通道三个维度全指定（如 `T[20, 5, :]` 返回 `(3,)`）。这正说明**阶数 = 需要的下标个数**——3 阶张量，就是必须 3 个下标才能钉死一个元素。

### 第三组

**3.1 答案：形状 `(32, 3, 224, 224)`（PyTorch 的 NCHW 惯例），必须 4 阶。**
- **思路**：每个像素有 3 个通道，单张图是 3 阶张量 $(3, 224, 224)$；32 张图摞起来，需要第 0 维表示"第几张"（批大小 N）——于是 4 阶：$N$（32 张）、$C$（3 通道）、$H$（224）、$W$（224）。只用 3 阶只能装下一张图，装不下"一批"这个信息。
- **点拨**：注意 PyTorch 惯用通道在前（CHW：`(C, H, W)`），而教材写的是通道在后（HWC：`(高, 宽, 通道)`）。两者数值内容相同，但第 0 维语义不同——**维度顺序是约定，不是数学**，跨框架搬运数据前先查清楚。

**3.2 思路（至少两条）**
1. **通道是"垂直堆叠的平行切片"，不是平面上的延伸**。把 3 个通道拼进宽里，等于把"红、绿、蓝三个平行世界"硬塞进同一个坐标轴——$100 \times 300$ 的第 0 个位置和后面的位置是"同一行的不同颜色"，而宽维里原本的相邻像素关系被破坏了。通道维和空间维的**几何语义不同**，不该混在一个维度里。
2. **卷积核天然要"跨通道"操作**。卷积网络的第一层权重是 4 阶张量 $(\text{out\_ch}, \text{in\_ch}, k_h, k_w)$——它要在每个空间位置同时看 $C$ 个通道（RGB 一起算）。若把通道拼进宽里，卷积核要自己拆开再拼回，形状语义会变得一团糟。通道独立成维，让"跨通道求和"变成张量运算里一个干净的轴。
3. **内存与计算是按轴对齐的**。通道独立成维，每个通道是一块连续区域（HWC）或一个连续平面（CHW），便于缓存与向量化；混进宽里则每个像素的 3 个颜色被打散，读写都不规整。
- **点拨**：选错的人往往觉得"反正都是数字，怎么排都一样"。但张量的维**不只是长度**，每个维度都携带语义——高是空间、宽是空间、通道是颜色。形状的每一个数，都在说它那一维"是什么"。

## 一个"为什么有人会答错"的提醒

1.1 的 D 是经典陷阱：看到"图片"就选 3 阶，忘了**灰度图没有通道维**。判据不是题材，是"取元素要几个下标"。1.2 最容易失分在"只是叫法不同"——物理张量与 DL 张量的区别不是用词，而是**是否要求坐标变换律**，这是两条完全不同的数学血脉。3.1 则考的是"批维度"：张量阶数不是数据本身固定死的，你每叠一层（图片→批→视频），就多一阶——阶数是**由你的组织方式决定的**，这也正是深度学习里"张量"这个词最灵活的地方。
