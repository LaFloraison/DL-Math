# 代码：熵——让 Python 聚合同一个信源的惊讶

主线里我们把单条惊讶（自信息 $-\log_2 P(x)$）按概率加权平均，得到信源的平均惊讶——熵 $H(X) = -\sum_x P(x)\log_2 P(x)$。本脚本把它写成函数，然后干四件事：验证主线那两枚硬币的数字、验证"均匀分布熵最大"、演示底数与单位、以及**不调用任何分布库、用 1 亿次模拟掷币让熵从"概率表"和"实际频率"两个方向分别浮出来**——数字会告诉你：频率逼近概率，熵逼近 1 bit。

---

## 层一：完整脚本

```python
import numpy as np                          # 向量化计算与大规模随机模拟

def entropy(probs, base=2):                 # ① 熵：加权平均的自信息
    """给定概率分布 probs，返回熵（单位由 base 决定）。"""
    probs = np.asarray(probs, dtype=float)
    probs = probs[probs > 0]                # 跳过 P(x)=0：约定 0·log0=0
    return -np.sum(probs * np.log(probs) / np.log(base))

# ---- ① 主线那两枚硬币：公平 vs 偏（0.9/0.1） ----
fair  = [0.5, 0.5]                         # 公平硬币
biased = [0.9, 0.1]                        # 偏硬币
print(f"H(公平硬币) = {entropy(fair):.3f} bits")    # 期望 1.000
print(f"H(偏硬币)   = {entropy(biased):.3f} bits")  # 期望 0.469

# ---- ② 均匀分布熵最大：把 0.9/0.1 一点点抹平 ----
print("\n-- 把分布从偏斜推向均匀，熵单调上升 --")
for alpha in [0.5, 0.6, 0.7, 0.8, 0.9]:
    p = [alpha, 1 - alpha]
    print(f"p = ({alpha:.1f}, {1-alpha:.1f}) -> H = {entropy(p):.3f} bits")

# ---- ③ 换底数：同一个熵，不同单位 ----
print("\n-- 同一个偏硬币，三个底数 --")
print(f"base=2  -> {entropy(biased, base=2):.3f} bits")
print(f"base=e  -> {entropy(biased, base=np.e):.3f} nats")
print(f"base=10 -> {entropy(biased, base=10):.3f} hartleys")

# ---- ④ 从随机掷币的频率反推熵：1 亿次硬币 ----
print("\n-- 1 亿次公平硬币模拟：频率逼近概率，熵逼近 1 bit --")
np.random.seed(42)                          # 固定随机种子：保证每次运行输出可复现
n = 100_000_000
flips = np.random.randint(0, 2, size=n)     # 0/1 各 5 千万次
freq = np.bincount(flips) / n               # 实际出现频率，约 [0.5, 0.5]
print(f"正面频率={freq[1]:.4f}  反面频率={freq[0]:.4f}")
print(f"H(由频率算出) = {entropy(freq):.3f} bits")

# ---- ⑤ 四等分 vs 二八分：熵对均匀的敏感度 ----
print("\n-- 同样的四个结果，分布不同，熵天差地别 --")
print(f"四等分      -> H = {entropy([0.25]*4):.3f} bits")      # 均匀 = log2(4) = 2
print(f"四结果二八  -> H = {entropy([0.8, 0.1, 0.05, 0.05]):.3f} bits")
```

运行输出（Python 3.11 + NumPy）：

```text
H(公平硬币) = 1.000 bits    # 期望 1.000
H(偏硬币)   = 0.469 bits    # 期望 0.469

-- 把分布从偏斜推向均匀，熵单调上升 --
p = (0.5, 0.5) -> H = 1.000 bits
p = (0.6, 0.4) -> H = 0.971 bits
p = (0.7, 0.3) -> H = 0.881 bits
p = (0.8, 0.2) -> H = 0.722 bits
p = (0.9, 0.1) -> H = 0.469 bits

-- 同一个偏硬币，三个底数 --
base=2  -> 0.469 bits
base=e  -> 0.325 nats
base=10 -> 0.141 hartleys

-- 1 亿次公平硬币模拟：频率逼近概率，熵逼近 1 bit --
正面频率=0.5000  反面频率=0.5000
H(由频率算出) = 1.000 bits

-- 同样的四个结果，分布不同，熵天差地别 --
四等分      -> H = 2.000 bits      # 均匀 = log2(4) = 2
四结果二八  -> H = 1.022 bits
```

主线那两枚硬币，被 Python 精确复现：1.000 与 0.469。下面逐行拆开。

## 层二：分步逐函数拆解

### 步骤 1：导入 NumPy —— 向量化与大数模拟的引擎

```python
import numpy as np
```

#### `import numpy as np`

**操作**：加载 NumPy 并绑定 `np`。
**输入**：无。
**输出**：`np` 句柄，本脚本用到 `np.asarray`、`np.sum`、`np.log`、`np.bincount`、`np.random.randint`。
**可调参数**：无。
**对应数学**：这一行提供向量化能力——熵的公式里每个 $P(x)$ 都要乘一个对数，向量化让"一个分布的所有项一起算"。

### 步骤 2：定义 `entropy` —— 加权平均的自信息

```python
def entropy(probs, base=2):
    """给定概率分布 probs，返回熵（单位由 base 决定）。"""
    probs = np.asarray(probs, dtype=float)
    probs = probs[probs > 0]                # 跳过 P(x)=0：约定 0·log0=0
    return -np.sum(probs * np.log(probs) / np.log(base))
```

#### `entropy(probs, base)` —— $H(X) = -\sum_x P(x)\log_b P(x)$

**做什么**：传入一个概率分布（数组），返回它的熵。
**操作**：分三步。
1. `np.asarray(probs, dtype=float)` 把输入（列表/元组/数组）统一转成 float 数组——保证后面乘除都是浮点。
2. `probs[probs > 0]` 用布尔索引**过滤掉概率为 0 的项**。为什么？因为公式里 $0 \cdot \log 0$ 严格说是未定义的（$-\log 0 = +\infty$），但信息论约定 $0 \cdot \log 0 = 0$——概率为零的结果从不出现、不贡献惊讶。`probs > 0` 产生一个布尔数组，用它做索引直接挑出正概率项，天然实现这条约定，还能避免 `np.log(0) = -inf` 污染求和。
3. `-np.sum(probs * np.log(probs) / np.log(base))` 是公式的向量化。`np.log(probs)` 是自然对数；`np.log(base)` 是换底系数；两者相除得到 $\log_b \text{probs}$（换底公式 $\log_b x = \frac{\ln x}{\ln b}$）。然后 `probs *` 乘上权重，`np.sum` 求和，最外层负号还原 $-\sum$。
**输入**：
- `probs`：一个概率分布。可以是一维列表 `[0.5, 0.5]`、元组，或一维 NumPy 数组 `(n,)`。要求所有项 $\ge 0$ 且**和为 1**（本函数不校验和，传非归一化的分布会算出无意义的数——调用者有责任传合法分布）。
- `base`：对数底，标量，默认 2。
**输出**：一个标量（float），该分布的熵。非负；均匀分布时取到 $\log_b n$。
**可调参数**：
- `base=2` → 比特；`base=np.e` → 纳特；`base=10` → 哈特利。三者数值不同、物理量相同，换底只差常数因子 $\log_b 2$。
- 能不能加第三个参数？`probs, base` 已完备。如果想让它自动归一化（容忍 `[0.9, 0.1]` 之外的非归一化输入），可以在函数开头加一行 `probs = probs / probs.sum()`——但**不建议**：把"传非法分布"的错误静默吞掉，会让调用方察觉不到 bug。教材里所有分布都是归一化的，这里照做。
**对应数学**：主线定义块 $H(X) = -\sum_x P(x)\log_b P(x)$ 的逐符号翻译。特别注意 `probs * np.log(probs)` 的写法——它把"权重乘惊讶"的两件事（$P(x)$ 与 $-\log P(x)$）写进同一个逐元素乘法，这正是"概率加权平均自信息"的向量化表达。

---

### 步骤 3：两枚硬币 —— 1.000 与 0.469 的复现

```python
fair  = [0.5, 0.5]
biased = [0.9, 0.1]
print(f"H(公平硬币) = {entropy(fair):.3f} bits")
print(f"H(偏硬币)   = {entropy(biased):.3f} bits")
```

**做什么**：把主线手算的两个熵交给函数复核。
**操作**：`entropy([0.5, 0.5])` 内层计算 $-0.5\cdot\log_2 0.5 - 0.5\cdot\log_2 0.5 = 1$；`entropy([0.9, 0.1])` 计算 $-(0.9\cdot\log_2 0.9 + 0.1\cdot\log_2 0.1) = 0.469$。
**输入**：两个二元素列表，各自的和都是 1。
**输出**：两行文本 `1.000` 与 `0.469`。
**可调参数**：任何归一化分布都可以喂进来。想量"天气"的熵？`entropy([0.7, 0.3])`（70% 晴天 30% 雨天）→ 约 0.881 bits，与 6.3.2 节的例子相呼应。
**对应数学**：这是主线第二节"把熵展开"的数值落地——$H(\text{偏}) = 0.9\times0.152 + 0.1\times3.322 = 0.469$ bits 的精确复现。

### 步骤 4：均匀分布熵最大 —— 把分布抹平

```python
for alpha in [0.5, 0.6, 0.7, 0.8, 0.9]:
    p = [alpha, 1 - alpha]
    print(f"p = ({alpha:.1f}, {1-alpha:.1f}) -> H = {entropy(p):.3f} bits")
```

**做什么**：固定两个结果，让分布从完全均匀 (0.5, 0.5) 一路滑向极端偏斜 (0.9, 0.1)，观察熵的变化。
**操作**：循环里构造 `[alpha, 1-alpha]`，每次调用 `entropy`。
**输入**：`alpha` 从 0.5 递增到 0.9。
**输出**：五行，熵从 1.000 单调降到 0.469。
**可调参数**：把 `alpha` 推到 0.99 → 熵约 0.081 bits（几乎确定，几乎无惊讶）；推到 1.0 → 0 bits（完全确定）。或者改成三结果的分布（如 `[0.5, 0.3, 0.2]`）看同样的"抹平→熵升"规律。
**对应数学**：主线性质"均匀分布熵最大"。每个 `alpha` 对应一个分布，熵作为"分布偏斜程度"的函数单调下降——这行循环把"惩罚偏科"的定理做成了可视化表格。

### 步骤 5：换底数 —— 同一个熵，三个刻度

```python
print(f"base=2  -> {entropy(biased, base=2):.3f} bits")
print(f"base=e  -> {entropy(biased, base=np.e):.3f} nats")
print(f"base=10 -> {entropy(biased, base=10):.3f} hartleys")
```

**做什么**：对同一个分布传三个不同的底数。
**操作**：`np.log(base)` 在函数内部完成换底。底 $e$ 时 `np.log(probs)/np.log(np.e)` = 自然对数本身。
**输入**：同一个 `biased`，三个 `base`。
**输出**：`0.469 bits` / `0.325 nats` / `0.141 hartleys`。三者恒成比例：$\text{nats} = \text{bits}\times\ln 2 \approx 0.469\times0.693 = 0.325$；$\text{hartleys} = \text{bits}\times\log_{10}2 \approx 0.469\times0.301 = 0.141$。
**可调参数**：换任何分布，三个底数的输出都保持这个固定比例。深度学习论文常用 nats（如 VAE 的 ELBO、KL 散度），读到 `nats` 时心里 ×1.443 就是 bits。
**对应数学**：主线第三节"底数、单位，与熵是平均码长的下界"。换底公式 $\log_b x = \frac{\ln x}{\ln b}$ 是这里的全部魔法。

### 步骤 6：1 亿次模拟 —— 频率逼近概率

```python
n = 100_000_000
flips = np.random.randint(0, 2, size=n)
freq = np.bincount(flips) / n
print(f"H(由频率算出) = {entropy(freq):.3f} bits")
```

#### `np.random.randint(0, 2, size=n)` —— 掷 n 次硬币

**操作**：从 $[0, 2)$ 均匀抽取 $n$ 个整数，即 0/1 各半的独立随机序列。`size=n` 指定抽多少个。
**输入**：`0`（下界含）、`2`（上界不含）、`size=n`（个数）。
**输出**：形状 `(n,)` 的整数数组，约一半 0、一半 1。
**可调参数**：`size` 是主旋钮——越大越接近 0.5/0.5，熵越逼近 1.000；`10_000` 时频率抖到约 0.495/0.505，熵约 0.9999。还可以用 `p=[0.9, 0.1]` 参数直接掷偏硬币：`np.random.choice([0,1], size=n, p=[0.9,0.1])`——此时频率逼近 0.9/0.1，熵逼近 0.469。
**对应数学**：这是"大数定律"——频率依概率收敛到概率。掷币结果里蕴含的信息，最终由真实概率 $P$ 决定，而频率是 $P$ 的估计。

#### `np.bincount(flips)` —— 数每个取值出现几次

**操作**：对整数数组 `flips`，返回一个数组，第 $i$ 个元素是"$i$ 出现了多少次"。`np.bincount([0,1,0,1,1])` → `[2, 3]`。
**输入**：一维非负整数数组，形状 `(n,)`。
**输出**：形状 `(max(flips)+1,)` 的计数数组——这里固定是 `(2,)`。
**可调参数**：`np.bincount(flips, minlength=k)` 可强制最小长度；`.astype(float)` 或直接除以 `n` 转成频率。它只接受非负整数，对连续数据不适用（那是 `np.histogram` 的活）。
**对应数学**：把 1 亿次掷币压缩成两个数字——正面的次数和反面的次数，即频率 $\hat P(H), \hat P(T)$。

#### `entropy(freq)` —— 用频率算熵

**操作**：把频率数组当概率分布喂进 `entropy`。因为频率和恒为 1、各项非负，它天然是合法分布。
**输入**：`freq`，形状 `(2,)`，约 `[0.5000, 0.5000]`。
**输出**：约 `1.000` bits。
**可调参数**：把 `np.random.randint(0, 2, ...)` 换成 `np.random.choice(...p=[0.9, 0.1])`，就会算出约 `0.469`——频率从哪来，熵就逼近哪个真实分布。
**对应数学**：这是"用频率估计概率再算熵"的两步法，也是统计中"熵估计"的朴素形式。它验证了主线的一个深层承诺：**熵是信源（真实 $P$）的属性**，只要样本够多，频率就能把熵"挖"出来。

### 步骤 7：四结果 —— 均匀 vs 二八的鲜明对照

```python
print(f"四等分      -> H = {entropy([0.25]*4):.3f} bits")
print(f"四结果二八  -> H = {entropy([0.8, 0.1, 0.05, 0.05]):.3f} bits")
```

**做什么**：同为四个结果，均匀分布与倾斜分布的熵对比。
**操作**：`[0.25]*4` 是 `[0.25, 0.25, 0.25, 0.25]`，均匀四等分。
**输入**：两个四元素归一化分布。
**输出**：`2.000`（均匀，恰好 $\log_2 4 = 2$）与 `1.022`（二八倾斜）。
**可调参数**：把 `[0.8, 0.1, 0.05, 0.05]` 换成 `[0.97, 0.01, 0.01, 0.01]` → 熵约 0.24 bits，几乎确定。
**对应数学**：主线"均匀分布熵最大 = $\log_2 n$"。四个结果时天花板是 2 bits，任何倾斜都把它拉下来——这行对比就是 $H \le \log_2 n$ 的现场演示。

## 改个数字试试：把分布推向极端

熵对分布形状的响应，在两个极端最震撼。

### 实验 1：三结果，从均匀到必中

```python
for p in [[0.33, 0.33, 0.34], [0.6, 0.3, 0.1], [0.98, 0.01, 0.01]]:
    print(f"{p} -> H = {entropy(p):.3f} bits")
```

输出：

```text
[0.33, 0.33, 0.34] -> H = 1.584 bits
[0.6, 0.3, 0.1]    -> H = 1.296 bits
[0.98, 0.01, 0.01] -> H = 0.151 bits
```

三结果的天花板是 $\log_2 3 \approx 1.585$ bits。几乎均匀时 1.584，几乎确定时 0.151——**同一个信源，把分布一捏，熵缩到十分之一**。工程意义：模型输出分布越尖锐（confidence 越高），它的熵越低；两个模型的熵可以差出一个量级。

### 实验 2：加一个结果，熵反而可能变小

```python
print(f"两个结果(0.9,0.1)          -> H = {entropy([0.9, 0.1]):.3f}")
print(f"三个结果(0.9,0.05,0.05)    -> H = {entropy([0.9, 0.05, 0.05]):.3f}")
```

输出：

```text
两个结果(0.9,0.1)          -> H = 0.469
三个结果(0.9,0.05,0.05)    -> H = 0.569
```

加了第三个结果，熵只涨了 0.1 bits——因为多出来的那个结果概率才 5%，几乎不贡献惊讶。这提醒你：**熵不是"结果个数"，是"结果个数的对数的上界"**。结果多但概率高度集中，熵照样小；结果少但均匀，熵反而大。看到"类别很多"就以为"熵很大"是常见错觉——softmax 输出 1000 类但几乎全押在 1 类上时，熵接近 0。

## 边界声明：这套代码能做什么，不能做什么

1. **`entropy` 不校验归一化。** 传 `[0.9, 0.1]` 合法，传 `[0.9, 0.1, 0.1]`（和 1.1）也会算出一个数，但那个数没有意义——熵的定义要求 $\sum_x P(x) = 1$。本函数故意不自动归一化，是为了让非法输入"大声失败"而非"静默错误"。真实工程里（如 `scipy.stats.entropy`）默认 `base` 是 $e$，且会把 `0` 静默处理成 `0·log0=0`——与本函数行为一致，但底数不同，换算要 ×1.443。
2. **熵衡量不确定性，不衡量"有用性"。** `entropy(np.random.randint(0,2,1000000))` 会给出接近 1 的大数——但这段随机噪声里没有任何"知识"。熵大 ≠ 信息丰富，正如主线边界声明第一条所说：噪声让人处处意外，却不构成信息。要度量"降低的不确定性"，靠的是互信息（6.5 节），不是熵本身。
3. **频率算熵有偏差。** 第 ⑥ 步用频率当概率——样本少时（`size=100`）算出的熵会**偏低**（尤其分布高度倾斜时），这是统计上的系统性偏差，不是代码 bug。样本够多才逼近真熵。深度学习里监控验证集熵时，如果 batch 很小，得到的熵估计会有噪声——别拿单 batch 的熵当判决依据。
