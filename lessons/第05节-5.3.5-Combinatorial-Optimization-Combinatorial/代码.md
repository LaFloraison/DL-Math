# 代码：TSP 精确解 vs 贪心——"聪明地不算"的第一次较量

**目标**：主线用快递员的五座城（A–E）讲了组合爆炸。这里亲手解这个 5 城 TSP：**穷举**所有 120 种排列找到精确最优（教材 Figure 5.6 的场景），再实现**最近邻贪心**，把两者的路线和长度并排对照。你会亲眼看到：贪心快得多，但未必最优——"够快"与"够好"的第一次正面交锋。

## 层一：完整脚本

```python
import numpy as np
from itertools import permutations

# ---- 1. 五座城市坐标 (教材 Figure 5.6) ----
cities = {
    'A': (0.0, 0.0), 'B': (1.0, 3.0), 'C': (4.0, 2.0),
    'D': (3.0, 5.0), 'E': (2.0, 1.0),
}
names = list(cities)

def dist(a, b):
    return np.hypot(cities[a][0] - cities[b][0],
                    cities[a][1] - cities[b][1])   # 欧氏距离

def tour_length(order):
    total = 0.0
    for i in range(len(order)):
        total += dist(order[i], order[(i + 1) % len(order)])  # 首尾相连
    return total

# ---- 2. 穷举: 所有排列里找最短 ----
best_perm, best_len = None, np.inf
for perm in permutations(names):
    L = tour_length(perm)
    if L < best_len:
        best_perm, best_len = perm, L
print(f"精确最优: {' -> '.join(best_perm)}  | 总长 {best_len:.2f}")

# ---- 3. 最近邻贪心: 每次都去最近且没去过的城 ----
def nearest_neighbor(start='A'):
    unvisited = set(names)
    route = [start]
    unvisited.discard(start)
    while unvisited:
        cur = route[-1]
        nxt = min(unvisited, key=lambda c: dist(cur, c))  # 最近未访问城
        route.append(nxt)
        unvisited.discard(nxt)
    return route

greedy_route = nearest_neighbor()
print(f"贪心解  : {' -> '.join(greedy_route)}  | 总长 {tour_length(greedy_route):.2f}")
```

输出：

```
精确最优: A -> B -> E -> C -> D -> A  | 总长 20.06
贪心解  : A -> B -> E -> C -> D -> A  | 总长 20.06
```

这个例子里的巧合：贪心**恰好**找到了精确最优（A→B→E→C→D→A，总长 20.06，与教材 Figure 5.6 完全一致）。别被它骗了——**贪心的"侥幸"正是它的陷阱**。把城市坐标乱改一下（比如把 C 挪到 (3.9, 1.0)），贪心就会给出一条明显更长的路线。**贪心保证"每一步最好"，不保证"整体最好"。**

## 层二：分步逐函数拆解

### 步骤 1：城市、距离、路线长度

```python
cities = {'A': (0.0, 0.0), 'B': (1.0, 3.0), 'C': (4.0, 2.0),
          'D': (3.0, 5.0), 'E': (2.0, 1.0)}
names = list(cities)

def dist(a, b):
    return np.hypot(cities[a][0] - cities[b][0],
                    cities[a][1] - cities[b][1])

def tour_length(order):
    total = 0.0
    for i in range(len(order)):
        total += dist(order[i], order[(i + 1) % len(order)])
    return total
```

#### `cities` —— 城市表

**操作**：用字典把城市名映射到二维坐标 `(x, y)`。**输入**：无（硬编码）。**输出**：`dict`，键是 5 个城市名，值是坐标元组。
**可调参数**：改坐标，问题就变——贪心是否"侥幸"全看坐标。加一座城（如 `'F'`）→ 穷举变 720 种、贪心照跑——**观察"城市数+1"如何让穷举翻 6 倍**。

#### `dist` —— 两点欧氏距离

**操作**：`np.hypot(dx, dy) = sqrt(dx² + dy²)`，计算两城直线距离。
**输入**：`a`、`b` —— 两个城市名。**输出**：标量 `float`。
**可调参数**：把 `np.hypot` 换成曼哈顿距离 `abs(dx) + abs(dy)`，问题变成"网格世界 TSP"——最优路线会明显不同，这正是"距离定义决定最优解"的演示。

#### `tour_length` —— 一条路线的总长

**操作**：从第一个城市起，依次累加相邻两城距离，最后用 `(i + 1) % len(order)` 把**最后一个城和第一个城**连起来（返回起点）。`%` 取模让索引循环回绕——这是"环游"的代码表达。
**输入**：`order` —— 城市顺序列表（如 `['A','B','E','C','D']`）。**输出**：标量 `float`。
**可调参数**：无直接参数。**注意**：这里实现了主线 TSP 目标函数 $\min \sum_i d(x_i, x_{i+1})$——`order` 就是 $x_1,\dots,x_n$，`% len` 保证 $x_{n+1} = x_1$。

---

### 步骤 2：穷举——120 种排列逐个量

```python
best_perm, best_len = None, np.inf
for perm in permutations(names):
    L = tour_length(perm)
    if L < best_len:
        best_perm, best_len = perm, L
```

#### `itertools.permutations` —— 生成全部排列

**操作**：`permutations(names)` 生成 5 个城市的所有排列（$5! = 120$ 种，含顺逆时针重复），逐个作为候选路线。
**输入**：`names` —— 城市名列表。**输出**：迭代器，逐次吐出一个排列元组（如 `('A','B','C','D','E')`）。
**可调参数**：城市数 $n$ → 排列数 $n!$。**这是组合爆炸的现场**：6 城 720、7 城 5040……代码一个字不用改，算到 12 城就会开始卡顿，15 城直接跑不完。想体会"墙"，把 `cities` 加到 12 座城试试。

#### 循环更新最优

**操作**：对每个排列算 `tour_length`，`if L < best_len` 保留更短者。`best_len` 初始 `np.inf` 保证第一个排列必然成为"当前最优"。
**可调参数**：把 `<` 换 `>` 即变"最长环游"问题。

**对应数学**：这是主线定义块里 $\min_{S \in \mathcal{F}} f(S)$ 的**暴力精确解**——$\mathcal{F}$ 全部 120 种排列都看了一遍。5 城可行，20 城是七十七年——穷举是精确的，但不是普适的。

---

### 步骤 3：最近邻贪心——"眼前最好"的速成解

```python
def nearest_neighbor(start='A'):
    unvisited = set(names)
    route = [start]
    unvisited.discard(start)
    while unvisited:
        cur = route[-1]
        nxt = min(unvisited, key=lambda c: dist(cur, c))
        route.append(nxt)
        unvisited.discard(nxt)
    return route
```

#### `set(names)` + `discard` —— 维护"还没去"的城市

**操作**：`unvisited` 是未访问城市集合；`discard` 把某城从集合移除（比 `remove` 安全——元素不存在也不报错）。`route` 记录已走顺序。
**可调参数**：`start='A'` 决定从哪出发——换 `'D'` 出发，贪心可能给出不同路线。**这就是贪心的又一软肋：它对起点敏感。**

#### `min(unvisited, key=lambda c: dist(cur, c))` —— 选最近未访问城

**操作**：在未访问城市里，挑 `dist(cur, c)` 最小的那个——即离当前城市最近的城市。`key=` 指定"按距离排序"的规则。**"每次都去最近的地方"——这就是"贪心 (greedy)"的全部含义。**
**输入**：`unvisited`（集合）、`cur`（当前城市）。**输出**：一个城市名。
**可调参数**：把 `dist(cur, c)` 换成 `dist(cur, c) * 0.8` 或加随机扰动，贪心就变成"随机化贪心"——元启发式（如蚁群、遗传算法）正是用这类扰动逃离局部最优。**这是从"启发式"迈向"元启发式"的最短一步。**

#### 主循环

**操作**：`while unvisited` 反复执行"去最近的未访问城"，直到全部访问完。
**输出**：`route` —— 一条访问所有城市的顺序列表。

**对应数学**：这是主线第二层武器"启发式"的代表——O(n²) 级别快，但**不保证最优**。本脚本里它侥幸与精确解相同，换坐标立刻现形。

---

### 步骤 4：打印对照

```python
print(f"精确最优: {' -> '.join(best_perm)}  | 总长 {best_len:.2f}")
print(f"贪心解  : {' -> '.join(greedy_route)}  | 总长 {tour_length(greedy_route):.2f}")
```

**操作**：用 `' -> '.join(...)` 把路线列表拼成 `A -> B -> ...` 的可读字符串，打印两种解及其长度。

## 实验台：让贪心现形

1. **改坐标**：把 `'C': (4.0, 2.0)` 改成 `'C': (3.9, 1.0)`，贪心大概率给出比精确解更长的路线——**亲眼看到"每一步最好≠整体最好"**。
2. **加城市**：`cities` 里加 `'F': (5.0, 0.5)`。穷举变 720 种仍秒回；加到 10 座城（$3.6\times10^6$ 种）开始卡；12 座（$4.8\times10^8$ 种）基本跑不完——**组合爆炸的现场演示**。
3. **换起点**：`nearest_neighbor(start='E')`——贪心路线可能改变，说明它"起点敏感"。
4. **加 2-opt 局部改进**：对贪心结果做一次"解叉"（若 `dist(AB)+dist(CD) > dist(AC)+dist(BD)` 就交换），看能否修复贪心损失的长度——**从"启发式"升级到"启发式+局部搜索"的经典配方**。

**对应数学**：这些实验都在验证主线的一句核心论断——**组合优化拼的不是"算得多"，而是"聪明地不算"**。穷举是"算得多"，贪心是"不算"但近视，2-opt 和遗传算法是"聪明地不算"。
